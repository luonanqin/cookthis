# 分支与发布约定

> 2026-11-19 修订：增加长期 **`develop`**；**`main` 不含调试相关代码**；短生命周期分支命名须带 **`YYYY-MM-DD` 日期戳**。  
> 仍用开关裁剪「无会员 / 有会员 / 广告」，不维护多条「产品形态」长期分叉。

## 分支角色

| 分支 | 角色 |
|------|------|
| **`develop`** | 日常开发主干；**最完整**（含会员、广告能力、调试按钮与 `dev*` 云接口） |
| **`main`** | **可上线**主干；**不得含调试相关内容**（无会员页调试区、无 `devGrant` 等调试 action / 调试专用文案入口） |
| **`feat/*` · `fix/*`** | 从 **`develop`** 拉出；做完合回 **`develop`**，再视情况晋升 `main` |

**禁止：** 为「无会员 / 有会员」再开两条长期产品分支；无会员用 `MEMBERSHIP_ENABLED=false` 即可。

## 分支命名

短生命周期功能 / 修复分支 **必须带日期戳**，避免同名长期漂浮、worktree 与远程混淆。

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能 | `feat/<topic>-YYYY-MM-DD` | `feat/membership-2026-11-19` |
| 修复 | `fix/<topic>-YYYY-MM-DD` | `fix/pay-timeout-2026-11-20` |
| 发版剥离（可选） | `release/<tag或日期>` | `release/2026-11-19` |

- `<topic>`：小写英文短横线，一事一题；不要用笼统的 `feat/wip`、`feat/tmp`。  
- 日期用拉分支当天的 **本地日历日**（`YYYY-MM-DD`）。同一 topic 当天需再开第二条时，在日期后加时间：`feat/<topic>-YYYY-MM-DD-HHmm`（如 `feat/membership-2026-11-19-1502`）。  
- **不要**使用无日期的永久名（如 `feat/membership`）；合入 `develop` 后可删本地/远程该分支。  
- 长期只保留 **`develop`** 与 **`main`**；其余均为短生命周期。

## 从当前仓库一次性迁到该模型

当前工作区若在旧 `main` 且已含调试与会员完整代码，推荐顺序：

1. **提交或 stash** 现有 WIP（改名分支不要求干净树，但拆 `main` 并删调试时最好先有清晰提交）。  
2. 将当前主干改名：`git branch -m main develop`  
3. 从 `develop` 建发布线：`git checkout -b main`  
4. **仅在 `main` 上删除调试相关代码**（见下），保留会员/广告实现与开关。  
5. 推远程：`develop`、`main` 均设 upstream；默认开发检出 `develop`。  
6. 历史 `feat/*` worktree：已合入的可删；未合完的改名为带日期戳格式，并改基于 `develop` 变基/合并。

之后：**不要**在 `main` 上日常开发；只在发版时把 `develop` 合入 `main`（或 cherry-pick），合入时必须再次确保调试未进入 `main`（见「晋升规则」）。

## `main` 上须剥离的调试内容（清单）

- 会员页「调试（仅开发/体验版）」整块 UI 与 `onDev*`  
- `miniprogram/services/membership.js` 中 `devGrant` / `devClear` / `devExpireSoon` / `devResetFirstPurchase` / `devClearOrders` / `devCreatePending`  
- 云函数 `membership` 的对应 `dev*` action 与 `MEMBERSHIP_ALLOW_DEV_GRANT` 联调说明（正式云本就不设该变量；`main` 代码侧也不保留调试入口）  
- 仅服务于调试按钮的单测 / 文案，随删除一并调整  

**保留：** `MEMBERSHIP_ENABLED`、`ADS_ENABLED`、正式支付与换菜/菜数软限、正式埋点。

## 功能开关（两分支都有实现，发版改常量）

| 开关 | 位置 | 说明 |
|------|------|------|
| `MEMBERSHIP_ENABLED` | `miniprogram/services/membership.js` | 默认建议 `false`（无会员先上）；卖会员改 `true` |
| `ADS_ENABLED` | `miniprogram/utils/ads.js` | 默认 `false`；流量主就绪后再开 |

## 晋升规则（`develop` → `main`）

```
feat/<topic>-YYYY-MM-DD ──► develop（可含调试）──► 发版时去掉调试 ──► main 上线
```

- 合入 `main` 的变更 **不得**再带上调试 UI / `dev*`。  
- 若整分支合并会把调试带回来：用 **发版 PR**（从 develop 拉 `release/*`，在 PR 里删调试后再合 `main`），或只 cherry-pick 非调试提交。  
- **不要**指望「合完再在 main 上随手删」却无检查清单——每次晋升对照上一节清单。
