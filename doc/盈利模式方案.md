# 买菜做什么 / cookthis — 盈利模式方案

> 配套文档：`doc/需求概述.md`（产品 v1.0）  
> 整理日期：2026-09-30　|　定稿更新日期：2026-11-17  
> 目的：在核心体验（菜场决策 → 推荐 → 购买清单）成立的前提下，确定变现路径；候选方案保留备查。  
> 2026-10-11：对照「非日常 → 聚会」收口重评估广告/会员表述。  
> 2026-11-17：广告暂不可接、会员可先开 → 改为**会员轻先行、广告后置**；日常按**整次总菜数**软限；成员数不限；引导页不做变现；忌口变现暂不定。  
> 2026-11-17（晚）：**换菜**日额度与激励加次、会员不限次+防刷频控（产品入口已收为单一「换菜」，见需求概述模块 5）。  
> 2026-11-17（夜）：换菜额度改为**促转导向**——免费 **日 3**、激励一律 **看 1 得 1**、**日限制优于周限制**；触顶**只软挡再换菜，不挡今天买菜**（当前方案可去买菜）。激励广告收入对 ARPU 贡献有限，参数以会员转化与体验为准。

## 〇、最终方案（已定稿）

### 策略一句话

**会员轻先行、广告后置**：主链路（日常 / 聚会）始终可免费走完——**含换菜额度用尽后仍可按当前方案去买菜**。现阶段先上轻会员（换菜不限次相对免费日 **3** 次 + 日常总菜数软限等）；流量主达标后再开清单广告与换菜激励加次，并把**去广告**加成会员权益。分佣 / B 端等保留为候选，不进当前主路径。

### 相对「聚会」收口与 2026-11 约束：要不要改？

| 维度 | 结论 |
|------|------|
| **主链路免费** | **不变**。日常与聚会确认 → 推荐 → 清单 → 记录均可走完；**不以锁聚会作付费墙**。 |
| **落地顺序** | **已改**：由「先广告后会员」改为 **先轻会员 → 流量主达标后再广告**（广告位仍按原地图预埋）。 |
| **广告密度** | **规则不变**：日常清单原生 1 条；**聚会可第 2 条**（间隙原生、不插屏）。未开通流量主前不渲染。 |
| **会员卖点** | **已调**：主卖 **换菜不限次**（免看激励）、**日常整次总菜数更高/不限**；日后加 **去广告**。**不卖**成员数上限；**不卖**「能用聚会」。忌口是否进权益包**暂不定**（见下）。 |
| **方案 E（按次聚会/节日）** | **更往后**。聚会已是免费主路径；节日入口已隐藏。 |

### 广告插入时机（核心约定 · 预埋，开通后生效）

这里的「选菜」指用户**在摊位上挑选真正的菜**（眼睛看货、偶尔看手机），不是 App 内勾选食材。

| 项 | 约定 |
|----|------|
| **主广告位** | 点「去买菜」之后的 **购买食材页（清单）** |
| **为何合适** | 用户沿摊位采购时会反复对照清单，单次停留常有十几秒到数分钟；屏幕可伴随曝光，不必打断挑菜动作 |
| **推荐形态** | 清单页底部 / 列表间隙 **原生模板**（日常 1 条；**聚会可加第 2 条**，仍走间隙、不插屏）；可选封面广告（回前台时，控制频次） |
| **可用但非主位** | 「换菜」免费日额度用尽后的 **激励视频**（看完加次数，规则见下节）；特殊忌口若日后做，可激励换 7 日 |
| **明确不做** | 进场确认弹层插屏；出方案前的主流程插屏；挑菜对照清单时全屏挡住清单的插屏；**引导 / onboarding 任何广告或会员推销** |

### 换菜日额度（2026-11-17 定 · 夜修订）

产品入口：推荐页单一 **「换菜」**（原「换一批 / 不行」收口；面板跳过/完成且成功换批才计次；取消/遮罩不计）。日常与聚会 **共用** 下方免费池。

**窗口：用自然日，不用自然周。** 对齐「今天这一顿」；周额度易出现周初很松、周末一次砸脸，且与「人要吃饭不能等下周」冲突更大。

| 档位 | 规则 |
|------|------|
| **免费 · 基础** | 每自然日 **3** 次（日常+聚会合计）。目标：一轮买菜够换几轮；比日 5 更易触顶以促转会员，比日 2 少伤首周体验 |
| **免费 · 激励加次**（激励广告可用后） | 基础用尽后：日常 / 聚会均为完整看完 **1** 次激励 → 再赠 **1** 次换菜（**取消**「日常看 1 得 2」）。可重复观看加次，但建议另设 **激励完播日上限**（如再看 **3** 次），达上限后不再发激励加次、只留会员与「按当前方案去买菜」 |
| **会员** | **不限次**，不必看激励；须加 **防刷频控**，避免连点拖库 / 打爆候选池 |
| **无激励广告期** | 基础用尽后：**不**清空方案；主路径引导 **按当前方案去买菜**，次要引导开通会员（可文案预告激励上线后可看视频再换） |

**计次**：面板导致换批成功 +1；取消/点遮罩不换批则不计。免费与激励加次余额按自然日清零。

#### 硬约束：软挡「再换」，不挡「今天买菜」

用户今天仍要吃饭、仍可能站在菜场里。换菜额度用尽 **不得** 变成「不办会员 / 不看视频就不能买菜」。

| 允许 | 禁止 |
|------|------|
| 保留当前方案；「去买菜」始终可用 | 清空方案、禁止进清单 |
| 触顶只限制再次「换菜」 | 主按钮只有「开通会员」或「明天再来」 |
| 小字可说明「明天再送免费次数」 | 把「明天再买」当主出口 |

**触顶示意（有激励时）**：

1. 文案：今日免费换菜已用完；**当前方案仍可直接去买菜**  
2. **主按钮**：「去买菜」（结束今天的采购决策）  
3. 次按钮：「看视频，再换 1 次」  
4. 次按钮：「开通会员，换菜不限次」  

无激励或激励日上限已满：去掉「看视频」，保留「去买菜」+「开通会员」。

**参数取向说明**：激励完播对开发者侧 ARPU 贡献通常远小于清单广告；免费次数与「看 1 得几」以 **会员转化 + 不伤今天买菜** 为准，不为堆激励曝光而收太紧。调研中会员月费曾用 **¥6.6** 作页价对照锚；**月卡首购定稿 ¥0.99**（见会员设计）；季/年与月卡页价配置化，仍可调。  

**会员产品入口（2026-11-17）**：首页顶栏字号「大」左侧 VIP 闪光入口；「我的」展示会员状态；权益与开通同一页（不单开权益页）。详设 [`docs/superpowers/specs/2026-11-17-会员开通与权益-design.md`](../docs/superpowers/specs/2026-11-17-会员开通与权益-design.md)。

**会员 / 激励防刷（草案，实现时写死并埋点）**：

| 层 | 建议 |
|----|------|
| 客户端 | 换菜成功后短冷却（如 **2～3s** 内忽略连点）；按钮 loading 至本轮返回 |
| 服务端 | 同用户换菜（reject/swap）滑动窗口限流（如 **约 20 次 / 分钟** 或等价）；超限返回友好错误、不扣业务额度 |
| 激励 | 须校验激励回调真实发奖后再加次；**激励完播日上限**（如 3）达后只推会员 + 去买菜 |

### 日常总菜数软限（2026-11-17 定）

计量：**同一次推荐请求**内，各顿菜谱卡道数之和（不数清单 SKU 行）。

| 类型 | 规则 |
|------|------|
| **日常**（1 顿多菜或多顿少菜，同一套规则） | 免费档整次总菜数 ≤ **12**；超出部分软处理——先出满 12 道可用，超额折叠/灰显并引导会员，**不**在出方案前硬拦到空白 |
| **聚会** | **不按 12 限**，仍按 `suggestPartyCombo` / 人数出满 |
| **换菜** | 不重置本场菜数额度（换菜不换菜数帽） |

例：1 顿 3～4 道、3 顿×每顿 3 道（共 9）均在 12 内；约 **4 顿×3 道** 会触顶。改天再开一次日常请求 = 新额度。主转化仍是换菜日 3；菜数 12 主要挡住「一次排很多天」。

### 与会员的衔接

- **日常与聚会**：确认食材 → 推荐 → 清单 → 记录，**两条主路径均可免费走完**（聚会含自动 `suggestPartyCombo`、本场忌口）。  
- **成员数量**：不设免费上限；家庭构成是推荐前提，**不进会员墙**。  
- **引导 / onboarding / 首次填成员与基础忌口**：禁止广告与会员弹层。  
- **无广告期会员权益（可卖）**：**换菜不限次**（相对免费日 **3** 次）；日常总菜数更高或不限；可选导出 / 周菜单整理（若做）。文案**不要主打「去广告」**。  
- **广告上线后加成**：去广告（清单 Banner/原生、开屏等）；换菜免看激励。  
- **忌口变现**：**暂不定**（基础忌口须保持可免费设置；特殊食物 × 激励 7 日 / 会员长期仍为候选，另议）。  
- **待选项仍只记不做**（定权益包时再裁）：忌口条数上限、预算控制——见方案 A 表。（「无限制换方案」已收为会员正式卖点：不限次+频控。）

### 转化触点

| 时机 | 无广告期 | 有广告后 |
|------|----------|----------|
| 换菜触顶（日 3 用尽） | **主：去买菜**；次：开通会员 | **主：去买菜**；次：看视频再换 1 次 / 开通会员（激励日上限满则无视频项） |
| 日常总菜数超 12 | 软裁切 + 会员引导（方案仍可买） | 同左；会员不限 |
| 清单页 | 弱入口讲换菜不限 / 菜数权益 | 加「会员免广告」 |
| 「我的」 | 会员状态与开通 | 同左 |
| 引导 / 成员编辑 | **不出现** | **不出现** |

漏斗：**免费跑通主链路（含可去买菜）→ 想再换菜时碰壁 → 视频或会员**；清单/开屏广告上线后再加 **嫌广告 → 会员**。激励本身不是主要 ARPU，是转化钩。

### 分期落地（最终路径）

| 阶段 | 变现 | 要点 |
|------|------|------|
| **0 · MVP** | 无收费 | 埋点：采纳率、进清单停留、进场确认、换菜、换菜触顶、回访、日常/聚会占比、日常出菜道数分布；清单页预留广告容器（`ADS_ENABLED=false`） |
| **1 · 会员轻上** | **方案 A** | 换菜：免费日 **3**；会员不限次+频控；触顶不挡去买菜；日常总菜数软限；**不含去广告/激励**（无激励时触顶：去买菜 + 会员） |
| **2 · 流量主达标** | **叠加方案 C** | 清单广告（原生/Banner 等）+ 开屏克制 + **换菜激励看 1 得 1**（建议激励日上限）；会员 **去广告 + 免激励** |
| **3 · 可选扩展** | 候选 B / D / E | 视数据与合作再开；E 待节日/策划能力再议；忌口变现另议 |

## 一、变现原则

1. **主链路免费、可完成**：确认食材 → **日常 / 聚会**推荐 → 购买清单 → 饮食记录，均可走完，不设付费墙（不以锁聚会作墙）。  
2. **今天要吃饭**：换菜额度用尽只软挡「再换」；**当前方案必须仍能去买菜**，不以「明天再来」为主出口。  
3. **变现贴已产生价值的时刻**：广告钉在摊位对照清单；会员钉在「还想再换」与日常菜数超限——都不是引导填档阶段。  
4. **先轻会员收现金，广告达门槛再叠加**：未开通流量主时不假装「去广告」为主卖点；激励参数优先促转而非堆 ARPU。  
5. **合规**：流量主按微信规则；分佣若未来启用须走正规联盟；不做敏感画像售卖。  
6. **基础画像不作墙**：成员数不限；引导页无广告无会员；基础忌口须可免费设置（特殊忌口另议）。

## 三、方案详解

### 方案 A：会员订阅（阶段 1 主力 · 已定可先上）

**怎么赚**：按月 / 季 / 年收取会员费（定价待有使用数据后定；行业常见参考：月 6–15 元，年 48–98 元）。

**免费 vs 会员（权益以本表为准；可裁剪）**：

| 能力 | 免费 | 会员 |
|------|------|------|
| 日常推荐（整次总菜数） | ✓ 总道数 ≤ **12**（软限） | ✓ **不限** |
| **换菜**（日常+聚会共用入口） | ✓ 自然日 **3** 次；激励可用后一律看 1 得 **1**（建议激励完播另有日上限）；触顶仍可去买菜 | ✓ **不限次**（免激励）；**防刷频控**仍生效 |
| **聚会**推荐（自动 combo、本场忌口） | ✓ 完整主流程；**菜数不按 N 限** | ✓ 同左 |
| 购买清单 | ✓ | ✓ |
| 家庭成员数 | ✓ **不限** | ✓ 不限（非卖点） |
| 多顿 / 多日 | ✓ 计入整次总菜数，与「1 顿多菜」同一帽 | ✓ 同上帽放宽 |
| 导出清单、周菜单 | — / 弱 | ✓（若做） |
| 去广告（含聚会第 2 条） | — | ✓ **仅阶段 2 清单原生上线后写入售卖与实现** |
| 节日专题菜单等（若日后恢复） | — / 试用 | ✓ 或并入 E |

**会员能力待选项（只记录；忌口是否启用另议，其余定权益包时再裁）**：

| 待选项 | 含义（草稿） | 备注 |
|--------|--------------|------|
| **忌口有上限** | 免费档家庭忌口 / 相关勾选项有条数上限；会员提高或不限 | **2026-11-17：暂不定要不要做**。若做：勿做成「有忌口才能用」；主链路仍须能设基础忌口；**禁止在引导页推销**。 |
| **特殊忌口食物（激励广告 × 会员）** | 需指定**特殊食物**类忌口时：非会员可看 **1 次激励广告** 换 **7 天**可设置/生效；期满再设须再看广告。会员则**长期有效** | **暂不定**；与「忌口条数上限」可并存或互替。见下方简评。 |
| **预算控制** | 会员可设做饭时间 / 花费等预算约束并参与推荐；免费档弱化或不开放 | 与画像「做饭预算」字段可衔接；规则未设计。 |
| **无限制换方案** | （已升格）见上表「换菜」会员不限次 | 不再仅作待选项；实现时记得频控。 |

**简评 · 特殊忌口食物 × 广告 / 会员（2026-11-04 记；2026-11-17 仍未拍板）**

- **机制草稿**：基础忌口词表（猪肉类/海鲜等）仍免费可设；「特殊食物」须额外开通——非会员激励视频 → 7 日有效；会员永久。  
- **优点**：贴真实刚需，转化场景清晰；可与激励广告同测。  
- **风险**：须定义「特殊」vs 基础；过敏用户对催费容忍度低；到期后已写入项冻结/清空/只读需另设计；**不可在引导页出现**。  
- **结论**：仍为候选；**是否进正式权益包另议**，不阻塞阶段 1 会员（额度 + 菜数）上线。

**优点**：与换菜日额度、日常菜量复杂度绑定；可预期现金流；不依赖流量主门槛。  
**风险**：过早硬墙伤获客 → 故用软限 + 主链路免费；会员不限次须频控防拖库；**勿用锁聚会 / 锁成员换转化**。  
**要点**：卖的是换菜自由与「一次多出几道菜」，不是「能不能请客、能不能加家人」。

### 方案 C：微信流量主广告（阶段 2 叠加 · 位已预埋）

**怎么赚**：开通小程序流量主，按有效曝光与微信分成（比例以后台规则为准）。

**插入场景（已定）**：
- 用户在**线下菜场/摊位挑真菜**时，手机停留在购买食材清单页 → 底部或列表间原生广告伴随曝光。  
- **日常**：清单原生 **1 条**（底部或主料/调味分段间隙）。  
- **聚会**：桌菜通常更多，清单更长，允许 **第 2 条**原生，仍放间隙或第二条底部，**禁止插屏**。  
- 不是 App 内「勾选常见菜」页面；该页停留短，且尚未进入采购动作。  
- **未开通前**：容器可留，`ADS_ENABLED=false`，不渲染、不在会员文案主打去广告。

**形态优先级**：
1. 购买食材页原生模板（主；聚会可 2 条）  
2. 激励视频兑换换菜次数（辅；一律看 1 得 1；触顶须保留「去买菜」；与会员并列触达）  
3. 封面广告低频（辅）  
4. 插屏：默认关闭，尤其禁止盖住清单对照；禁止引导页

**优点**：开发成本低；吃的是采购停留时长；与会员「去广告」形成第二转化钩。  
**风险**：未达门槛前无广告收入（由阶段 1 会员补）；广告质量差会影响信任 → 频次与位置要克制。  
**要点**：清单支持「已买」勾选、亮屏对照，拉长有效停留。

---

### 方案 B：食材 / 生鲜电商分佣（候选）

**怎么赚**：清单页跳转美团买菜 / 朴朴 / 盒马等，按成交佣金；或本地生鲜 CPS。

**产品落点（若启用）**：清单上「一键按清单线上买」弱入口，线下用户可忽略；不替代摊位采购主路径。

**为何暂列候选**：主场景是线下菜场对照清单；强推线上易与「摊位挑菜」心智冲突。有明确线上需求或合作后再评。

---

### 方案 D：品牌 / 本地 B 端合作（候选）

**怎么赚**：调味/厨电/预制菜场景露出；本地菜场「在售同步」SaaS；匿名聚合报告（合规脱敏）。

**为何暂列候选**：需销售与数据成熟度；过早接品牌易伤中立推荐信任。

---

### 方案 E：聚会策划增值 & 轻企业服务（候选 · 更靠后）

**怎么赚**：若日后恢复节日标签或「桌宴策划」深度能力，可按次付费或纳入会员；小 B 一周菜单订阅。

**为何暂列候选（且比原先更靠后）**：当前聚会已是免费主路径；节日选择已隐藏。待有节日/策划差异化后再与会员合并评估。

## 四、不推荐过早做的模式

| 模式 | 原因 |
|------|------|
| 自营生鲜电商 | 库存履约重，偏离决策工具定位 |
| 出方案前 / 清单对照时强插屏 | 破坏菜场短决策与对照采购体验 |
| 主推荐结果里强插商品 | 破坏中立搭配信任 |
| 引导页 / 成员编辑上广告或会员 | 极大打击首次使用兴趣 |
| 限制家庭成员数量 | 成员是推荐前提，不是增值 |
| 用「锁聚会」或硬拦「只能 1 顿」作墙 | 聚会是主路径；顿数可被「1 顿多菜」绕过，改用整次总菜数软限 |
| 无数据即推高价会员 | 伤获客与口碑 |
| 贩卖忌口等敏感画像 | 合规与舆论风险高 |

## 五、决策记录

| # | 问题 | 结论 |
|---|------|------|
| 1 | 第一笔钱靠会员还是分佣？ | 分佣（B）不进主路径。战略上重视会员（A）；**2026-11-17**：因广告暂不可接，**落地改为先轻会员（A）→ 再广告（C）**。 |
| 2 | 清单页是否上「去美团等下单」？ | **现阶段不上主路径**。B 保留候选，若做仅弱入口、可关闭。 |
| 3 | 会员年费低价还是中价？ | **暂不定价**。等阶段 1～2 用留存、采纳、清单停留、换菜触顶率、激励完成率、日常超 N 率等再定；文档仅保留 48–98 元/年作行业参考。 |
| 4 | 非日常收口为聚会后，广告/会员要改吗？ | 广告：用语改聚会，仍日常 1 / 聚会可 2。会员：**聚会主流程免费**；不卖锁聚会。 |
| 5 | 广告未开通时能否先会员？ | **能**。阶段 1 卖换菜不限次 + 日常总菜数；去广告与激励加次待阶段 2。 |
| 6 | 成员数、引导页变现？ | **成员不限**；**引导/onboarding 禁止广告与会员**。 |
| 7 | 多顿 vs 一顿多菜怎么限？ | **日常整次总菜数 ≤12** 软限；会员不限；聚会免检；换菜不重置菜数帽。不单独立「只能 1 顿」墙。 |
| 8 | 忌口进不进会员？ | **暂不定**；基础忌口须免费可设；特殊食物方案仍候选另议。 |
| 9 | 换菜频率怎么定？ | **日限制**（不用周限制）。免费自然日 **3** 次（日常+聚会一池）。用尽后激励一律 **看 1 得 1**（建议激励完播日上限如 3）。会员 **不限次** + 频控。 |
| 10 | 额度用尽能否强推会员、不让继续？ | **否**。只软挡「再换菜」；**当前方案必须仍可去买菜**。触顶主按钮是「去买菜」，会员/视频为次。人要吃饭，不能以「明天再来」为主出口。 |
| 11 | 激励是否为了拉齐会员 ARPU？ | **否**。激励对开发者 ARPU 贡献有限；参数以促转与体验为准。清单广告才是广告侧主量。会员月费调研对照曾用 ¥6.6，正式定价待定。 |
