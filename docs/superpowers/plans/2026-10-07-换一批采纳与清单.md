# 换一批 / 采纳 / 购买清单 / engage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在推荐页接上换一批、不行（可选原因）、可以、查看清单；购买清单页主料前调味后并可勾已买；推荐页可见累计 ≥30s 写 `engage`。验收以 **`npm test` 为主**，开发者工具人工点验暂缓。

**Architecture:** 清单聚合与排序为可单测纯函数；`recommend` 云函数按 `action` 分发 `swap|reject|accept|engage`；长期降权写入 `users.rejectDownranks`（recipeId 列表），组菜时降权但不硬删（相对 session `excludedDishIds`）；小程序推荐页接按钮与停留计时，清单页读 plan 快照。

**Tech Stack:** 同前；`node --test`；云函数 continue vendor `homePlans.js`。

## 验收状态

**已验收 · 2026-10-08**（`npm test` + 微信开发者工具人工点验）。

## Global Constraints

- swap：当次 `excludedDishIds` + 重跑，**不**写长期降权。  
- reject：弹原因可选可不选；记 feedback + 并入 excluded + 重跑；**写** `users.rejectDownranks`。  
- accept：**不**写 meal_logs；跳转清单 `accepted=true`；日常 home 可写回 defaultPeopleCount/combo（若 scene 带 persist 或人与搭配相对默认有改——本切片：accept 时若 daily 则写回当前 scene 的 people+combo）。  
- ~~查看清单预览~~：**已取消**；进清单只走「去买菜」。方案卡每菜「食材 名」或「名等N种」。  
- engage：可见 ≥30000ms 才写；`engagedAt` 只写一次。  
- 清单：主料未持有优先，已有主料次之，调味靠后；勾选已买本地 storage。  
- 不做：进场确认、饮食记录写入、非常规方案、埋点全表、广告。

### Task 3: 云函数 `swap` / `reject` / `accept` / `engage`

**Files:** Modify `cloudfunctions/recommend/index.js`；README Slice 3 准备（增量）

共用：按 `requestId` + uid 查 recommendations；重跑时读原 scene/selected + excludedDishIds。

| action | 行为 |
|--------|------|
| swap | 当前 plans 的 recipeId → excluded；swapCount++；feedback swap；rebuild plans；update doc；return plans |
| reject | event.reason?；event.planIndex?；同 swap 更新 excluded；feedback reject；users.rejectDownranks upsert ids；rebuild |
| accept | event.planIndex；accepted true + timestamps；不写 meal_logs；daily 写回 users defaults；return ok |
| engage | event.dwellMs, planIndex；若无 engagedAt 且 dwellMs>=30000 写 engagedAt/engagedPlanIndex；可更新 dwellMs |

- [x] 实现 + vendor 同步  
- [x] commit `feat: recommend swap reject accept engage actions`
