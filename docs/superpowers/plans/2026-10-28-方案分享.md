# 方案分享（点对点）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 自产方案可从推荐卡 / 食材页 / 已选方案调起微信分享；落地只读预览菜名+完整用料；「保存到我的」幂等并入已选方案并打「分享」标；收到的条目不可再分享、无已吃。

**Architecture:** 新集合 `plan_shares`（不可变快照）+ `received_plans`（接收者挂载）。云函数 `share`：`create` / `get` / `save`。`listAccepted` 合并自产与收到项。落地页 `pages/sharedPlan/sharedPlan`；三处 `open-type="share"` + `onShareAppMessage` 异步 `create`。快照用料用现有 `buildShoppingList` 聚合（忽略 bought）。

**Tech Stack:** 微信小程序原生；云开发 Node；`node --test`。

**Spec:** `docs/superpowers/specs/2026-10-28-方案分享-design.md`

## 实现拍板（设计二选一处）

| 项 | 本计划选定 |
|----|------------|
| 接收者挂载 | 集合 **`received_plans`**（不污染 `recommendations`） |
| 列表合并 | `recommend.listAccepted` **扩展**返回 `source: 'own' \| 'shared'` |
| 快照过期 | MVP **不过期**；`get` 仅校验文档存在 |
| 卡片 title | 菜名用 `、` 拼接，超长截断约 30 字 + `…`；无自定义封面（系统默认） |
| 预览登录 | `get` **不要求**已有 users 文档；有 OPENID 即可读。`save` / `create` 必须已登录 uid |

## Global Constraints

- 快照创建后不可变；完整用料，无 bought / 步骤。  
- 收到的：无分享、无去买菜、无 plan_ate。  
- `(ownerUid, shareId)` 保存幂等。  
- 同一分享人同一 `(requestId, planIndex)` 可复用 `shareId`。  
- 非社区 / Feed / 排行榜。

### Task 2: 云函数 `share`（create / get / save）

**Files:**
- Create: `cloudfunctions/share/package.json`
- Create: `cloudfunctions/share/planShare.js`（`cp` 自 `_shared`）
- Create: `cloudfunctions/share/shoppingList.js`（`cp` 自 `_shared`，供 planShare 依赖）
- Create: `cloudfunctions/share/index.js`

**Interfaces:**

#### `create`

入参（二选一）：

```ts
{ action:'create', requestId: string, planIndex: number, entry?: string }
// 或已选自产：
{ action:'create', recommendationId: string, entry?: 'accepted' }
```

逻辑：

1. resolveUid；无用户 → `NO_USER`  
2. 加载 `recommendations`：`requestId`+`uid` 或 `doc(recommendationId)`；校验 `doc.uid === uid`  
3. `planIndex`：显式传入，或自产已选时用 `acceptedPlanIndex`  
4. `plan = doc.plans[planIndex]`；无则 `PLAN_NOT_FOUND`  
5. 查复用：`plan_shares.where({ createdBy: uid, sourceRequestId: doc.requestId, sourcePlanIndex: planIndex }).limit(1)`  
6. 若无：`buildSnapshotPayload` + `add`；`categoryByName` 可从 `doc.selectedIngredients` 建 map（`name→category`），缺则 `{}`  
7. 返回 `{ ok, shareId }`

#### `get`

```ts
{ action:'get', shareId: string }
```

- **允许**仅有 OPENID、尚无 users（预览）：不 resolveUid 失败则仍可读快照  
- 返回 `{ ok, share: shapeShareView, saved: boolean }`  
  - 若能 resolveUid：查 `received_plans` 是否已有 `(ownerUid, shareId)` → `saved`  
  - 否则 `saved: false`

#### `save`

```ts
{ action:'save', shareId: string }
```

1. 必须 uid  
2. 读快照；无则 `NOT_FOUND`  
3. 若已有 `received_plans` 同 `(ownerUid, shareId)` → 返回已有 `{ ok, saved: true, id }`（幂等）  
4. 否则 `add`：

```js
{
  ownerUid: uid,
  shareId,
  source: 'shared',
  savedAt: db.serverDate(),
  dishNamesSummary: dishes.slice(0, 6).map(d => d.name), // 冗余列表
  sharerNickname: snap.sharerNickname || null,
  createdBy: snap.createdBy
}
```

索引（控制台）：

- `plan_shares`：`createdBy + sourceRequestId + sourcePlanIndex`  
- `received_plans`：`ownerUid + shareId`（唯一语义靠查询幂等）；列表：`ownerUid + savedAt desc`

**Interfaces:**
- `shapeSharedListItem(receivedDoc, shareDoc?) →`  
  `{ source:'shared', shareId, savedAt, recommendationId:null, requestId:null, dishes:[{name,ate:false}], scene:null, badge:'分享', … }`  
- 列表时间键：自产用 `acceptedAt`，收到用 `savedAt`；合并后按时间倒序再 cursor 分页（MVP 可：**先各取一页再 merge sort**，或收到的单独二次查询 merge）。

**推荐实现（简单稳）：**

1. 仍按现逻辑拉自产 `accepted` 页（limit 稍放大或保持）。  
2. 另查 `received_plans.where({ ownerUid }).orderBy('savedAt','desc').limit(PAGE_SIZE)`（带 cursor 时两边都应用时间游标较难）。  

**MVP 分页策略（写进代码注释）：**

- 首次：取自产最新 N + 收到最新 N，内存按 `sortAt` 降序 merge，切 `PAGE_SIZE`，`nextCursor` 用最后一项的 `{ sortAt, kind, id }`。  
- 翻页：两边用 cursor 过滤后各再取，再 merge（与 meal 列表同类近似即可；总量不大可接受）。  

每条返回增加：

```ts
source: 'own' | 'shared'
shareId?: string
badge?: '分享'
```

自产项 `source: 'own'`。收到项 **不**查 meal_logs / ate。

#### 5.1 推荐页

每张方案卡标题行旁增加：

```xml
<button
  class="plan-share"
  size="mini"
  open-type="share"
  data-plan-index="{{item.planIndex}}"
  data-entry="recommend"
  hover-class="tap-hover"
>分享</button>
```

```js
onShareAppMessage(res) {
  const entry = (res.target && res.target.dataset.entry) || 'recommend'
  const planIndex = Number(
    (res.target && res.target.dataset.planIndex) != null
      ? res.target.dataset.planIndex
      : 0
  )
  const requestId = this._requestId || (this.data && this.data.requestId)
  track('plan_share_create', { entry })
  return callCloud('share', {
    action: 'create',
    requestId,
    planIndex,
    entry
  }).then((r) => {
    const shareId = r && r.shareId
    const plan = (this.data.plans || [])[planIndex]
    const dishes = []
    ;((plan && plan.meals) || []).forEach((m) => {
      ;(m.dishes || []).forEach((d) => dishes.push({ name: d.name }))
    })
    // 若页面 meals 已分组，按现有数据结构取菜名
    return {
      title: shareCardTitle(dishes) || '买菜做什么 · 方案',
      path: '/pages/sharedPlan/sharedPlan?shareId=' + encodeURIComponent(shareId || '')
    }
  }).catch(() => ({
    title: '买菜做什么',
    path: '/pages/index/index'
  }))
}
```

`recommend.json` 无需改；页面需支持分享（默认可）。按钮样式勿抢「去买菜」主 CTA（outline / 文字钮）。
