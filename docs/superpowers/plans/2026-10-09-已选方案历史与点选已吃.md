# 已选方案历史与点选已吃 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户可在「我的 → 已选方案」按时间倒序回顾已采纳方案（分页 7），并在卡片内点选/取消已吃（即时写 `plan_ate` / 删日志）；进场确认继续排除已标记菜。

**Architecture:** 列表读现有 `recommendations`（`accepted: true`）经 `recommend.listAccepted`；点选写/删 `meal_logs`（`source=plan_ate`，一道菜一条）经 `meals.planAteOn` / `planAteOff`。纯决策函数放 `_shared` 并 vendoring 到云函数目录；小程序新建 `pages/acceptedPlans`，勾选样式复用进场确认 chip。

**Tech Stack:** 微信小程序 + 云开发；`node --test`；无新 npm 依赖。

## Global Constraints

- 「去买菜」**不**自动写 `meal_logs`（已有行为保持）。
- 点选即写、再点即取消；**无**单独提交按钮。
- 历史点选：**一道菜一条**日志，`source: 'plan_ate'`，必带 `requestId` / `recommendationId`。
- 列表每页 **7**；`acceptedAt` 倒序；cursor 分页。
- 勾选视觉与进场确认一致（chip + `✓`）。
- 列表顶长期小字 + 首次悬浮气泡（storage key：`cookthis_plan_ate_tip_seen`）。
- **不在本计划重做**已吃删除：`meals.remove` + 记录页删除 UI **已存在**，仅复用 `remove` 给 `planAteOff`。
- 进场确认去重：已有「锚点后 meal_logs 菜名」逻辑；`plan_ate` 写入后自动生效，**不必改** `confirmCandidates` 算法（加一条回归测即可）。

### Task 1: `listAccepted` 纯函数 + 单测

**Files:**
- Create: `cloudfunctions/_shared/listAccepted.js`
- Create: `cloudfunctions/_shared/listAccepted.test.js`

**Interfaces:**
- Produces:
  - `PAGE_SIZE = 7`
  - `normalizeDishName(name: string): string` — 去空白（与 confirmCandidates 一致）
  - `collectAteNamesByRequestId(mealLogs: object[]): Map<string, Set<string>>` — key=`requestId`，value=该请求下所有日志 `dishNames` 归一化名集合（不限 source，便于回显）
  - `shapeAcceptedItem(doc, ateNamesSet): object | null` — 无 `accepted` 或无 plan 则 `null`；否则返回：

```js
{
  recommendationId: doc._id,
  requestId: doc.requestId,
  acceptedAt: doc.acceptedAt,
  scene: doc.scene || null,
  plan: doc.plans[doc.acceptedPlanIndex] || null,
  dishes: [{ recipeId, name, meatVeg, ate: boolean }, ...], // 展平 plan.meals[].dishes
  ateDishNames: string[] // 原始展示名中已 ate 的
}
```

  - `applyAcceptedCursor(rows, cursor): object[]` — `cursor` 形如 `{ acceptedAtMs: number, id: string } | null`；过滤掉「严格晚于上一页末条」之后应跳过的项（见实现约定），再 `slice(0, 7)`。**本任务只测内存排序后的切片**；云查询仍 `orderBy acceptedAt desc` + `limit(8)` 等在 Task 3 接线。

Cursor 约定（与 Task 3 一致）：客户端传上一页最后一项的 `acceptedAt`（ISO 或 ms）与 `recommendationId`；服务端查询 `acceptedAt <= cursorAt`，再在内存丢掉 `acceptedAt === cursorAt && _id >= cursorId` 的已见项（或等价稳定序），取 7 条。纯函数测「已排序数组 + cursor → 下一批」。

### Task 2: `planAte` On/Off 纯函数 + 单测

**Files:**
- Create: `cloudfunctions/_shared/planAte.js`
- Create: `cloudfunctions/_shared/planAte.test.js`

**Interfaces:**
- Produces:
  - `planAteOnDecision({ uid, requestId, recommendationId, dishName, existingRow })`  
    - 校验：缺 `requestId`/`dishName` → `{ ok:false, error:'...' }`  
    - 若 `existingRow` 已存在（同 uid+requestId+归一化菜名的 plan_ate）→ `{ ok:true, noop:true, logId: existingRow.logId }`  
    - 否则 → `{ ok:true, noop:false, record: { uid, logId: null, dishNames:[trimmed], source:'plan_ate', recommendationId, requestId, ... } }`（`logId` 由云函数生成）
  - `planAteOffDecision({ uid, requestId, dishName, existingRow })`  
    - 无行 → `{ ok:true, noop:true }`  
    - 有行 → 调用方再用 `planRemoveMealLog`；本函数返回 `{ ok:true, noop:false, logId }`
