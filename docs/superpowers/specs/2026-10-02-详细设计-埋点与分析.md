## 1. 目标

- 全端统一事件名与属性，便于日后 App 共用  
- **已放出能力全打**；未放出入口（拍照/语音补菜等）不打占位事件  
- **所有「跳过 / 先逛逛 / 暂不」类按钮必须打点**，用于判断哪些浮层/步骤帮助弱、被跳过过多  
- 支撑：进场完成率、换一批、采纳进清单、记录、回访、首启转化、画像缺口等

## 2. 存储与上报

### 2.1 `events` 集合

| 字段 | 说明 |
|------|------|
| `uid` | 未登录可空 |
| `event` | 事件名 |
| `props` | object |
| `platform` | `mp` \| `ios` \| `android` |
| `loginProvider` | 可选：`wechat_mp` 等 |
| `appVersion` | 小程序版本 |
| `sessionId` | 会话 |
| `requestId` | 可选，推荐会话 |
| `ts` | 客户端时间 |
| `serverTs` | 服务端写入时间 |

### 2.2 客户端

- 统一 `track(event, props)` → 本地队列 → `analytics.trackBatch`  
- **禁止** props 写入 openid、完整手机号、`userNo` 以外的可枚举身份（`userNo` 仅允许出现在首启本人事件）  

### 2.3 云函数 `analytics.trackBatch`

- 校验登录态（允许少量匿名 `app_open`）  
- 批量 insert；超限丢弃并打日志

## 3. 跳过类按钮（强制）

**原则：** 文案为「跳过」「先逛逛」「暂不设置」等、表示**不完成当前引导/浮层**的出口，一律打点；尽量带 `surface` / `source` / `step`，便于按页面汇总跳过率。

| 表面 | 按钮 | event | props |
|------|------|-------|-------|
| 进场确认 | 跳过 | `confirm_sheet_skip` | — |
| 菜场规模 | 跳过（按默认中） | `market_scale_sheet_skip` | `source`: `sheet` \| `page_switch` |
| 日常轻量补全 | 跳过 | `profile_lite_skip` | `source`（如 `pre_create_sheet`） |
| 完整引导单步 | 跳过 | `onboarding_step` | `step`, `skipped: true` |
| 首页完善家庭提示 | 先逛逛 | `onboarding_tip_skip` | — |
| 首启仪式 | 先逛逛 | `user_no_reveal_ack` | `via: browse` |
| 首启仪式 | 完善偏好 | `user_no_reveal_ack` | `via: onboarding`（非跳过，对照用） |
| 不行原因 | 跳过（不选原因） | `recommend_reject` | `skippedReason: true` |
| 做饭水平重测 | 取消/返回 | `cook_skill_retake_cancel` | — |

新增跳过入口时：**先补本表，再合代码**。关闭/点遮罩若产品规定「不算跳过、须点按钮」则可不打 skip（如首启遮罩不关）。

## 5. 与验证指标映射

| 指标 | 算法思路 |
|------|----------|
| 进场完成 | `confirm_sheet_submit` / `market_entry` |
| 浮层被跳过过多 | 各 `*_skip` / `onboarding_tip_skip` / `user_no_reveal_ack(via=browse)` 相对对应 `*_show` |
| 换一批 | `recommend_swap` / 有 `recommend_show` 的会话 |
| 采纳进清单 | `recommend_accept` → `shopping_list_open(accepted=true)` |
| 首启→引导 | `user_no_reveal_ack(via=onboarding)` / `user_no_reveal_show` |
| 7 日回访 | 同一 uid 两日 `app_open`/`session_start` |
| 会员开通 | `membership_pay_click` → `membership_pay_success` / `membership_page_show`；是否到账以服务端 `membership_orders.status=paid` 为准 |
