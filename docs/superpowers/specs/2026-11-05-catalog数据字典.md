## 2. 食材 `ingredients-builtin.json`

数组；每条导入云库时通常加 `_id = id`。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 稳定 id，如 `ing_egg`、`ing_<hash>` |
| `name` | string | 展示/匹配名（与菜谱主料字符串对齐） |
| `category` | string | 品类。历史英文码（`meat`/`leaf`/…）仍可能存在；正式 taxonomy 为中文（见 §6），运行时 `normalizeCategory` 可映射 |
| `cities` | string[] | `[]` = 全国；非空 = 仅这些城 |
| `kind` | `main` \| `seasoning` | 主料 / 调味 |
| `availability` | `year_round` \| `seasonal` | **仅 main**；调味一般不写 |
| `onConfirmPage` | boolean | 是否进确认页主列表（多为时令主料）；调味常省略 |
| `sort` | number | 越小越靠前；截断用 |
| `avoidTags` | string[] | 忌口 code（如 `pork`）；由忌口底稿导出 |
| `source` | string | 常 `builtin` |
| `updatedAt` | ISO string | 更新时间 |

**导入文件** `ingredients-for-import.json`：JSON Lines，每行一个对象，含 `_id`（= `id`）+ 同上字段。

## 3. 菜谱 `recipes-builtin.json`

数组。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 如 `rcp_potato_pork`、`rcp_xf_<hash>` |
| `name` | string | 菜名 |
| `mainIngredients` | string[] | 主料名；须能在食材表（或别名归一后）命中 |
| `seasonings` | string[] | 调料名 |
| `meatVeg` | enum | 结构角色，见下 |
| `tasteTags` | string[] | 口味，见下 |
| `dishForms` | string[] | 菜式形态，见下 |
| `stapleForms` | string[] | 主食形态，见下；可 `[]` |
| `cities` | string[] | `[]` = 全国；非空 = 城限定（城菜 Tab 可改全国） |
| `minutes` | number | 大约分钟 |
| `difficulty` | `easy` \| `home` \| `advanced` | 可选。显式做法难度，见 §3.1。缺省不写 |
| `servings` | number | 大约人数 |
| `enabled` | boolean | `false` = 下架不参与推荐 |
| `cuisineTags` | string[] | 可选；如 `home_style`、地方菜系 code |
| `stepsBrief` | string | 可选；简要步骤 |

### 3.1 枚举

**`meatVeg`**

| 值 | 含义 |
|----|------|
| `meat` | 荤菜 |
| `veg` | 素菜 |
| `soup` | 汤 |
| `staple` | 主食（面/饺等占位） |
| `other` | 其它 |

**`tasteTags`**（可多选）

| 值 | 含义 |
|----|------|
| `light` | 清淡 |
| `normal` | 适中 |
| `heavy` | 偏重 |
| `spicy` | 辣 |

**`dishForms`**（常见）

| 值 | 含义 |
|----|------|
| `stir_fry` | 炒 |
| `braise` | 烧/焖/烩 |
| `steam` | 蒸 |
| `soup` | 汤 |
| `noodle` | 面 |
| `dumpling` | 饺 |
| `hotpot` | 火锅 |

**`stapleForms`**：`rice` / `noodle` / `dumpling` 等；表示更适合配什么主食。

**`difficulty`**（建议全量有值，便于维护时看清现状；有合法值时推荐侧直接用）

| 值 | 含义 |
|----|------|
| `easy` | 轻松上手 |
| `home` | 家常 |
| `advanced` | 进阶 |

缺省时推荐侧按 `cloudfunctions/_shared/cookSkill.js` 的 `inferDifficulty` 兜底：`minutes <= 20` 且 `dishForms` 不含 `steam` / `hotpot` / `dumpling` / `bake` → `easy`；`minutes >= 50` 或含上述形态 → `advanced`；其余 → `home`。

回填脚本 `scripts/backfill-recipe-difficulty.js`：默认只出报告；`--apply-probe-names` 对探针菜名精确匹配且尚无字段时写入探针档；`--apply-inferred` 对其余空白写入与运行时相同的推断（**不覆盖**已有值）。两旗可并用。改档后跑 `node scripts/import-recipes.js` 再导入云库。

推荐拉池：`cookSkill === beginner` 时 `where` 为 `cities` + `difficulty ∈ ['easy','home']`（见设计 [`2026-11-05-做饭能力与菜品难度-design.md`](./2026-11-05-做饭能力与菜品难度-design.md) §4.1）。云库集合 `recipes` 须建**普通复合索引** `cities` ASC + `difficulty` ASC（勿勾唯一）；文档须含 `difficulty` 后再指望该查询命中。

**导入文件** `recipes-for-import.json`：JSON Lines，每行一道菜（字段同 builtin；控制台若需要 `_id` 可与 `id` 相同）。

## 4. 别名

### 4.1 `aliases.json`

```jsonc
{
  "_meta": { "note": "...", "sources": ["aliases-editor.json"] },
  "鸡爪": ["鸡脚", "凤爪"],   // 键 = 通用名；值 = 别名列表（不含键自身亦可）
  "...": []
}
```

匹配时键与值同属一组；热度分档对组内取 **max(score)**。

### 4.2 `aliases-editor.json`

```jsonc
{
  "_meta": {},
  "categories": {
    "肉类": {
      "groups": [
        { "id": "…", "canon": "三线肉", "aliases": ["三层肉", "五花肉"] }
      ],
      "ungrouped": ["…"]
    }
  }
}
```

品类键与 `ingredients-all-by-category` taxonomy 对齐。

## 5. 全量品类 `ingredients-all-by-category.json`

```jsonc
{
  "description": "…",
  "source": "ingredients-all.json",
  "total": 1265,
  "categories": {
    "肉类": ["猪肉", "…"],
    "调味": ["盐", "…"]
  }
}
```

- 每名 ideally 只属一个类。  
- 分档归类、热度表 `category`、别名编辑器品类以此为准。

### 5.1 中文 taxonomy（现行）

`肉类` · `内脏` · `火锅` · `菜叶` · `瓜果` · `根茎` · `水果` · `豆类` · `豆制品` · `主食` · `菌菇` · `鱼` · `河鲜` · `海鲜` · `蛋奶` · `调味` · `其他`

英文旧码 → 中文见 `cloudfunctions/_shared/categoryTaxonomy.js`（`LEGACY_CATEGORY_MAP`）。

## 6. 热度 `ingredient-popularity.json`

```jsonc
{
  "_meta": {
    "builtAt": "…",
    "popularitySource": ["xiachufang-*-cleaned.json"],
    "categorySource": "ingredients-all-by-category.json",
    "categoryRule": "…"
  },
  "items": {
    "猪肉": { "score": 12345, "category": "肉类" },
    "三层肉": { "score": 12345, "category": null }  // 别名表面名常无 category
  }
}
```

- `score`：先按条目键加总菜谱 count，再别名组 **max** 写回组内各名。  
- `category`：只查 by-category 字面名；别名非通用名常为 `null`（分档用通用名再查类）。

## 7. 分城分档 `cities/{城}/ingredients-by-scale.json`

```jsonc
{
  "city": "北京",
  "categoriesTaxonomy": "ingredients-all-by-category",
  "scales": {
    "small" | "medium" | "large": {
      "seasonal": { "菜叶": [{ "name": "菠菜", "displayName": "菠菜" }] },
      "yearRound": { "肉类": [{ "name": "猪肉", "displayName": "精瘦肉" }] }
    }
  },
  "_meta": { "builtAt": "…", "unmapped": ["…"], "…" }
}
```

| 字段 | 说明 |
|------|------|
| `name` | 通用名（排序/匹配） |
| `displayName` | 城货架当地叫法（确认页展示） |
| `scales.*` | 小 ⊆ 中 ⊆ 大；类内按 popularity score 截断 |

城货架源：`cities/{城}/ingredients.json`（按粗类/当地名列表，结构随清洗产物，分档前须能映射到 by-category）。

## 8. 忌口底稿 `ingredients-major-minor.json`（相关字段）

| 字段 | 说明 |
|------|------|
| `avoidVocab` | `{ id, label }[]` 忌口组（含自定义 `gN`） |
| `avoidMembers` | `{ [avoidId]: string[] }` 组成员（通用名） |
| `aliasMap` / 大小类树 | 历史确认页/implies 底稿（与 avoid 并存） |

导出：按 members + 别名表面名重写 `ingredients-builtin[].avoidTags`。

## 9. 下厨房 TSV / cleaned（摘要）

**`dish-ingredients.txt`**

```text
# 菜名\t食材（顿号分隔）\t口味（重口味|清淡|正常口味）
蒜蓉西兰花	大蒜、西兰花	正常口味
```

**`review-titles-over-6.txt`**

```text
# 字数\t做过人数\t条目食材\t原菜名\t清洗菜名
```

**`xiachufang-category-results.cleaned.json`**（紧凑：一菜一行）

```jsonc
{
  "updatedAt": "…",
  "items": {
    "西兰花": {
      "categories": ["瓜果"],
      "count": 123,
      "recipes": [
        {"title":"蚝油蒜蓉西兰花","count":10,"ingredients":["蚝油","大蒜","西兰花"]}
      ]
    }
  }
}
```
