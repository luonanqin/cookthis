# 菜场规模与食材列表档位

日期：2026-10-14  
状态：已定稿（**后置**；先做食材名单与排序，规模档再实装）  
相关：确认页时令/四季截断；与进场确认弹层的时序。

## 背景

- 餐厅主料 ≠ 菜场必有；美团卖菜货架往往宽于普通线下菜场。  
- 用「小 / 中 / 大」菜场规模只调节**展示条数**，不改变「按城市 + 需求∩货架排序」的资格池。  
- 近距离常有中、小菜场并存，定位分不清时靠页内改档，不靠过紧的米数阈值。

## 决策摘要

| 项 | 结论 |
|----|------|
| 选项 | 小 / 中 / 大，均带说明文案；下方另有 **「不知道」** |
| 「不知道」 | 等价 **中**（与未选过时的默认一致） |
| 默认（从未选） | **中** |
| 首次出现 | 进确认页**之前**弹层（见时序，避免与进场确认叠弹） |
| 记住 | 写 **账号**（`users`）；换机仍在 |
| 再弹 | 相对上次选中锚点位移 **≥ 约 1 km**，或账号城市变更，或用户主动改档后可选「重选」 |
| 同片区换中↔小 | **不**靠定位；确认页提供改规模入口 |
| 时令主列表条数 | 小 **10** / 中 **20** / 大 **30**（后续可调） |
| 四季常见条数 | 小 **12** / 中 **18** / 大 **24**（初值，后续可调；仍折叠不占主列表） |
| MVP | **后置**（本期先定名单与排序；规模 UI 与截断接档后做） |

## 与进场确认是否冲突？

**会抢注意力，但可用时序避免「两层同时弹」。**

进入「今天菜场有什么」时约定：

```
首页点击
  → 若需进场确认：只弹进场确认（已吃）
  → 关闭后（确认/跳过）或无需进场确认
  → 若需选菜场规模：再弹规模（小/中/大/不知道）
  → 再进入确认页（食材+场景）
```

规则：

- **禁止**进场确认与规模选择叠在同一屏。  
- 规模已记住且未触发「走远了 / 换城」→ 进场确认后（或无需确认时）**直接进确认页**。  
- 同一小程序会话内规模弹层最多一次（避免进场确认→食材之间 GPS 抖一下再弹）。

## 选项文案（露出说明）

- **小菜场** — 小门面、路边摊位  
- **中菜场** — 小超市、连着几个门面  
- **大菜场** — 集贸市场、大超市、很多摊位  
- **不知道** — 按中菜场给你看常见菜（可之后再改）

## 数据（实装时）

```ts
// users（示意）
marketScale?: "small" | "medium" | "large"  // 「不知道」写入 medium
marketScaleAnchor?: { lat: number, lng: number, at: string }  // 选中时坐标

```

确认页改档：更新 `marketScale` + 刷新锚点；按新档重新截断时令/四季（已勾选尽量保留交集）。

## 截断规则

1. 候选池：按城过滤后的 ingredients（资格：排序分，餐厅需求 ∩ 美团货架等，见食材筛选讨论；本设计不定义打分公式）。  
2. 分成 `yearRound` / `seasonal`。  
3. 按档截断到上表条数（`sort` / 分数从高到低）。  
4. 主列表只渲染 seasonal；yearRound 折叠默认计入。

## 定位再问

- 阈值：**约 1 km**（直线距离）。  
- 无定位权限：沿用账号规模；**仅城市字段变化**时再弹。  
- 不用 500 m（易误弹）。

## 确认页改档入口

轻文案如「货架不对？切换菜场规模」→ 同款三档 + 不知道；改完即时重截列表。

## 非范围（本期后置时也不做）

- 用规模改城市或菜系  
- 规模影响推荐引擎（只影响确认页可选食材集合宽度）  
- 与进场确认合并成一个弹层
