# 菜场规模与食材列表档位

日期：2026-10-14  
修订：2026-10-27（名单排序与截断口径重定；§4.7 UI 详设）  
状态：已实现（见 [`../plans/2026-10-14-菜场规模与食材列表档位.md`](../plans/2026-10-14-菜场规模与食材列表档位.md)）

相关：确认页时令 / 四季；城市货架；下厨房热度；`ingredients-all-by-category.json`。

## 背景

- 餐厅主料 ≠ 菜场必有；美团货架往往宽于普通线下菜场。  
- 用「小 / 中 / 大」调节确认页**展示名单**（时令主列表 + 四季折叠）。  
- 城货架曾用美团类名且清洗度不一；分类以 **`ingredients-all-by-category.json`** 为准，热度以全国下厨房清洗结果为准。

## 决策摘要

| 项 | 结论 |
|----|------|
| 分类 | 仅用 `ingredients-all-by-category.json` 的类目（肉类 / 菜叶 / …）；城货架展示前须映射到此类 |
| 热度 | **全国一份**：清洗后菜谱的 `recipes[].count` 按食材加总；category + search **合并**，同 title **去重** |
| 缺热度 | 计 **1**（排类内末尾 → 只稳定出现在**大**档全量中） |
| 分档 | 全国序 ∩ **该城货架** 后，**每类内**倒排：小 = 前 ⌈n/3⌉，中 = 前 ⌈2n/3⌉，大 = 全部；n=0 不展示该类 |
| 绝对条数 | **不再使用** 时令 10/20/30、四季 12/18/24 |
| 时令 / 四季 | **保留**折叠结构；时令名 ∈ `seasonal-ingredients.json` ∩ 该档货架；四季 = 该档货架 − 时令；时令展示类目与四季一致，该类无时令则不展示该类 |
| 别名 | **不合并**成一条货架；计分取别名组 **max**；排序用通用名分数；**展示城货架当地名**；必须映射正确以免漏档 |
| implies / 大小类 | **本期不做**（忌口侧再优化） |
| 产物 | **预生成**分档 JSON（不运行时现算） |
| 选项 UI | 小 / 中 / 大 + 「默认中菜场」；贴底半屏详设见 **§4.7**；定位 / 账号见 §4 |

## 一、全国热度（构建脚本）

### 输入

- `data/recipes/xiachufang/xiachufang-category-results.cleaned.json`
- `data/recipes/xiachufang/xiachufang-search-results.cleaned.json`（若存在）
- `data/catalog/aliases.json`（计分 max）
- `data/catalog/ingredients-all-by-category.json`（类目归属）

### 规则

1. 合并两份 cleaned 的 `items`；同一食材键下 `recipes[]` 按 **`title` 去重**（保留首次或 count 较大者，实现时写死一种）。  
2. **忽略** `items[食材].count` 顶层字段。  
3. 对每个食材键 `ing`：只把该键下每道菜的 `recipe.count`（缺省当 0）**加到 `ing` 自己**；**不**把同一道菜的 count 加到 `ingredients[]` 里的其它食材。  
4. 无任何菜谱 / 加总为 0 → 热度记 **1**。  
5. 别名组：对组内每个表面名，排序用分 = `max(组内各名已加算分)`；**不**把组缩成一条展示名。  
6. 输出建议：`data/catalog/ingredient-popularity.json`（`name → { score, category }`），category 取自 by-category（一名多类时实现时取主类或首个，须文档化）。

## 二、分城分档名单（构建脚本）

### 输入

- 各城 `data/catalog/cities/{城}/ingredients.json`（须先洗到与 all 同级、并能映射到 by-category；脏名进 reject 或清洗流水线）  
- 全国热度表  
- `aliases.json`  
- `seasonal-ingredients.json`（扁平名集合即可，不依赖其内部「素菜时令」桶名）

### 步骤（每城）

1. 展开城货架所有当地名 → 经别名得到 **通用名**（用于排序与类目）；保留 **displayName = 当地名**。映射失败的名：记日志，**不得静默丢掉**（优先修清洗 / 别名，避免「本该进小档却因未映射消失」）。  
2. 按 by-category 归类；只保留能归类的名。  
3. **每类内**：候选 = 该类 ∩ 本城货架；按热度分降序（同分按通用名稳定序）；  
   - `n = 候选数`  
   - 小：前 `ceil(n/3)`  
   - 中：前 `ceil(2n/3)`  
   - 大：全部 `n`  
   - `n=0`：该类不出现在任何档。  
4. 对每一档结果再拆：  
   - **时令** = 该档名（当地名或通用名，实现时统一用「是否落在 seasonal 集合」：当地名或 canonical 任一命中即可）∩ `seasonal-ingredients.json`  
   - **四季** = 该档 − 时令  
   - 时令按类展示；某类时令为空则**不展示该类时令块**；四季同理。  
5. 写入预生成文件（建议其一）：

```text
data/catalog/cities/{城}/ingredients-by-scale.json
```

```jsonc
{
  "city": "北京",
  "categoriesTaxonomy": "ingredients-all-by-category",
  "scales": {
    "small": {
      "seasonal": { "菜叶": [{ "name": "菠菜", "displayName": "菠菜" }], "...": [] },
      "yearRound": { "肉类": [{ "name": "五花肉", "displayName": "五花肉" }], "...": [] }
    },
    "medium": { "seasonal": {}, "yearRound": {} },
    "large": { "seasonal": {}, "yearRound": {} }
  },
  "_meta": { "builtAt": "...", "popularitySource": "xiachufang-*-cleaned" }
}
```

`name` = 排序 / 匹配用通用名；`displayName` = 确认页展示的当地叫法。

运行时确认页：**只读**对应 `scales[effective]`，按档切换即换数据，不现场算热度。

## 三、确认页展示（消费预生成数据）

1. 取 `users.marketScaleEffective`（见下）。  
2. 加载该城 `ingredients-by-scale.json` 的 `small|medium|large`。  
3. **时令**：主列表，按类渲染，默认全选；无时令的类不出现。  
4. **四季**：折叠「四季常见」，默认计入；无条目的类不出现。  
5. 手补、语音/拍照后置逻辑不变。  
6. **本期不做** implies 可用集扩展；推荐仍按用户勾选名（+ 既有别名展开匹配，若已接）。

## 四、规模选择 UI 与账号字段（完整条款）

> **唯一详设**：本节为选择方式、与进场确认时序、定位再弹、账号字段的完整规范。  
> `doc/需求概述.md` 模块 1 / 页面结构仅摘要，**实现以本节为准**，勿只按概述推断。

### 4.1 决策摘要

| 项 | 结论 |
|----|------|
| 选项 | 小 / 中 / 大，均带说明文案；下方另有 **「默认中菜场」** |
| 「默认中菜场」 | **名单按中**（读 `scales.medium`），落库 `choice=default_medium`，与用户点「中菜场」的 `medium` **可区分** |
| 默认（从未选） | **中**（`effective=medium`） |
| 首次出现 | 进确认页**之前**弹层（见 4.2）；**仅当能拿到定位时**弹；拿不到则不弹、默认中 |
| 记住 | 写 **账号**（`users`）；换机仍在 |
| 再弹 | **须拿到定位**，且距上次规模弹窗/选档 **≥ 30 分钟**，且相对锚点位移 **≥ 约 1 km**；否则不弹，沿用最近一次档位（从未选过则默认中） |
| 同片区换中↔小 | **不**靠定位；确认页提供改规模入口；**切换成功后时令 + 四季均须按新档刷新** |
| 页内主动切换 | **不受** 30 分钟限制 |

### 4.2 与进场确认的时序（禁止叠弹）

进入「今天菜场有什么」时约定：

```
首页点击
  → 若需进场确认：只弹进场确认
  → 关闭后（确认/跳过）或无需进场确认
  → 若需选菜场规模：再弹规模（小/中/大/默认中菜场）
  → 再进入确认页（食材+场景）
```

规则：

- **禁止**进场确认与规模选择叠在同一屏。  
- 规模已记住且未触发「走远了」→ 进场确认后（或无需确认时）**直接进确认页**。  
- **拿不到定位（拒权 / 失败 / 超时）→ 不弹规模窗**，沿用账号最近一次 `marketScale`；若从未选过则按默认 **中** 进确认页（可用页内「切换」改）。  
- **距上次选档 / 规模弹层处理未满 30 分钟 → 不弹**，沿用最近一次档位（半小时内跨很大菜场的概率低）。  
- **同一小程序会话内规模弹层最多一次**（避免进场确认→食材之间 GPS 抖一下再弹）。

### 4.3 选项文案

- **小菜场** — 小门面、路边摊位  
- **中菜场** — 小超市、连着几个门面  
- **大菜场** — 集贸市场、大超市、很多摊位  
- **默认中菜场** — 按中菜场档位展示（可之后再改）

### 4.4 账号数据

```ts
type MarketScaleChoice = "small" | "medium" | "large" | "default_medium"
// small/medium/large = 用户点了对应档；default_medium = 点了「默认中菜场」（名单同 medium，分析可区分）

type MarketScaleHistoryItem = {
  choice: MarketScaleChoice
  effective: "small" | "medium" | "large"  // default_medium → medium
  source: "sheet" | "page_switch" | "system_default"  // 弹层 / 确认页切换 / 无定位未选过时的系统默认
  lat?: number
  lng?: number
  at: string  // ISO 时间
}

// users（示意）— 最新快照 + 历史
marketScaleChoice?: MarketScaleChoice           // 最近一次选择（可区分默认中）
marketScaleEffective?: "small" | "medium" | "large"  // 读分档名单用；由 choice 派生
marketScaleAnchor?: { lat: number, lng: number }     // 最近一次有定位时的锚点
marketScaleChosenAt?: string                    // 最近一次选档时间；30 分钟冷淡期
marketScaleHistory?: MarketScaleHistoryItem[]   // 历史，按 at 追加；建议最多保留最近 30 条（超出丢最旧）
```

派生：`effective = choice === "default_medium" ? "medium" : choice`。  

系统在「无定位且从未选过」静默用中时：写入 `choice=default_medium`、`source=system_default`，并追加一条 history（**建议仍入 history**，便于统计「有多少人从未点过」）。

确认页改档：更新上述快照字段 + **追加一条** `marketScaleHistory`（不要只覆盖导致丢历史）；有定位则更新锚点。**切换成功后必须同时刷新**：

- **时令主列表**（`seasonal`）：按新档 `effective` 重载预生成名单、重渲染；  
- **四季常见**（`yearRound`）：按新档重载，折叠区与勾选一并更新。  

已勾选项：与新列表交集的尽量保留勾选；落出新列表的去掉；新进列表的按时令默认全选 / 四季默认计入规则处理。

### 4.5 定位再问（「走远了」）

须**同时**满足才弹规模窗：

1. 成功拿到当前定位；  
2. 与 `marketScaleAnchor` 直线距离 **≥ 约 1 km**；  
3. 距 `marketScaleChosenAt`（上次选档或弹层关闭）已满 **30 分钟**。

否则 **不弹**，保持最近一次档位：

- **拿不到定位** → 不弹；  
- **半小时内** → 不弹（即便位移 ≥1 km，也认为同一次买菜行程）；  
- 无历史档位 → 默认中。  

**不用 500 m**（易误弹）。  
用户仍可在确认页主动「切换」改档（成功则更新 choice/effective/时间/锚点并 **append history**；无定位则 lat/lng 可空）。  
页内主动切换**不受** 30 分钟限制。

UI 展示当前档：`medium` 显示「中菜场」；`default_medium` 显示「默认中菜场」（或「中菜场（默认）」），避免和真选中混淆。

### 4.6 确认页改档入口

入口文案与布局见 **§4.7**。点开后为与首次弹层**同款**半屏；当前档高亮。  

**切换成功后**：按 `effective` 立即重载并刷新 **时令 + 四季**；写回快照 + 追加历史。选「默认中菜场」时 `choice=default_medium`、`effective=medium`，**不要**写成 `choice=medium`。点新档即提交并关层，**无**二次「确定」。

### 4.7 UI 详设（已定：贴底半屏方案 A）

视觉语言对齐首页进场确认（`sheet-confirm` 一类贴底半屏 + `mask`），**不**新开居中窄 dialog、**不**做四档平铺。

#### 信息架构（半屏内）

```
[遮罩]
┌─────────────────────────────┐
│ 标题                         │
│ 副文（一行）                  │
│                              │
│ ┌ 小菜场 ………………… 说明 ┐     │  ← 整卡可点
│ ├ 中菜场 ………………… 说明 ┤     │
│ └ 大菜场 ………………… 说明 ┘     │
│                              │
│      [ 默认中菜场 ]           │  ← outline / 弱按钮，单独一行
└─────────────────────────────┘
```

#### 文案

| 场景 | 标题 | 副文 |
|------|------|------|
| 首次 / 无历史后首次弹 | 你常去的菜场大概多大？ | 用来决定今天展示多少常见菜，可随时改 |
| 定位再弹（走远了） | 换地方了？再确认一下菜场规模 | 同上副文（可省略副文若嫌重复） |

三卡主标题 + 说明（与 §4.3 一致，说明跟在标题下、字号更小、次要色）：

- **小菜场** — 小门面、路边摊位  
- **中菜场** — 小超市、连着几个门面  
- **大菜场** — 集贸市场、大超市、很多摊位  

底栏弱按钮文案固定：**默认中菜场**（不要写成「跳过」或「随便」）。

#### 交互

| 操作 | 行为 |
|------|------|
| 点某一档卡 | 立刻落库对应 `choice`（`small`/`medium`/`large`）、`source=sheet` 或页内则为 `page_switch`；更新 effective / 时间 / 有定位则锚点；append history；关层 |
| 点「默认中菜场」 | `choice=default_medium`、`effective=medium`；其余同上 |
| 点遮罩 | **不关闭**（首次与再弹均须明确选一档或默认中，避免无 history 静默进页） |
| 右滑返回 / 物理返回 | 同遮罩：**拦截**，不关层（若平台无法拦截，则视为未选、仍停在首页不进确认页） |
| 页内半屏点当前已选档 | 可关层无写库，或视为无操作；**不要**重复 append 一条相同 history |

首次弹层挂在**首页**流程（进场确认关闭之后、`navigateTo` 确认页之前），与进场确认**禁止同屏**。  
页内改档半屏挂在**确认页**。

#### 确认页入口（非弹层态）

- 位置：时令主列表**上方**一行轻链（勿做成大按钮抢主 CTA）。  
- 文案：  
  - `choice === medium` → `中菜场 · 切换`  
  - `choice === small` → `小菜场 · 切换`  
  - `choice === large` → `大菜场 · 切换`  
  - `choice === default_medium` → `默认中菜场 · 切换`（勿显示成「中菜场 · 切换」）  
- 点开 → 同款半屏；三卡中对应 **effective** 档高亮（`default_medium` 时高亮中档卡，底栏「默认中菜场」可另加选中态以区分真选中）。  
- 切换成功后入口文案与时令/四季列表同步更新。

#### 视觉与无障碍（约束）

- 复用现有 `--color-*` / `--radius-sheet` / 半屏圆角；三卡用描边或浅底区分，选中态与进场确认 chip `on` 同系即可。  
- 大字版：标题/卡文跟随 `typeScale`；卡高度保证手指可点（建议整卡 ≥ 约 96rpx）。  
- **不做**：档位插画、滑动条、把规模放进「我的偏好」主路径、与进场确认合并成一个弹层。

#### 埋点（建议）

- `market_scale_sheet_show`：`{ reason: "first" | "relocate" | "page_switch" }`  
- `market_scale_sheet_select`：`{ choice, source }`  
- 遮罩误点可不打或打 `market_scale_sheet_mask_tap`（可选）

## 五、展示集 vs implies（本期范围）

| 集合 | 本期 |
|------|------|
| 展示集（时令/四季/手补） | **做**（来自分档预生成文件） |
| implies 可用集（猪肉→五花等） | **不做**；忌口 / 大小类后续再优化 |

## 六、前置数据债（脚本前必须）

- 城货架清洗到与 `ingredients-all` 同级，去掉「猪后」「腿肉」等脏名。  
- 城内名 → by-category + 别名映射可测；未映射可观测。  
- 下厨房 cleaned 持续补全；未覆盖食材热度=1。

## 非范围

- 用规模改城市或菜系  
- 确认页铺开猪肉等小类芯片  
- 与进场确认合并弹层  
- 运行时现算全国热度与 1/3 截断  
- 规模选择插画 / 四档平铺 / 居中窄 dialog / 「我的偏好」内改规模主路径

## 成功标准

- 能按脚本产出各城 `ingredients-by-scale.json`（或等价）；小 ⊂ 中 ⊂ 大（按通用名集合）。  
- 确认页按档切换时令+四季；无时令类不展示。  
- 城当地名展示正确，且不因别名漏映射而从本应进入的小/中档消失。  
- 无 implies 也能完成展示与勾选主路径。  
- 规模半屏：三卡 +「默认中菜场」；遮罩不关；确认页入口文案能区分 `medium` 与 `default_medium`；页内切换即时刷新名单。
