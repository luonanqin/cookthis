## 1. 范围

- `meal_logs` 写入：手动、语音、进场确认；拍照后置且入口不展示  
- 进场确认弹层：候选组装、去重、确认落库  
- **硬规则**：采纳推荐 **不** 写 `meal_logs`

---

## 2. 数据模型 `meal_logs`

| 字段 | 说明 |
|------|------|
| `uid` | — |
| `logId` | — |
| `date` | 业务日 `YYYY-MM-DD`（用户本地时区） |
| `meal` | `lunch` \| `dinner` \| `other` \| `unknown` |
| `dishNames` | string[] |
| `ingredientNames` | string[] 可选，供推荐新鲜度降权（主料重叠） |
| `source` | `manual` \| `photo` \| `voice` \| `confirm` |
| `recommendationId` | 可选，关联推荐会话 |
| `requestId` | 可选 |
| `createdAt` | 服务器时间，**用于「近期已记录」窗口** |

### 2.1 完整示例（1 用户 : N 记录；可选关联 1 次推荐）

关系：同一 `uid` 多条 `meal_logs`；一条记录可含多道菜名；可选挂 `recommendationId` / `requestId`。

```jsonc
[
  {
    "uid": "u_demo001",                        // 用户
    "logId": "log_001",                        // 记录 id
    "date": "2026-10-02",                      // 业务日
    "meal": "dinner",                          // 餐次：晚饭
    "dishNames": ["红烧茄子", "紫菜蛋花汤"],     // 吃过的菜名（可多道）
    "ingredientNames": ["茄子", "鸡蛋", "紫菜"], // 相关主食材（新鲜度降权用）
    "source": "manual",                        // 来源：手动记录
    "recommendationId": null,                  // 未关联推荐文档
    "requestId": null,                         // 未关联推荐请求
    "createdAt": "2026-10-02T19:30:00.000Z"    // 写入时间（去重窗口用）
  },
  {
    "uid": "u_demo001",
    "logId": "log_002",
    "date": "2026-10-03",
    "meal": "dinner",
    "dishNames": ["土豆烧肉", "蒜蓉青菜", "蛋花汤"],
    "ingredientNames": ["猪肉", "土豆", "青菜", "鸡蛋"],
    "source": "confirm",                       // 来源：进场确认
    "recommendationId": "rec_doc_001",         // 关联推荐会话文档
    "requestId": "req_20261003_001",           // 关联推荐请求 id
    "createdAt": "2026-10-04T09:00:00.000Z"
  }
]
```

读法：进场确认一次可写入多道菜；`requestId` 与推荐会话对齐，便于「采纳之后已记录」去重。

## 3. 进场确认

### 3.1 触发

首页点击「今天菜场有什么」→ `meals.confirmCandidates`。

### 3.2 候选组装

1. 在该 uid 近期 `recommendations`（如近 14 天）中找 **锚点会话**：  
   - 有 `acceptedAt` 的会话（点过「可以」）  
   - 有 `engagedAt` 的会话（推荐页累计可见 ≥ **30 秒**，见推荐详细设计）  
   - 两者都有时，取 **锚点时刻更晚** 的那一条；锚点时刻 = `max(acceptedAt, engagedAt)`（该条上有哪个用哪个）  
2. **没有锚点**（从未采纳且从未有效停留）→ 候选为空，**不弹层**，直接进输入页  
3. 菜名来源：该锚点会话对应 plan 的菜  
   - 若锚点靠采纳：用 `acceptedPlanIndex`  
   - 若锚点靠停留：用 `engagedPlanIndex`  
   - 若同条既采纳又停留且时刻相同：优先 `acceptedPlanIndex`  
4. **近期已记录** = `meal_logs` 中 `createdAt >=` 锚点时刻 的所有 `dishNames`  
5. 候选 = 锚点 plan 菜名 − 近期已记录（菜名去空白归一化）  
6. 若候选为空 → 不弹层，直接进输入页  

### 3.3 弹层交互

- **默认全部不选**，只展示候选菜名；由用户勾选吃过的  
- 可提供「全选」快捷，但不预勾  
- 提交 → `meals.confirmWrite`：仅对**勾选**项写 `meal_logs`（`source=confirm`，`date=今天`）；若一个都没勾，等同跳过（可不调写入或写空）  
- 允许跳过：不写日志，直接进输入页（打 `confirm_sheet_skip`）  

### 3.4 「近期已记录」口径

窗口起点 = 最近一次 **采纳或有效停留** 的锚点时刻，不是「最近 7 天」日历窗（7 天窗留给推荐：同菜名硬排除 + 主料重叠降权）。

---

## 4. 手动记录

`meals.addManual`：

- 入参：`dishNames[]`，可选 `date`/`meal`，可选从历史推荐多选  
- `source=manual`  
- 埋点 `meal_log_manual`

### 4.1 语音记录

`meals.addVoice`（或先转写再走与手动相同的确认提交）：

- 录音 → 转写 → 抽出菜名，用户确认后写入，`source=voice`  
- 埋点 `meal_log_voice_start` / `meal_log_voice_result`

拍照记录：**不展示**入口；预留 `source=photo` / `addPhoto` / `meal_log_photo_*` 命名，实装后再露出。

---

## 5. 供推荐消费

`recommend` 读取近 **7 天**（可配置）`meal_logs`：

- **硬排除**：相同 `dishNames`（或可关联到同 `recipeId`）  
- **降权，不删除**：候选菜 `mainIngredients` 与近期 `ingredientNames` 有重叠（如都有土豆）→ 新鲜度分降低；重叠越多、吃得越近，降权越大  

与进场确认窗口（锚点时刻之后）是两套逻辑，勿混用。

| 方法 | 说明 |
|------|------|
| `confirmCandidates` | 返回候选列表 |
| `confirmWrite` | 批量写 confirm 日志 |
| `addManual` | 手动记 |

## 8. 边界

采纳 / 有效停留只改 `recommendations` → 推荐与反馈。候选菜名来自锚点 plan，依赖 `plans` / `acceptedPlanIndex` / `engagedPlanIndex`。
