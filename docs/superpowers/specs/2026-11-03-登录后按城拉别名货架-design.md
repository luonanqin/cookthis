# 登录后按城拉别名 / 货架（安全 #5）

日期：2026-11-03  
状态：已拍板，待写实现计划

## 目标

小程序包内不再携带可解包的 `aliases.js`、`city-shelves.js`。登录后按需从云函数拉取，本地缓存；换城只重拉货架。

## 方案

新云函数 **`catalog`**（方案 A）：

| action | 行为 |
|--------|------|
| `getAliases` | 返回全国别名表；需登录；可带弱限流 |
| `getCityShelf` | **忽略客户端 city**，只信 `users.city`；返回该城货架名序；无城则失败或空序 |

服务端数据打进 `catalog` 函数目录（由现有 catalog 产物同步），与 `ingredients` 按城文件同类。

## 客户端缓存

| 数据 | Storage key（示例） | 失效 |
|------|---------------------|------|
| 别名 | `cookthis_aliases_v1` | 升 key 版本作废；换城不删 |
| 货架 | `cookthis_shelf_<cityKey>` | 换城删旧城 key；升版本作废 |

命中缓存不再打云函数。

## 拉取时机

1. `ensureLogin` 成功：无别名缓存则预拉别名；有 `users.city` 且无该城货架缓存则预拉货架（失败静默）。
2. 进购物清单：缺别名或缺当前城货架则**等待补拉**再渲染。
3. 「我的」换城保存成功：删除旧城货架缓存，拉新城货架；别名不动。
4. 尚无城市：可不拉货架；别名仍可预拉。

## 失败策略

| 场景 | 行为 |
|------|------|
| 登录后预拉失败 | 静默，不挡首页 |
| 购物清单补拉**货架**失败 | 可提示加载失败或货架序降级为空（按现有无序逻辑） |
| 购物清单补拉**别名**失败 | **不 Toast**；`track` 打点即可；用户无感知；异名展示降级 |
| 限流 | 货架等用户可感知路径可用「请求太频繁，请稍后再试」；别名仍不打扰用户 |

## 包体

- 移除（或停止打包引用）`miniprogram/data/aliases.js`、`city-shelves.js` 及仅服务于进包的分城 json 引用。
- 仓库内源数据与云函数侧数据源保留，供构建同步。

## 安全口径（目标 A）

- 货架不可扫城：与 #1 相同，只信账号城市。
- 解包不再直接得到全量别名 + 多城货架。
- 接口需登录 + 弱限流，避免脚本高频拉别名。

## 非目标

- 不做 CDN/静态 HTTPS 下发。
- 不做按城裁剪别名。
- 首版不做内容 hash 自动刷新（靠 storage key 版本）。

## 验收

1. 正式包 / 源码包中无 `aliases.js`、`city-shelves.js` 业务引用。
2. 登录有城后，storage 出现别名与对应城货架；购物清单别名与货架序正常。
3. 换城保存后旧城货架 key 清除，新城货架可用。
4. 别名接口失败时购物清单无 Toast，有打点。
