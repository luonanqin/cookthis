## 2. 架构一览

```text
首页 index
  ├─ link「建议反馈」± 无数字红点  ← feedback.hasUnread
  ├─ ?openFeedback=1 → navigateTo list（订阅消息落地）
  └─ navigate → pages/feedback/list
                    ├─ 顶部常驻：类型 chip + 矮 textarea + 提交
                    ├─ 缓存 / listMine
                    ├─ create 成功 → 感谢弹窗 → 可选 requestSubscribeMessage
                    └─ 点卡片/展开 → markRead（不重排）

运营：feedback.reply(adminKey)
      → 写回复 + bump epoch
      → 若 subscribeReady：subscribeMessage.send
         page = pages/index/index?openFeedback=1
```

云函数：`cloudfunctions/feedback/`。

## 3. 数据模型

### 3.1 集合 `feedbacks`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | |
| `uid` | string | |
| `category` | enum | `recipe` \| `ingredient` \| `feature` \| `other` |
| `content` | string | ≤100 字 |
| `createdAt` | Date | |
| `replyText` / `repliedAt` / `repliedBy` | | 回复不截断 |
| `userReadAt` | Date \| null | |
| `unreadForUser` | boolean | 冗余；有回复且未读为 true |
| `sortKey` | number | 未读：`UNREAD_SORT_BASE + max(created,replied)ms`；否则时间 ms |
| `subscribeReady` | boolean | 该条提交后用户是否授权了订阅（仅当次成功才 true） |

索引：`uid ASC + sortKey DESC`；频控辅助：`uid + createdAt DESC`。

### 3.2 `users`

| 字段 | 说明 |
|------|------|
| `feedbackListEpoch` | 运营回复时 `+1`；客户端缓存对 epoch |

## 4. 云函数 API

`callCloud('feedback', { action, ... })`。

### 4.1 `create`

入参：`{ category, content, subscribeReady?: boolean }`  
校验：四类；正文非空 ≤100；**60s 频控**。  
写：`subscribeReady: !!event.subscribeReady`，`unreadForUser: false`，算 `sortKey`。  
出参：`{ ok, item }`。

### 4.2 `listMine` / `markRead` / `hasUnread`

同前稿：`listMine` 返回 `items/nextCursor/feedbackListEpoch/hasUnread`；`hasUnread` 亦返回 `feedbackListEpoch`；`markRead` 清未读并降 `sortKey`，客户端不重排。

### 4.3 `reply`

鉴权：`adminKey === process.env.FEEDBACK_ADMIN_KEY`。  
写回复 + `unreadForUser=true` + 高 `sortKey` + bump `feedbackListEpoch`。  
**然后**若该条 `subscribeReady === true`：查 `user_identities` 得 openid，调

```js
cloud.openapi.subscribeMessage.send({
  touser: openid,
  templateId: process.env.FEEDBACK_SUBSCRIBE_TMPL_ID,
  page: 'pages/index/index?openFeedback=1',
  data: { /* 按模板字段填：如反馈类型、回复摘要截断 */ }
})
```

发送失败只打日志，**不回滚**回复写入。模板 ID、字段名以微信后台申请结果为准，实现时用环境变量，勿写死进仓库。

## 5. 客户端

### 5.1 仅一页：`pages/feedback/list`

**不做** `compose` 页。

列表顶部常驻写作区：

- 一行类型 chip（四选一，默认 `feature` 或上次选择）
- `textarea`：**矮**（约 2 行高，`auto-height` 上限约 120rpx），`maxlength=100`，旁或下显示 `n/100`
- 「提交」按钮；成功 → `showModal('感谢您的反馈')` → unshift 卡片；关闭弹窗后再 `wx.requestSubscribeMessage`（拒绝不影响）

下方为卡片列表（折叠 150rpx、渐隐、配色、分隔、分页、缓存）——逻辑同前。

### 5.2 订阅授权时机

感谢弹窗 `success` 回调里请求订阅（需用户手势链路：提交按钮 → modal 确认也算延续；若平台要求必须紧挨 tap，则在提交成功的同一同步栈先 `requestSubscribeMessage` 再 modal，或 modal 的「确定」里请求）。**推荐：提交成功后先 modal，点「确定」时 `requestSubscribeMessage`，再把结果通过一次轻量 `feedback` 更新或创建时已带 flag。**

更稳：

1. 用户点提交 → `create`（先 `subscribeReady: false`）  
2. 感谢 modal 点确定 → `requestSubscribeMessage`  
3. 若 accept → `callCloud('feedback', { action: 'markSubscribeReady', id })` 将该条置 true  

或 create 前先 requestSubscribe（手势最新）再 create 带 flag。**采用：提交按钮点击后先 `requestSubscribeMessage`，再带 `subscribeReady` 调 `create`，成功后再感谢弹窗**（拒绝也继续 create）。这样一条 API、无二次更新。

### 5.3 订阅消息落地

模板 `page`：`pages/index/index?openFeedback=1`

`index` `onLoad` / `onShow`：

```js
if (options.openFeedback === '1' || query.openFeedback === '1') {
  wx.navigateTo({ url: '/pages/feedback/list' })
}
```

（`onShow` 用一次性标志防重复跳转。）

### 5.4 列表缓存 / 首页红点 / 配色

同前：TTL 7 天 + epoch；首页 `hasUnread` 圆点；卡片配色 token。
