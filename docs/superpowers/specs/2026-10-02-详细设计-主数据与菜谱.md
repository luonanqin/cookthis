## 2. `ingredients`

| 字段 | 说明 |
|------|------|
| `id` | 稳定 id，如 `ing_tomato` |
| `name` | 展示名 |
| `category` | 见菜场输入详细设计分类枚举 |
| `cities` | `string[]`，适用城市；`[]` = 全国。见 §2.1 |
| `kind` | `main` 主料 \| `seasoning` 调味常备（盐、生抽、葱姜蒜等） |
| `availability` | 仅主料：`year_round` 四季常见 \| `seasonal` 时令。调味不填 |
| `onConfirmPage` | 是否进入确认页**主列表**。仅 `kind=main` 且 `availability=seasonal` 可为 true；截断后为 false 的走搜索/补菜 |
| `sort` | 数字越小越常见；主列表按类截断时用 |
| `aliases` | string[] 可选，匹配别名 |
| `avoidTags` | string[] 忌口大类，取值同画像词表（`pork` / `seafood` / …）；硬排除与成员降权都靠它，**不**靠菜名 |
| `source` | `builtin` \| `manual` \| `meituan`（预留） |
| `updatedAt` | — |

以 `data/ingredients-builtin.json` 导入；用户自定义菜可不入库或 `source=manual` + `uid`（用户食材表可后置）。

### 2.1 适用城市 `cities`（食材与菜谱共用）

**存储方向：食物对应城市。** 不建「城市文档里挂食物 id」的集合。用户侧仍是单个 `users.city`。

| JSON | 含义 |
|------|------|
| `"cities": []` | 全国可见 |
| `"cities": ["杭州"]` | 仅杭州 |
| `"cities": ["杭州", "宁波"]` | 多城共用 |

入库只认数组。导入若写成单个字符串 `"杭州"`，脚本收成 `["杭州"]`。不要同时保留旧字段 `city`。

可见规则（确认列表与推荐候选的城市范围相同）：

- `cities.length === 0` → 全国  
- 否则 `cities` **包含** 当前 `users.city`（列表入参城市）才可见  

无用户城市或该城几乎没有专属条 → 列表可 fallback 全国（`cities: []`），返回 `fallback: "national"`。

### 2.2 确认页分层（主料）

可见集合仍先按 `cities` 过滤，再分层：

| 层 | 条件 | 确认页 | 提交给推荐 |
|----|------|--------|------------|
| 调味 | `kind=seasoning` | 不出现 | **不计入**已选主料（菜谱本就允许缺调味） |
| 四季常见 | `kind=main` 且 `availability=year_round` | 主列表不展示；折叠「四季常见 · 已计入 N 样」，可取消 | 未取消则计入已选，清单标场内已有 |
| 时令主列表 | `kind=main` 且 `seasonal` 且 `onConfirmPage=true` | 分组展示，默认全选 | 勾选的计入 |
| 长尾 | 其余主料 | 不预展示，搜索/补菜 | 用户补上才计入 |

时令主列表上限：每类约 6～10 条、整页约 40～70；按 `sort` 截断，落选将 `onConfirmPage` 视为 false（数据里可预写好，导入脚本也可按规则生成）。美团日更写入可以多，**不能**全部提权进主列表。

MVP 不做按月时令表；`seasonal` 由内置数据标好即可。猪肉/海鲜/内脏等食材入库时必须打好 `avoidTags`，否则家庭忌口硬排除会漏网。

## 3. `recipes`

| 字段 | 说明 |
|------|------|
| `id` | `rcp_xxx` |
| `name` | 菜名 |
| `mainIngredients` | string[]（与 ingredients.name 或 id 对齐，可用 name） |
| `seasonings` | string[] |
| `meatVeg` | `meat` \| `veg` \| `soup` \| `staple` \| `other` |
| `tasteTags` | `light` \| `normal` \| `heavy` \| `spicy` 等 |
| `dishForms` | 菜式形态 tag[] |
| `stapleForms` | 主食形态 tag[] |
| `cities` | 同食材 §2.1；`[]` = 全国。地区面食（小笼、油泼面等）写多城，不另建面食表 |
| `minutes` | 预计耗时 |
| `servings` | 建议人数（下限或区间） |
| `stepsBrief` | 可选简要步骤 |
| `enabled` | bool，可下架 |
| `cuisineTags` | `string[]` 菜系英文 code；可含 `home_style`；可空 |

规模：先 **100～200** 道，结构正确优先于数量；目标可扩到 200～500。

主料与可选食材匹配：recipe 主料名称 ∈ 用户选中名称集合（别名表可选）。

### 3.2 非常规菜谱（入库就要有）

家常热炒之外，库里必须有可被引擎拼成方案的火锅 / 面条 / 水饺条目（数量不求多，标签要全）：

| 类型 | 标签 | `meatVeg` 约定 | 例 |
|------|------|----------------|----|
| 火锅 | `dishForms` 含 `hotpot` | 锅底=`soup`；荤涮=`meat`；素涮=`veg` | 番茄锅底、肥牛卷、白菜豆腐 |
| 面条 | `stapleForms` 含 `noodle` | 主食=`staple` | 番茄鸡蛋面、阳春面 |
| 水饺 | `stapleForms` 含 `dumpling` | 主食=`staple` | 猪肉白菜饺 |

主食载体（面条、饺皮、成品锅底料）允许**不在**用户已选食材里，推荐仍可出该方案，清单里标未持有。浇头、馅料、涮菜主料仍按已选匹配。

```jsonc
{
  "id": "rcp_tomato_egg_noodle",               // 菜谱 id
  "name": "番茄鸡蛋面",                         // 菜名
  "mainIngredients": ["面条", "番茄", "鸡蛋"],   // 面条可为未选主料，进清单
  "seasonings": ["盐", "油"],
  "meatVeg": "staple",                         // 主食
  "tasteTags": ["normal", "light"],
  "dishForms": ["soup"],                       // 汤面可同时带汤羹形态
  "stapleForms": ["noodle"],                    // 面食
  "cities": [],                                // 全国；地区面食写成 ["上海","杭州"]
  "minutes": 20,
  "servings": 2,
  "enabled": true
}
```

## 4. `holidays`

一年一条文档（或 JSON 里一个 year 对象）。按年整包替换；农历节日的公历日期每年不同。

| 字段 | 说明 |
|------|------|
| `year` | 公历年，如 2026；云库可用作文档 id |
| `items` | 该年节日列表 |

`items[]`：

| 字段 | 说明 |
|------|------|
| `id` | 稳定代号，**不含年份**（`mid_autumn` / `national_day` / `spring_festival`）。给 `scene.holidayId` 用 |
| `date` | 该年公历 `YYYY-MM-DD`（农历节导入时算好） |
| `nameZh` | 中文名 |
| `nameEn` | 英文名（界面可先只用中文） |

列表接口：读今年（跨年再读明年），筛 `date` 落在「今天起 N 天」（N=30）内。展示 `nameZh` + `date`。

```jsonc
{
  "year": 2026,                                // 公历年
  "items": [                                   // 该年节日列表
    {
      "id": "mid_autumn",                      // 稳定代号，场景 holidayId
      "date": "2026-09-25",                    // 该年公历
      "nameZh": "中秋节",                      // 中文名
      "nameEn": "Mid-Autumn Festival"          // 英文名
    },
    {
      "id": "national_day",
      "date": "2026-10-01",
      "nameZh": "国庆节",
      "nameEn": "National Day"
    }
  ]
}
```

不按城市拆节日表。自定义节日名后置。

## 5. 导入与发布

1. 仓库 `data/*.json` 为源文件  
2. 脚本或云函数管理员接口：清空/upsert 导入（个人主体可用本地开发者工具上传）  
3. 版本字段可选 `dataVersion` 写在单独 `meta` 集合，便于客户端缓存  

禁止小程序端写 recipes/ingredients（除明确允许的 custom）。
