# 用户建议反馈

状态：已定稿（待实现）  
日期：2026-10-27  
需求摘要：[`2026-10-24-用户建议反馈-requirements.md`](./2026-10-24-用户建议反馈-requirements.md)  
权威产品：`doc/需求概述.md` 模块 5「产品建议反馈」

## 目标

- 用户可提交建议（增菜谱 / 增食材 / 功能建议 / 其他），支撑内容与产品迭代。
- 运营可导出、可回复；用户能在站内看到回复，并用轻量红点拉回访（增强粘性）。
- 与方案「不行 / 换一批」分离：后者服务推荐权重，本项服务产品反馈。

## 已定决策

| 项 | 决定 |
|----|------|
| 入口 | 仅「我的 → 建议反馈」；有未读回复时入口旁**小红点、不显示数字** |
| 与画像缺口 | **分开**：画像缺口用标题标红等（见跳过引导设计）；反馈红点独立、更弱，因优先级低于补全画像 |
| 表单 | 类型四选一 + 正文必填；不收集联系方式（本期） |
| 列表字段 | **类型、内容摘要、时间**；**不显示**「待回复 / 已回复 / 未读」等状态文案 |
| 列表排序 | **有未读回复的在上**；组内与其余均按 **创建倒序** |
| 未读样式 | 该行**右侧小红点**；**不加粗** |
| 已读时机 | 用户**点击该行**进入详情（或点行）后，该条未读清除、行红点消失 |
| 「我的」红点 | 仍存在 ≥1 条未读回复时显示；全部已读则灭 |
| 通知 | 站内列表 + 红点为主；提交时可请求**订阅消息**，有回复时尝试推送（未授权则仅站内） |
| 运营回复 | 云开发控制台 / 脚本调云函数写回复；**无** Web 后台、无运营小程序页 |
| 数据 | 单集合 `feedbacks`（一条建议一行，回复字段挂同文档） |

## 用户流程

```text
我的（入口 ± 红点）
  → 建议反馈列表
       ├─ 写建议 → 选类型 + 正文 → 提交 → 回列表
       └─ 点某行 → 详情（正文 + 若有则显示运营回复）→ 该条已读
```

### 写建议

- 类型：`recipe` 菜谱 / `ingredient` 食材 / `feature` 功能建议 / `other` 其他（展示中文标签）。
- 正文：必填；建议长度上限实现时定（如 500 字），超限 toast。
- 提交成功：toast「已提交」；可选拉起订阅消息授权（拒绝不影响提交）。
- 频控（建议）：同 uid 短时防刷（如 1 分钟 1 条或每日上限），实现时定具体数；超限友好提示。

### 列表

- 每行：类型标签、内容摘要（单行省略）、时间（相对或 `MM-DD HH:mm`）。
- **不**渲染状态文案。
- 排序键：`hasUnreadReply` DESC，再 `createdAt` DESC。
- `hasUnreadReply === true` 时行右侧小红点。
- 点击整行 → 详情；同时将该条标为用户已读（清 `userReadAt` / 清未读标记）。

### 详情

- 展示：类型、完整正文、提交时间；若有 `replyText` 则展示「回复」区块与 `repliedAt`。
- 无回复时只显示用户内容，不假装有空状态文案「等待回复」（避免变相状态条）；需要时可极弱提示一句「收到后会在这里回复你」。

## 运营流程

1. 云库导出 / 控制台按 `createdAt`、`category` 筛选查看。
2. 回复：调用受控云函数（如 `feedback.reply`，校验管理员密钥或白名单）写入：
   - `replyText`、`repliedAt`、`repliedBy`
   - 清空或重置用户已读：`userReadAt = null`（表示对用户而言又是未读）
3. 若用户曾授权订阅消息：尝试发送「反馈有回复」模板，跳转路径带 `feedbackId`。
4. 不支持用户在站内再跟帖（多轮后置）；运营改回复以最后一次为准即可。

## 数据模型（建议）

集合 `feedbacks`：

```ts
{
  _id: string
  uid: string
  category: 'recipe' | 'ingredient' | 'feature' | 'other'
  content: string
  createdAt: Date
  // 运营回复（可空）
  replyText?: string
  repliedAt?: Date
  repliedBy?: string
  // 用户已读：有回复且 (userReadAt == null || userReadAt < repliedAt) ⇒ 未读
  userReadAt?: Date | null
  // 订阅
  subscribeReady?: boolean  // 提交时是否授权成功（可选）
}
```

未读判定：`replyText` 非空且（`!userReadAt` 或 `userReadAt < repliedAt`）。

「我的」入口红点：`count(uid 下未读) > 0` → 显示点，**不显示数字**。

## 云函数 / 页面（实现提示）

| 能力 | 建议 |
|------|------|
| 提交 | `feedback.create` |
| 我的列表 | `feedback.listMine`（服务端排好序：未读优先 + 时间倒序） |
| 详情 + 已读 | `feedback.get` / `feedback.markRead`（进详情时调） |
| 未读布尔 | `feedback.unreadCount` 或 list/profile 附带 `hasUnreadFeedback`（供「我的」红点；**只要 >0**） |
| 运营回复 | `feedback.reply`（管理员）+ 可选发订阅消息 |

小程序：`pages/feedback/list`、`pages/feedback/compose`（或 list 内 sheet）、`pages/feedback/detail`；「我的」增加入口与红点样式（与画像 `section-title-gap` 视觉区分：反馈用入口旁小圆点即可）。

## 与现有文档关系

- 概述模块 5：产品建议反馈；本设计落地交互与数据。
- 跳过引导 / 画像提醒：画像缺口标红逻辑不变；反馈红点独立字段/独立计算，勿并入 `computeProfileGaps`。
- 「不行」原因面板：仍属推荐 reject，不进 `feedbacks`。

## 非目标

- 公开社区、点赞、用户互评
- 用户上传菜谱直接入推荐池
- Web / 运营小程序后台
- 多轮工单对话
- 确认页 / 推荐页投放反馈入口
- 列表展示状态文案或未读数字角标

## 成功标准

- 用户能从「我的」提交四类建议并在列表看到类型、内容、时间。
- 运营写入回复后：列表该行右侧出现红点并排在未读区；「我的」入口出现无数字红点。
- 用户点开该行后行红点消失；全部未读处理完后入口红点消失。
- 可从云库导出反馈；订阅消息未授权时站内路径仍完整可用。

## 实现分期（可选）

1. 提交 + 列表 + 详情 + 已读 + 「我的」红点 + 控制台/脚本回复。  
2. 订阅消息模板与授权。  
3. 频控与敏感词（若需要）。
