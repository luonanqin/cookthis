# 用户建议反馈

状态：已定稿（待实现）  
日期：2026-10-27  
需求摘要：[`2026-10-24-用户建议反馈-requirements.md`](./2026-10-24-用户建议反馈-requirements.md)  
权威产品：`doc/需求概述.md` 模块 5「产品建议反馈」

## 目标

- 用户可提交建议（增菜谱 / 增食材 / 功能建议 / 其他），支撑内容与产品迭代。
- 运营可导出、可回复；用户能在站内看到回复，并用轻量红点拉回访（增强粘性）。
- 与方案「不行 / 换一批」分离：后者服务推荐权重，本项服务产品反馈。

## 已定决策

| 项 | 决定 |
|----|------|
| 入口 | **首页** `link-row` 第三项「建议反馈」，与「已选菜品」「我的偏好」并列；**不**放在偏好编辑页内 |
| 首页红点 | 有未读回复时「建议反馈」旁**小红点、不显示数字**；与「我的偏好」上的**缺口数字角标**完全分开 |
| 表单 | 类型四选一 + 正文必填，**最多 100 字**；不收集联系方式（本期） |
| 运营回复字数 | **不设上限**（脚本 / 控制台写入） |
| 列表 | 类型、内容、时间；无状态文案 |
| 初始排序 | **拉取时**：未读优先，组内及其余按时间倒序 |
| 已读后排序 | 未读→已读后**只消该条红点，不立刻重排列表**（避免卡片乱跳） |
| 分页 | **滚动加载**；首屏 **5** 条，每次再加载 **5** 条 |
| 端上缓存 | 列表缓存 **7 天**（TTL）；未过期且未强制失效则用缓存 |
| 用户新提交 | **插到列表最前面**（并写入/刷新缓存）；不必整表重排 |
| 运营回复后 | **清除该用户列表缓存**，下次进列表（或收到订阅进页）**重新拉取** |
| 行高 / 展开 | **固定折叠高度**；超出显示「展开」/「收起」；不加粗 |
| 折叠截断视觉 | 可见区最后一行**半隐藏渐隐**（上半正常、下半变浅）；展开后取消 |
| 条目分隔 | 卡片间距（+ 可选分割线） |
| 配色 | 用户反馈与运营回复不同色 |
| 未读样式 | 卡片**右侧小红点** |
| 已读时机 | 点该条（卡片或「展开」）→ `markRead`，**该条红点马上消失**；无其它未读则首页红点灭；**不重排** |
| 入口红点条件 | ≥1 条未读则显示点、无数字 |
| 通知 | 站内为主；可选订阅消息 |
| 运营回复 | 控制台 / 脚本；无 Web / 运营小程序页 |
| 数据 | 单集合 `feedbacks` |
| 详情页 | **不做**独立详情；列表卡片内展开即可 |

## 用户流程

```text
首页 link-row：已选菜品 | 我的偏好(缺口数字) | 建议反馈(±无数字红点)
  → 建议反馈列表（卡片）
       ├─ 写建议 → 选类型 + 正文（≤100 字）→ 提交 → 回列表
       └─ 点卡片 / 展开 → 该条已读；可「展开」看全文 / 回复
```

**首页入口示意**（与现网结构对齐）：

```
[今天菜场有什么]
[记一下吃了什么]
[大字版]
已选菜品    我的偏好 [3]    建议反馈 [·]
```

- 「我的偏好」仍进 `pages/mine`（画像编辑）；缺口用**数字**角标（现有 `profileGapCount`）。  
- 「建议反馈」进 `pages/feedback/list`；未读只用**小圆点**，不用数字。

### 写建议

- 类型：`recipe` 菜谱 / `ingredient` 食材 / `feature` 功能建议 / `other` 其他（展示中文标签）。
- 正文：必填；**最多 100 字**（端上计数 + 云函数校验）；超限不可提交 / toast。
- 提交成功：**弹窗**文案「感谢您的反馈」（确认关闭即可；不用「已提交」类冷淡 toast）；可选在关闭后再拉起订阅消息授权（拒绝不影响已提交结果）。
- 频控（建议）：同 uid 短时防刷（如 1 分钟 1 条或每日上限），实现时定具体数；超限友好提示。

### 列表（卡片）

- 每条卡片结构（自上而下）：
  1. 顶栏：类型标签 + 时间；右侧未读小红点（若有）
  2. **用户反馈区**（色 A）：正文；折叠在固定高度内，超出显示「展开」/「收起」
  3. **运营回复区**（色 B，仅有 `replyText` 时）：回复正文；同样可固定高度 + 展开（因回复不限字）
- **折叠渐隐**：内容被裁切时，在可见区底部叠一层由正文色→透明（或→卡片底色）的纵向渐变，使**最后一行呈现上半清晰、下半变浅**的半隐藏效果；勿用生硬 `…` 代替该渐隐（可与「展开」并存）。展开态去掉遮罩。实现可用伪遮罩 `linear-gradient` 盖在裁切容器底部。
- **不**渲染「待回复 / 已回复」等状态文案。
- **卡片之间**：明确分隔（推荐：白底卡片 + 列表灰底间距，或加分割线），避免连成一片。
- **拉取时排序**：`hasUnreadReply` DESC，再 `createdAt` DESC。
- **分页**：`listMine` 支持 cursor；首次 `limit=5`，上拉再要 5；服务端排序稳定，cursor 基于排序键。
- **缓存**：端上缓存已加载列表，**TTL = 7 天**（本地存 `cachedAt` + 数据）；进列表时未过期且无强制失效则直接用缓存；满 7 天或运营回复导致失效后再请求。
- **用户新提交成功**：新卡片 **unshift 到列表顶部**（更新缓存）；感谢弹窗关闭后仍停在列表即可。
- **点已读**：立刻 `markRead`，**该条右侧红点消失**（本地先消）；**保持当前列表顺序，不因已读而重排**；其余未读红点不变。
- **配色**：用户反馈与回复对比清晰（如反馈深字浅底、回复另一弱色底或左侧色条），具体 token 跟现有小程序色板，避免高饱和。

## 运营流程

1. 云库导出 / 控制台按 `createdAt`、`category` 筛选查看。
2. 回复：调用受控云函数（如 `feedback.reply`，校验管理员密钥或白名单）写入：
   - `replyText`、`repliedAt`、`repliedBy`（`replyText` **不截断**）
   - 清空或重置用户已读：`userReadAt = null`（表示对用户而言又是未读）
   - **使该 uid 的列表缓存失效**（服务端可 bump `feedbackListVersion` / 删缓存键；或约定客户端在 `onShow` 发现有新回复红点则强制刷新）。用户下次进列表须**重新拉**，以看到回复并按「未读优先」重排。
3. 若用户曾授权订阅消息：尝试发送「反馈有回复」模板，跳转路径带 `feedbackId`。
4. 不支持用户在站内再跟帖（多轮后置）；运营改回复以最后一次为准即可。

## 数据模型（建议）

集合 `feedbacks`：

```ts
{
  _id: string
  uid: string
  category: 'recipe' | 'ingredient' | 'feature' | 'other'
  content: string              // 用户正文，≤100 字
  createdAt: Date
  // 运营回复（可空；字数不限）
  replyText?: string
  repliedAt?: Date
  repliedBy?: string
  // 用户已读：有回复且 (userReadAt == null || userReadAt < repliedAt) ⇒ 未读
  userReadAt?: Date | null
  // 订阅
  subscribeReady?: boolean  // 提交时是否授权成功（可选）
}
```

未读判定：`replyText` 非空且（`!userReadAt` 或 `userReadAt < repliedAt`）。

首页「建议反馈」红点：`count(uid 下未读) > 0` → 显示点，**不显示数字**。

## 云函数 / 页面（实现提示）

| 能力 | 建议 |
|------|------|
| 提交 | `feedback.create`（校验 ≤100 字） |
| 我的列表 | `feedback.listMine`（未读优先 + 时间倒序；`limit=5` + cursor 滚动加载） |
| 已读 | `feedback.markRead`（点卡片/展开；客户端不重排） |
| 未读布尔 | `hasUnreadFeedback`（供**首页**「建议反馈」红点；**只要 >0**；可在 `auth` 回包或进首页时轻量查询） |
| 运营回复 | `feedback.reply`（管理员；`replyText` 不截断）+ 可选发订阅消息 |

小程序：首页 `index` 增加「建议反馈」链接；`pages/feedback/list`、`pages/feedback/compose`（或 list 内 sheet）；**不做** `detail` 页。**不**改 `mine` 偏好表单结构来塞反馈入口。

## 非目标

- 公开社区、点赞、用户互评
- 用户上传菜谱直接入推荐池
- Web / 运营小程序后台
- 多轮工单对话
- 确认页 / 推荐页投放反馈入口
- 列表展示状态文案或未读数字角标
- 独立详情页

## 成功标准

- 用户能从**首页「建议反馈」**进入并提交四类建议（正文 ≤100 字），列表见类型、内容、时间。
- 列表卡片固定折叠高，超出可展开；用户文与回复配色可辨；卡片之间分隔清楚。
- 运营写入回复后：该卡右侧红点且排在未读区；**首页**「建议反馈」出现无数字红点（「我的偏好」数字角标不变）。
- 用户点卡片或展开后该条红点消失且列表不跳动重排；全部未读处理完后首页入口红点消失。
- 首屏 5 条、上拉再 5 条；用户新提交置顶；运营回复后缓存失效并重新拉取可见回复。
- 可从云库导出反馈；订阅消息未授权时站内路径仍完整可用。

## 实现分期（可选）

1. 首页入口 + 提交（≤100 字）+ 列表卡片（展开/配色/分隔）+ 已读 + 首页红点 + 控制台/脚本回复。  
2. 订阅消息模板与授权。  
3. 频控与敏感词（若需要）。
