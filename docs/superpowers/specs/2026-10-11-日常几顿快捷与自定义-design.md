# 日常几顿：快捷 + 自定义

日期：2026-10-11  
状态：已实现（见 `docs/superpowers/plans/2026-10-11-日常几顿快捷与自定义.md`）  
范围：确认页**日常**「几顿」交互；聚会不变。

## 背景

- 现状：日常仅 4 个快捷芯片（一顿晚饭 / 两顿晚饭 / 一顿午饭 / 午+晚），无法表达如「3 顿晚饭」「2 午 1 晚」等。  
- 数据层已是 `mealSlots[]`（`meal: lunch | dinner | other`），缺的是确认页交互。  
- 目标：主路径仍点快捷；需要时用「自定义」弹窗选午/晚顿数。

## 决策

| 项 | 结论 |
|----|------|
| 范围 | **仅日常**；聚会仍只调顿数、`meal: other`，不选午晚 |
| 布局 | 芯片行：4 预设 + **自定义**；步进器**不**常驻页面 |
| 自定义入口 | 点「自定义」→ **弹窗**；加减按钮（非滑动） |
| 弹窗初值 | 首次进入固定 **午 0、晚 0**，不从快捷反推；再次打开用**上次确认的 n/m** |
| 步进范围 | 午、晚各自 0～7；合计上限 **14**；减到 0 不可再减 |
| 弹窗确认 | 允许 0+0；关闭后 `dailySlotMode = custom`，按 n/m 写 `mealSlots` |
| 芯片文案 | 确认后自定义芯片显示 `n午+m晚`；无午则只 `m晚`；无晚则只 `n午`；仍为 0+0 则保持「自定义」 |
| 等于某预设 | **保持自定义高亮**，不自动切到预设芯片 |
| 点回预设 | 按预设写 `mealSlots`；自定义芯片文案恢复「自定义」 |
| `mealSlots` 顺序 | 先全部午饭（`午饭①`…），再全部晚饭（`晚饭①`…） |
| 页面提交 | `mealSlots.length ≥ 1`；自定义 0+0 时 toast **「请先选择吃几顿」**，不打 `recommend.create` |
| 各顿 combo | 仍共用当次一个 `combo`（既有规则） |

## 交互摘要

```
[一顿晚饭] [两顿晚饭] [一顿午饭] [午+晚] [自定义|n午+m晚]
                                              ↓ 点开
                              弹窗：午饭 − N ＋ · 晚饭 − M ＋
                              [取消]  [确认]
```

## 数据

- 提交 `scene.mealSlots` 形状不变：`{ meal, label? }[]`。  
- 前端可增：`dailySlotMode: 'preset' | 'custom'`、`customLunchCount` / `customDinnerCount`（仅 UI；不必落库）。  
- 云函数 / 推荐：按 slot 数拆顿；日常自定义须接受最多 **14** 顿（原建议 ≤7 对日常放宽；**聚会**步进仍建议 ≤7）。

## 埋点（轻量）

- 可选：`meal_slots_mode` = `preset` | `custom`；自定义带 `lunchCount` / `dinnerCount`。

## 非范围

- 聚会选午晚；绑日历日；顿次类型超出午/晚  
- 页面内常驻步进器；滑动选择器  
- 自定义弹窗内「一键填成某预设」（不需要）
