# 家庭菜系偏好与城市提示

日期：2026-10-12  
状态：已实现（见 docs/superpowers/plans/2026-10-12-家庭菜系偏好与城市提示.md）  
范围：家庭级菜系偏好（影响推荐出菜）；城市编辑提示；不改食材货架逻辑。

## 背景

- 城市决定**当地常见食材列表**；用户口味未必是本地菜系（如上海外地人口）。  
- 已有 `dishFormPrefs`（火锅/面食等**菜式形态**），不能替代**菜系**（川/粤/湘…）。  
- 目标：家庭一份菜系偏好，提升出菜准确度；填写要轻；主广告在清单页，准推荐优先于「靠换一批刷曝光」。

## 决策

| 项 | 结论 |
|----|------|
| 食材列表 | **仍只由城市决定**；菜系不改确认页货架 |
| 作用对象 | 推荐出的**菜**（加权 / 硬排除） |
| 层级 | **仅家庭**；本期不做成员覆盖 |
| 强度 | `prefer` / `neutral` / `avoid`（未设=`neutral`） |
| 讨厌 | **硬排除**：菜谱 `cuisineTags` 与任一家庭 `avoid` 有交集 → **整道菜不进入推荐** |
| 喜欢 | 软加权 |
| 填写 UX | 默认全一般；先多选「喜欢」，再多选「讨厌」；互斥；可取消回一般 |
| 入口 | 「我的」完整编辑；**引导保留一步**（可跳过）；轻量弹层本期不收菜系 |
| 家常 | **不对用户展示、不可选**；不写入用户可选词表。菜谱可保留 `home_style` 标签作数据，但不参与 prefer/avoid |
| 字段 code | **英文**（与 `dishFormPrefs` / `avoidTags` 一致） |
| 城市文案 | 编辑城市旁提示：用于匹配当地常见食材，不是口味偏好 |

## 数据

```ts
// users
cuisinePrefs?: { [code: string]: "prefer" | "neutral" | "avoid" }

// recipes
cuisineTags?: string[]  // 英文 code；可多值；可含 home_style（仅数据，不进用户词表）
```

- 与 `dishFormPrefs` 并列；保存走 `profile.updateFamily`（或等价）。  
- 无 `cuisineTags` 的菜：不因菜系被加权或排除（逐步补标）。

## 推荐规则（摘要）

1. 硬排除：若 `recipe.cuisineTags ∩ familyAvoidCuisines ≠ ∅` → 丢弃该菜（「整道去掉」= 不出现在任何方案里）。  
2. 软分：命中 `prefer` 菜系则加分（与品类 prefer 同类，量级实现时定）。  
3. 顺序建议：家庭忌口 / 本场忌口 → **菜系 avoid** → 其余软分（含菜系 prefer、品类、成员等）。  
4. 聚会：用家庭 `cuisinePrefs`（本场不另收菜系）。

## 城市提示

「我的」/ 引导选城市：

- 标题可仍为「城市」  
- 辅助说明：`用于匹配当地常见食材，不是口味偏好`  
- （可选）与菜系区块邻近时加对比句：菜系管爱吃哪路菜，城市管菜场常见货。

## 埋点（轻量）

- 引导步：`onboarding_step` 含菜系步  
- 保存：`profile_update` 带 `fields` 含 `cuisinePrefs`（或专用 `cuisine_prefs_save`，实现时二选一）  
- 不强制新广告相关埋点

## 非范围

- 用菜系改确认页食材列表 / 城市货架  
- 成员级菜系覆盖  
- 轻量补全弹层收菜系  
- 用户可选「家常」档位  
- 拼音 code
