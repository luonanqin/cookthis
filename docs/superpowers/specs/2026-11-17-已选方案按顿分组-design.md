# 已选方案按顿分组

**日期：** 2026-11-17  
**状态：** 待实现  
**相关：** `pages/acceptedPlans`、`listAccepted`、`2026-10-09-已选方案历史与点选已吃-design.md`、`2026-10-28-方案分享-design.md`

## 问题

采纳方案后，已选方案页把一顿方案里的菜打平成一串 chip / 菜名，多顿时无法分辨哪些菜属于同一顿。推荐页已按 `meals[].slot` 分组展示；分享落地页可按 `mealLabel` 分组；列表接口展平时丢掉了顿次。

## 目标

- 已选方案页（自产 + 收到的分享）按顿分组展示菜品。
- **一顿也显示**顿次标签（与推荐页「仅多顿显示」不同）。
- 不改变已吃点选、分享、引导 tip、吸顶 meta 的行为。

## 方案（选定）

列表接口给每道菜带上 `mealLabel`；小程序按标签拼 `mealGroups` 渲染。扁平 `dishes[]` 保留给已吃 / tip / 分享。

### 1. 数据：`listAccepted` 整形

**文件：** `cloudfunctions/_shared/listAccepted.js`（同步 `cloudfunctions/recommend/listAccepted.js`）

**自产 `shapeAcceptedItem`：** 展平时写入：

| 字段 | 规则 |
|------|------|
| `mealLabel` | 优先 `meal.slot.label`；否则 `meal.slot.meal`；再无则 `''` |

其余字段不变：`name`、`recipeId`、`meatVeg`、`ate`。

**分享 `shapeSharedListItem`：** 从 `shareDoc.dishes` 透传已有 `mealLabel`（`buildDishesFromPlan` 已写入）。无字段时等同 `''`。

`plan` / `ateDishNames` / 分页合并逻辑不变。

### 2. 客户端：`acceptedPlans`

**`mapItem`：** 在现有 `dishes` 映射上保留 `mealLabel`；另建 `mealGroups`：按菜品出现顺序，相同 `mealLabel` 归入同一组（与 `sharedPlan.groupDishesByMeal` 同思路）。组内自产项仍带 `ate` 等字段供 chip 绑定。

**标签文案：** 有非空 `mealLabel` 用它；空则显示「本顿」。**始终渲染**标签（含仅一组时）。

**WXML：**

- 自产：按 `mealGroups` 循环 → 标签 + 现有「已吃」chip 行。
- 分享：按 `mealGroups` 循环 → 标签 + 只读菜名；整卡进只读页不变。

**样式：** 复用推荐页 / 分享页 `meal-label` 量级（字号、色、顿间距），不新开视觉体系。

**不变：** tip 仍锚定首张自产卡第一道菜；`onToggleDish` / 分享 `open-type` / sticky meta；`formatSceneSummary(..., { omitSlots: true })` 不改为本需求的一部分。

### 3. 兼容与边界

| 情况 | 行为 |
|------|------|
| 旧分享快照无 `mealLabel` | 整卡一组，标签「本顿」 |
| 聚会单场 | 通常一顿；标签用 slot 文案（如「本场」）或兜底 |
| 多顿日常（第1顿 / 第2顿；旧数据可能仍是午饭①/晚饭①） | 多组，各组有标签 |

**范围外：** 推荐页、买菜清单、已吃记录页、场景摘要行是否展示顿次。

**部署：** 同步并重新部署云函数 `recommend`；小程序重新编译。

### 4. 测试

- `listAccepted.test.js`：多顿自产菜品带正确 `mealLabel`；分享透传 `mealLabel`；无 label 时字段为空/可缺省且不崩。
- 手工：多顿已选方案卡可见分组；一顿卡仍有标签；点选已吃正常。

## 非目标

- 不改 `plan_shares` 快照 schema（已有可选 `mealLabel`）。
- 不强制历史 recommendations 回填；标签来自已存 `plans[].meals[].slot`。
