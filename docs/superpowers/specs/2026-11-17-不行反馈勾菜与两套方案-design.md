# 换菜反馈勾菜与两套方案

**日期：** 2026-11-17  
**状态：** 已实现（交互）；`dishFeedback` 落库待后续讨论  
**相关：** `pages/recommend`、换菜面板、`buildHomePlans`、`2026-10-02-详细设计-推荐与反馈.md` §3.1 / §3.2 / §3.0.6

## 问题

1. 原「不行」只选一个全局原因，无法标出具体哪几道菜、也不能一菜多原因。  
2. 同屏三套方案需要滑屏才能看完，对比负担大。  
3. 「换一批」与「不行」双按钮并存，意图拆分过细；产品改为单一「换菜」入口。

## 目标

- 推荐页**只保留一个 FAB「换菜」**（沿用原「不行」暖色样式以突出），点开原因+勾菜面板；**去掉**独立「换一批 / 换菜」绿钮。  
- 面板：**原因选项卡 + 勾菜**；一道菜可挂多个原因；无面板大标题。  
- 可选菜 **≤10**，从当前批按荤/素/汤比例抽样；列表样式对齐方案卡（类标签固定在左，菜名向右排）。  
- 选中态：菜名上叠**红叉**，不打原因小标签（省空间）。  
- 家常推荐目标套数 **3 → 2**。  
- 交互为主；勾选结果经 `dishFeedback` 随 `reject` 请求带上，**服务端落库另议**（当前仍按整批方案菜写入 `rejectDownranks`）。

## 1. 入口与面板

### 1.1 入口

| 项 | 决定 |
|----|------|
| 推荐页 FAB | **仅**「换菜」一枚；`fab-reject` 暖色（原不行样式） |
| 点击 | 打开换菜原因面板（原 reject 面板） |
| 原「换一批」绿钮 | **移除**（客户端不再调独立 swap UI；云端 `swap` 仍可保留供兼容，产品路径不走） |

### 1.2 面板结构

| 区域 | 内容 |
|------|------|
| 标题 | **无**「不太合适的原因（可选）」 |
| 顶栏 | 4 个原因选项卡，**等分撑满一行**；选中为暖红（与换菜钮同系：`#b35c2e` / `#fff7f0`） |
| 原因顺序与文案 | 不想吃 → 太麻烦 → 不会做 → 没食材 |
| 原因 id | `dont_want` · `too_hard` · `cant_cook` · `wrong_ingredients`（「没食材」沿用 id，仅改文案） |
| 默认选中 | 「不想吃」 |
| 列表 | ≤10 道候选；**荤 / 素 / 汤** 行：左侧 `type-badge` 固定，右侧菜名横向换行（近方案卡，间距略紧） |
| 选中反馈 | 当前原因下已勾的菜：菜名偏暖色 + **红叉叠在菜名正中**（absolute，不占宽）；**不**显示原因小标签 |
| 底栏 | **跳过**（不标菜直接换批）· **完成**（带勾选映射后换批）· **取消**（关面板，不换批） |

- 点菜：在**当前原因**下勾选/取消；换原因可再勾同一道或其它菜。  
- **一菜多原因**：在原因 B 下勾同一道时**保留**原因 A（数据层仍记多 reason；UI 只看当前 tab 是否打叉）。  
- **完成**零勾选 ≡ 跳过。  
- 点遮罩 = 取消（不记 reject、不换批）。

### 1.3 候选菜池（≤10）

1. 从当前批 `plans` 展平，按 `recipeId` 去重（无 id 用规范化菜名）。  
2. 只收 `meat` / `veg` / `soup`；其它类型不进池。  
3. 上限 10：按三类数量比例最大余数分配；某类为 0 则名额匀给有菜的类。  
4. 同类按出现顺序取样；不足 10 则全展示。  
5. 展示顺序：荤块 → 素块 → 汤块。

实现：`miniprogram/utils/rejectDishPool.js`（`buildRejectDishPool`）。

### 1.4 客户端 payload（示意）

```text
{
  planIndex?: number,
  dishFeedback?: { recipeId?, name, reasons: string[] }[],
  skippedReason?: boolean
}
```

`reasons[]` 元素为上表 id（如 `cant_cook`）。  
**落库现状：** 云函数 `reject` 仍写 `feedback[{ type:'reject', at, reason?, planIndex? }]`（仅当有顶层 `reason`）+ 整批 `plans` 菜进 `users.rejectDownranks`；**尚未持久化 `dishFeedback`**（后续讨论）。

## 2. 推荐两套方案

- `TARGET_PLAN_COUNT` / `maxPlans` 默认：**2**。  
- 方案间重复上限只约束两套。  
- 非常规插入逻辑保持；家常基数为 2。

## 3. 非目标

- 不按勾选「只替换问题菜」。  
- 不恢复面板大标题。  
- 不在菜名旁展示多原因标签。

## 4. 验收要点

- 推荐页仅一枚暖色「换菜」；点开无大标题面板。  
- 原因顺序：不想吃 / 太麻烦 / 不会做 / 没食材；选中暖红且四钮等分满宽。  
- ≤10 菜，荤素汤行布局；勾选为菜名上红叉。  
- 跳过 / 零勾选完成 → 换批；取消 → 不换批。  
- 家常最多 2 套。
