# 会员页调试快捷按钮

日期：2026-11-18  
状态：已定稿（待实现）  
范围：开发/体验版会员页底部调试区 + 云函数 `dev*` 扩展；正式环境无入口且云端拒绝。

## 目标

在会员页底部提供一组快捷按钮，方便本机/体验版联调会员态、叠期、即将过期、首购价，无需改库或走真实支付。

## 非目标

- 不改变正式用户购买/履约路径。
- 不在正式版小程序展示调试 UI。
- 不替代真实支付验收（支付链路仍用手点套餐测）。

## 可见性与安全

| 层 | 规则 |
|----|------|
| 前端 | 仅 `wx.getAccountInfoSync().miniProgram.envVersion` 为 `develop` 或 `trial` 时渲染页底「调试」区（对齐首页 `isNonReleaseEnv`） |
| 云函数 | 全部调试 action 要求 `MEMBERSHIP_ALLOW_DEV_GRANT=1`；否则返回 `{ ok: false, error: 'FORBIDDEN' }` |
| 正式 | 正式版无入口；正式云环境不设该环境变量 |

## UI

- 位置：会员页**底部**（页脚链接/刷新等之后，或整页最后一块）。
- 标题：如「调试（仅开发/体验版）」。
- 按钮（一行或多行紧凑）：
  1. 开月卡
  2. 开季卡
  3. 开年卡
  4. 清会员
  5. 约 1 天后到期
  6. 重置首购
  7. 待支付 20s（造单）
  8. **清历史订单**
- 样式：弱视觉，不抢正式套餐区；不必卡片化。
- 交互：点击 → 调对应云 action → 成功则用返回状态 `applyStatus` 刷新；失败 Toast（含未开开关时的 `FORBIDDEN`）。

## 云端行为

共用门禁：`assertDevGrantAllowed()`（与现有 `devGrant` 相同条件）。成功后均返回与 `getStatus(uid)` 同形的状态对象（或 `{ ok: true, ...getStatus fields }`，前端与现网 `applyStatus` 对齐即可）。

### 1. `devGrant(sku)`（已有，前端接线）

- 行为不变：写 `membership_orders`（`amountFen: 0`, `dev: true`）→ `fulfillPaidOrder`。
- **叠期必须保留**：多次点「开月/季/年」走 `computeNewExpiry(max(now, prevExpiresAt) + days)`，同档/跨档均从原到期日累加；不得改为覆盖到期日。
- 首购标记仍按真实履约：该档首次 grant 会占用首购。

### 2. `devClear`

- 将当前 uid 的 `memberships` 行 `expiresAt` 设为已过期（如 `nowMs - 1000`），保留 `tier`/历史字段；若无行则 no-op 后仍 `getStatus`。
- 不删订单、不改 `firstPurchaseUsed`。

### 3. `devExpireSoon`

- 若当前无有效会员：先按月卡执行与 `devGrant('month')` 相同履约（含叠期语义），再把 `expiresAt` 设为 `nowMs + 1 天`。
- 若已有会员行：直接把 `expiresAt` 设为 `nowMs + 1 天`（覆盖当前到期，便于测临期；与「开卡叠期」不同，本按钮语义是「强制改到约一天后」）。

### 4. `devResetFirstPurchase`

- `users.firstPurchaseUsed` 置为 `{}`。
- 该 uid 下所有 `status === 'paid'` 的订单打标 `ignoreForFirstPurchase: true`。
- `loadFirstPurchaseUsed`：跳过带该标的订单，再 `writeFirstPurchaseUsed`，使月/季/年重新显示首购价。
- 订单列表仍展示这些历史单；会员有效期不因本操作改变。

### 5. `devClearOrders`

- 删除该 uid 下 **全部** `membership_orders`（含待支付 / 已支付 / 已关闭）。
- `users.firstPurchaseUsed` 置为 `{}`（无 paid 历史后首购价恢复）。
- **不改** `memberships` 有效期（清列表 ≠ 清会员；要过期用「清会员」）。

## 前端接线

`miniprogram/services/membership.js` 增加：

- `devGrant(sku)`
- `devClear()`
- `devExpireSoon()`
- `devResetFirstPurchase()`
- `devClearOrders()`

会员页：`showDevTools`（`isNonReleaseEnv`）、`onDevGrant` / `onDevClear` / `onDevExpireSoon` / `onDevResetFirstPurchase` / `onDevClearOrders`。

既有单测里「前端禁止出现 `devGrant`」改为：「正式路径（支付 success）仍不直写会员；`devGrant` 仅出现在 `showDevTools` / 调试处理函数中」。

## 测试

- 云：`devGrant` 叠期（连续两次 month，第二次 expiry = 第一次 + 31 天）；`devClear` 后 `isMember=false`；`devExpireSoon` 到期约 +1d；`devResetFirstPurchase` 后 offers 重现首购；无 env 时四者皆 `FORBIDDEN`。
- 前端：wxml 含调试区与按钮；`showDevTools` 依赖 env；service 暴露上述方法。

## 运维

开发云已设 `MEMBERSHIP_ALLOW_DEV_GRANT=1` 才能点通；README / Slice 18 补一句「会员页底调试区仅 develop/trial + 该开关」。

## 验收

1. 开发版会员页底可见调试区；正式版不可见。
2. 连点两次「开月卡」到期日约为起点 +62 天（31+31 叠期）。
3. 「清会员」后状态未开通；「约 1 天后到期」后文案临期。
4. 「重置首购」后三档再出首购标；关云开关后点按钮 Toast 失败。
