## 1. 背景与目标

在需求 v1.0 已归档的前提下，确定 **MVP 技术架构**：微信小程序先验证运营，App 未定；满足日后「手机号统一登录、数据双端同步、打点共享」的扩展条件，但不为未定的 App 提前重做 UI。

### 1.1 已确认约束

| 约束 | 决策 |
|------|------|
| 端 | 先做微信小程序；App 看运营再定 |
| 前端 | 原生微信小程序（暂不上 Taro / uni-app） |
| 后端 | 微信云开发（云函数 + 云数据库）；撑不住再迁自建 |
| 主体 | 个人主体 |
| 登录 | **方案 C**：微信登录为主；手机号选填；后期可强制验证绑定 |
| 账号主键 | 业务 **uid**；登录凭证落在 **`user_identities`**（多身份，详见详细设计） |
| 「我的」资料展示 | **方案 A（自建）**：默认昵称 `大厨` + 短码；默认头像；可自行修改。不拉取微信昵称/头像 |
| 埋点 | **全打**（含食材/记录多方式、场景过程事件）；事件带 `platform`（端）与可选 `loginProvider` |

### 1.2 非目标（本设计不覆盖实现）

- 美团菜品抓取日更、拍照识菜实装、AI 菜谱、订阅消息、社区
- App 客户端 UI
- 短信强制验证（仅预留模型与开关）

## 2. 总体架构

```
小程序（原生）
  ├─ 登录：wx.login → 云函数 auth.login → uid（默认昵称「大厨xxx」）
  ├─ 可选：填写手机号 → users.phone（phoneVerified=false，后期可验）
  ├─ 「我的」：自建昵称/头像（可改）+ 画像 / 手机号选填
  ├─ 页面：首页 / 进场确认 / 输入+场景 / 推荐 / 购买清单 / 记录 / 我的
  └─ 埋点：统一 track() → 云函数 analytics → events

云开发
  ├─ 云函数：auth / profile / ingredients / recommend / meals / analytics
  ├─ 云数据库：users, user_identities, members, ingredients, recipes, meal_logs,
  │            recommendations, events, holidays（可静态）
  └─ 安全：登录态校验；业务数据按 uid 隔离；主数据只读

预留（不做 App UI）
  └─ 自定义登录 / HTTP 访问同一 uid 与库表
```

### 2.1 技术路线结论

| 方案 | 结论 |
|------|------|
| 原生小程序 + 云开发 + uid 账号层 | **采用** |
| Taro + 云开发 | App 未定，暂不采用 |
| 自建 Node 后端 | 云开发配额/能力不足时的后备 |

## 3. 账号与登录（概述）

> 字段级规则、绑定/合并流程、openid 与端类型区分等见  
> **`2026-10-02-详细设计-账号与身份.md`**。

### 3.1 原则（摘要）

- 业务主键：**uid**（一人一条 `users`）  
- 登录方式：多条 **`user_identities`**（`wechat_mp` / 预留 `wechat_app` / `phone`），openid 等是某一 provider 下的平台侧 id，**不**写死在用户「唯一平台类型」上  
- 端类型 `platform`（`mp` / `ios` / `android`）：记在会话与埋点，表示**本次从哪端来**  
- 小程序微信登录 + 手机号选填绑定；展示资料自建（默认「大厨xxxx」）  
- 个人主体：不以微信手机号组件、微信头像昵称为主路径  

### 3.2 登录与资料流程（摘要）

1. `wx.login` → `auth.login`：按 `wechat_mp` 身份查/建 uid，新用户默认昵称/头像  
2. 「我的」改昵称头像 → `profile.updateDisplay`  
3. 「我的」选填手机号 → 写入 `user_identities(provider=phone)`（可不验证）  
4. 后期可强制验证绑定并按功能门槛拦截

## 4. 数据模型

### 4.1 集合

| 集合 | 作用 | 关键字段（示意） |
|------|------|------------------|
| `users` | 账号 + 家庭级设置 | `uid`；`nickname`；`avatarUrl?`；`phone?`；`phoneVerified`；`city`；`defaultPeopleCount` **成员数缓存**（UI 不单独编）；`defaultCombo`；`mealTimes`；`cookBudget`；`familyAvoids[]`；`familyAvoidsNone?`；`cuisinePrefs{}`；`cuisinePrefsConfirmedAt?`；`dishFormPrefs{}`；`onboardingDone`；`profileLitePromptedAt?`；`profileLiteSkipped?`；`rejectDownranks[]`；`createdAt`（常驻提醒见 `2026-10-19-跳过引导与画像提醒-design.md`） |
| `user_identities` | 登录身份绑定 | `uid` 所属用户；`provider` 登录方式（小程序微信/App微信/手机号）；`providerUserId` 该方式下的平台 id（如 openid、手机号）；`unionId?` 微信开放平台统一 id；`verified` 该身份是否已验证；`createdAt` 绑定时间（详见账号详细设计） |
| `members` | 家庭成员（人数唯一来源） | `uid`；`memberId`；`name`；`ageBand`（仅 `5_15`/`16_25`/`26_40`/`41_59`/`60_plus`）；`taste`；`avoids[]`；`dishFormPrefs?`；大/小/老映射见用户画像 §2.2.2 |
| `ingredients` | 常见/在售菜 | `id` 食材 id；`name` 名称；`category` 分类；`cities[]` 适用城市（空数组=全国）；`kind` 主料/调味；`availability` 四季/时令；`onConfirmPage` 是否进确认主列表；`avoidTags[]` 忌口大类（pork/seafood 等）；`sort` 常见度；`source` 来源；`updatedAt` 更新时间 |
| `recipes` | 菜谱库 | `id` 菜谱 id；`name` 菜名；`mainIngredients[]` 主料；`seasonings[]` 调味；`meatVeg` 荤/素/汤/主食等；`tasteTags[]` 口味标签；`dishForms[]` 菜式形态；`stapleForms[]` 主食形态；`cities[]` 适用城市（同食材）；`minutes` 预计耗时（分钟）；`servings` 适合人数 |
| `meal_logs` | 饮食记录 | `uid` 用户；`date` 日期；`meal` 餐次（`lunch`/`dinner`/`unknown` 等，**不是**场景的 `mealType`）；`dishNames[]` 菜名；`ingredientNames[]` 相关食材；`source` 来源（手动/拍照/语音/进场确认/`plan_ate`）；`recommendationId?` / `requestId?`；`logId`；`createdAt` 写入时间 |
| `recommendations` | 推荐会话 | `uid` 用户；`requestId` 本次请求 id；`scene` 当次场景快照；`plans[]` 推荐方案列表；`accepted` 是否点过方案旁「去买菜」；`acceptedAt?` 采纳时间；`acceptedPlanIndex?` 采纳的方案序号；`engagedAt?` 有效停留时刻（可见≥30s）；`dwellMs?` 累计可见毫秒；`engagedPlanIndex?` 停留时方案；`entryConfirmHandled?` 进场确认已处理（确认或跳过）；`entryConfirmHandledAt?`；`swapCount` 换一批次数；`createdAt` 创建时间 |
| `events` | 统一埋点 | `uid?` 用户（可空）；`event` 事件名；`props` 事件属性；`platform` 端（小程序/iOS/Android）；`loginProvider?` 本次登录方式；`appVersion` 应用版本；`sessionId?` 会话 id；`ts` 客户端时间 |
| `holidays` | 节日日历 | 一年一条：`year`；`items[]`：`id` 稳定代号、`date` 该年公历、`nameZh` / `nameEn` |

`ingredient_sync_jobs`：命名预留（美团同步任务），MVP 不建表不写任务。

> 说明：`users` **不再**单独存一份「当前 openid」作为主键替身；微信身份一律进 `user_identities`。`users.phone` 可作展示冗余，以 identities 中 `phone` 记录为准（详细设计约定同步规则）。
### 4.2 权限

- 业务读写以 **云函数** 为准，减少小程序直连写库  
- 业务记录均带 `uid`，函数内校验当前用户  
- `ingredients` / `recipes` / `holidays`：客户端只读；写入用脚本或管理流程

## 5. 云函数边界

| 函数 | 职责 | 不负责 |
|------|------|--------|
| `auth` | login（写/查 identities）、bindPhone | 推荐 |
| `profile` | 家庭设置、成员 CRUD、**updateDisplay（昵称/头像）** | 推荐 |
| `ingredients` | 按时令/四季分层的确认列表（无城市→全国兜底） | 美团抓取 |
| `recommend` | 规则引擎、换一批、写 recommendations、采纳标记、**listAccepted（已选方案分页）** | 写 meal_logs |
| `meals` | 进场确认候选与去重、确认写入、手动记、语音记、**按 logId 删除**、**planAteOn/Off** | 采纳/停留时自动记；拍照识菜 |
| `analytics` | track 批量写 events | 报表 UI |

### 5.1 推荐引擎

顺序：

1. 家庭忌口硬排除（按菜谱食材 `avoidTags` 与词表求交，不用菜名）  
2. 近 7 日 `meal_logs`：同菜名硬排除；主料重叠按分档+时间衰减加软惩罚（越高越靠后；细则 → 推荐与反馈 §3.0.4）  
3. 按搭配 + 顿数组合**家常**候选；画像品类 `prefer` 时再尝试至多 1 套非常规方案（火锅 / 面条 / 水饺）  
4. **用餐人软分**（§3.0.8）：日常 = members ∪ `guestCounts`；聚会 = 仅 `partyCounts` 档位默认；硬排除日常 `familyAvoids` / 聚会 `partyAvoids`；聚会 `combo` 来自 `suggestPartyCombo`；菜式品类加权；耗时等  
5. **组合多样性**：软排序后按 `hash(uid+requestId)` 对桶内稳定旋转（§3.0.5）  
6. 拼单套 home 时 **方案内去重**（§3.0.7）  
7. 输出 1～3 个 plan；**多方案菜名重复上限**（§3.0.6）；换一批排除已展示菜  

成员忌口完整占比配额后续细化。学龄前（5 岁以下）不在推荐范围。

### 5.2 进场确认去重

锚点 = 近期会话中 **锚点时刻最晚** 的一次 **采纳**（`acceptedAt`）或 **有效停留**（`engagedAt`，推荐页可见 ≥30s）；只看这一条，**不往前翻**更早会话。  
若该条已 `entryConfirmHandled`、或候选为空、或无锚点 → **不弹层**。  

待确认列表 = 该锚点 plan 菜名 −「近期已记录」（`meal_logs.createdAt >=` 锚点时刻）。  

用户对该弹层 **确认（含勾 0 道）或跳过** 后：标记 `entryConfirmHandled=true`；下次仍只评估最新锚点，已处理则不弹。仅出现**更新的**采纳/有效停留才会再弹。  

采纳 / 有效停留 **不** 自动写 `meal_logs`，只更新 `recommendations` 上对应字段。

### 5.3 场景与搭配

- 日常：大/小/老由 `members` 派生；`guestCounts` 可加减；`defaultCombo` **可改**；写回只写 combo。细则 → 菜场 §3.1.1、用户画像 §2.2.2  
- **聚会**：三档 `partyCounts`；**不露荤素汤**；`combo = suggestPartyCombo`（无小孩荤+1；总菜 n 或 n+种子随机 1~2；见菜场 §3.2.1）；`partyAvoids` 硬排除；档位默认软分；不写回  
- 日常午/晚在 `mealSlots`；聚会默认 1 顿、不区分午晚。

## 6. 页面与接口流程

| 页面 | 用户动作 | 云函数 | 成功后 |
|------|----------|--------|--------|
| 启动 / 首页 | 静默登录 | `auth.login` | 本地存 uid |
| 首页 | 今天菜场有什么 | `meals.confirmCandidates` | 有候选→弹层，无→输入页 |
| 进场确认 | 确认吃过 / 跳过 | `meals.confirmWrite` 或 skip（均标 `entryConfirmHandled`） | 输入页 |
| 首页 | 记一下 | — | 记录页 |
| 输入页 | 日常：大/小/老+可改搭配；聚会：大/小/老+本场忌口、自动 combo | `ingredients.list`；`profile.get`；`suggestPartyCombo`（聚会） | 日常忌口空 → 轻量补全；否则 `recommend.create`；**create 空 → 本页同款「食材不够出菜了」弹窗，不进推荐页、不写空会话** |
| 轻量补全弹层 | 保存忌口/可选品类，或跳过 | `profile` liteSave；标记 `profileLitePromptedAt` | `recommend.create` |
| 推荐页 | 方案旁「去买菜」/换一批·不行/有效停留 | `recommend.*`（含 `engage`、`accept`+planIndex） | 去买菜→购买食材页；**swap/reject 无新方案 →「好吧」弹窗并保留当前方案（不切空页）** |
| 购买食材页 | 勾选已买；底部菜谱弹层 | 本地 | — |
| 记录页 | 手动提交；按条删除 | `meals.addManual` / `meals.remove` | — |
| 我的 → 已选方案 | 浏览；点选/取消已吃 | `recommend.listAccepted`；`meals.planAteOn` / `planAteOff` | 乐观勾选 |
| 我的 | 头像昵称 / **成员 CRUD** / 家庭忌口品类搭配城市 / 手机号 | `profile.updateDisplay` / `addMember`/`updateMember`/`removeMember` / `updateFamily` / `auth.bindPhone` | 人数摘要随成员变 |

主路径：

```
首页 → confirmCandidates
  ├─ 有候选：弹层 → confirmWrite → 输入页
  └─ 无候选：输入页
输入页 →（日常且忌口空：轻量补全弹层可跳过）→ recommend.create → 推荐页
  ├─ swap / reject
  └─ accept（「去买菜」）→ 购买食材页（无「查看清单」预览入口）
```

`recommend.create` / `swap`：**不**全量拉 `recipes`；按用户城市优先、再补全国，每批最多 50 道（见推荐详设候选池）；`ingredients` 可在云函数实例内缓存；鉴权后读库尽量 `Promise.all` 并行。

## 8. MVP 交付与工程结构

### 8.1 做 / 不做

**做：** …场景（**日常 / 聚会**；聚会自动 combo、不露荤素汤）…规则推荐（§3.0.8；`suggestPartyCombo`）…画像成员 CRUD…

**不做：** 美团日更实装、拍照识菜 / **语音补菜** / 拍照记饮食（入口不展示）、AI、订阅消息、App、短信强制验证。

### 8.2 目录建议

```
miniprogram/          # 页面、组件、services（含 track）、云调用封装
cloudfunctions/       # auth profile ingredients recommend meals analytics
data/                 # recipes.json、ingredients-builtin.json、holidays.json
doc/                  # 需求与流程图等
docs/superpowers/specs/  # 技术设计概述 + 各模块详细设计
```

详细设计文件名见本文 **§0 索引**。
### 8.3 里程碑

| 里程碑 | 内容 |
|--------|------|
| M1 | 登录 + 画像 + 埋点骨架 |
| M2 | 食材 + 场景 + 进场确认 |
| M3 | 推荐 + 换一批 + 购买清单 |
| M4 | 手动记录 + 菜谱/食材数据导入 + 打磨 |

### 8.4 风险

| 风险 | 对策 |
|------|------|
| 个人主体手机号能力弱 | 选填不验证；后期短信+功能锁 |
| 菜谱数据不足 | 初期目标 200～500 道 JSON 导入（结构正确优先） |
| 推荐空结果 | **禁止整页空态**：create / swap / reject 空均用同款窄窗「食材不够出菜了」；create 空留确认页且不写会话；swap/reject 空保留原方案（`noNewPlans`）；埋点 `empty_recommend` |
| 埋点量大 | 批量写 events |
| 以后上 App | uid + 自定义登录预留；UI 重做 |
