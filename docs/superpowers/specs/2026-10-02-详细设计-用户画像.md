## 1. 范围

- 家庭级设置：默认搭配、用餐时间、做饭预算、城市、家庭忌口、菜式品类偏好；**人数由成员列表派生**  
- 成员：在「我的」与引导中增删改；每人口味 / 忌口 / 年龄段；可选品类覆盖  
- 大/小/老展示与当次访客规则（与菜场场景协同）  
- 首次引导（onboarding）步骤与落库  
- **不含**：登录 identities、默认「大厨」生成算法（见账号详细设计）；学龄前（5 岁以下）饮食推荐

## 2. 数据模型

### 2.1 落在 `users` 的家庭字段

| 字段 | 说明 | 枚举 / 结构 |
|------|------|-------------|
| `city` | 城市，影响默认食材与可见菜谱；UI 旁注「仅用于匹配当地常见食材」 | 单个行政区名或 adcode |
| `defaultPeopleCount` | **成员数缓存**（= `members.length`；增删成员后回写；**UI 不单独编辑**） | number ≥ 0 |
| `defaultCombo` | 日常默认搭配 | `{ meat, veg, soup }` 或编码如 `1-1-1` |
| `mealTimes` | 一般几点吃饭 | `{ lunch?: "12:00", dinner?: "18:30" }` |
| `cookBudget` | 做饭时间预算 | `le15` \| `about30` \| `ge60` |
| `familyAvoids` | 家庭忌口（硬排除） | string[]，词表见 §3 |
| `dishFormPrefs` | 家庭菜式品类偏好（形态，非菜系） | `{ [tag]: "prefer"\|"neutral"\|"avoid" }` |
| `cuisinePrefs` | 家庭**菜系**偏好（只影响出菜） | `{ [code]: "prefer"\|"neutral"\|"avoid" }`；词表与规则 → [`2026-10-12-家庭菜系偏好与城市提示-design.md`](./2026-10-12-家庭菜系偏好与城市提示-design.md) |
| `onboardingDone` | 是否完成完整引导 | bool |
| `profileLitePromptedAt` | 日常轻量补全弹层已展示并处理（保存或跳过）的时间 | date? |
| `rejectDownranks` | 点「不行」累积的软降权菜谱 id（非硬排除） | string[]（recipeId） |

### 2.2 `members`

| 字段 | 说明 |
|------|------|
| `uid` | 所属用户 |
| `memberId` | 成员 id |
| `name` | 展示名（本人/配偶/孩子或自定义） |
| `role` | 可选：`self` \| `spouse` \| `child` \| `other` |
| `ageBand` | 年龄段，见 §2.2.1；引导与「我的」必填 |
| `taste` | `light` \| `normal` \| `heavy` \| `spicy` |
| `avoids` | string[]，词表与家庭忌口同一套 |
| `dishFormPrefs` | 可选，覆盖家庭级同名 tag |
| `sort` | 展示排序 |
| `createdAt` / `updatedAt` | — |

约束：同一 `uid` 下引导完成后建议 ≥1（本人）；0 个成员时日常人数按 1 大处理（或强制补本人）。  
**人数唯一来源**：`peopleCount`（档案）= 成员条数；摘要 `x大 y小 z老` 由年龄段映射（§2.2.2）。

#### 2.2.1 年龄段 `ageBand`（枚举，仅五档）

| 值 | 含义 | 大/小/老 |
|----|------|----------|
| `5_15` | 5–15 岁 | **小** |
| `16_25` | 16–25 岁 | **大** |
| `26_40` | 26–40 岁 | **大** |
| `41_59` | 41–59 岁 | **大** |
| `60_plus` | 60 岁及以上 | **老** |

**不做** `0_2` / `3_5` 等学龄前档：5 岁以下饮食需特殊处理，**不在**本产品菜谱推荐范围内。  
历史数据若仍为旧枚举：读时把 `6_15`→`5_15`，`41_60`→`41_59`；`0_2`/`3_5` 提示用户改选或忽略不计人「小」。

#### 2.2.2 大 / 小 / 老

| 档 | 年龄段 | 用途 |
|----|--------|------|
| 小 | `5_15` | 展示；推荐对辣/重口软降权；访客默认口味 `light` |
| 大 | `16_25` `26_40` `41_59` | 展示；访客默认口味 `normal` |
| 老 | `60_plus` | 展示；推荐对辣/重口软降权；访客默认口味 `light` |

**不**用大/小/老自动改 `defaultCombo` / 当次荤素汤份量（用户自选搭配）。

#### 2.2.3 「我的」成员管理（必做）

- 列表展示每位：称呼、年龄段、口味、个人忌口摘要；顶栏或列表上：`共 N 人 · x大 y小 z老`。  
- 支持添加 / 编辑 / 删除；字段必填：`name`、`ageBand`、`taste`（默认 `normal`）、`avoids`（可空）。  
- **无**独立「日常默认人数」编辑控件；保存成员后同步 `users.defaultPeopleCount = N`。  
- 入口文案可与「日常默认」区并列：只读人数摘要 +「管理家人」跳转成员列表；搭配编辑仍可保留。

### 2.3 忌口词表（固定）

| code | 展示 | 覆盖食材（示例，入库用 `avoidTags` 标注） |
|------|------|------------------------------------------|
| `pork` | 猪肉类 | 猪肉、五花肉、排骨、猪蹄、火腿、腊肉、肉末（猪）、猪油等 |
| `seafood` | 海鲜 | 鱼、虾、蟹、贝、鱿鱼等 |
| `offal` | 内脏 | 猪肝、腰花、鸭血等 |
| `coriander` | 香菜 | 香菜 |
| `peanut` | 花生 | 花生、花生酱等 |
| `dairy` | 乳制品 | 牛奶、奶油、奶酪等 |
| `other` | 其他 | 附 `avoidNote`；**不参与**自动硬排除，标准大类请用上表 code |

宗教 / 全户绝不碰的品类（如不吃猪肉）必须放在**家庭忌口**勾 `pork`，不要只放成员忌口（成员忌口仅降权）。

### 2.3.1 硬排除怎么匹配（家庭 / 本场忌口）

**只按菜谱所含食材匹配词表，不靠菜名。**

1. 取菜谱 `mainIngredients` ∪ `seasonings`（名称或 id）  
2. 解析到 `ingredients`；每条食材带 `avoidTags: string[]`（如五花肉 → `["pork"]`，带鱼 → `["seafood"]`）  
3. 若与 `familyAvoids` / `partyAvoids` **有交集** → **丢弃该菜谱**  
4. 未入库自定义主料：别名能归到某大类则同样排除，否则可留下并打日志；猪肉/海鲜等大类别名须在导入数据里配齐  

成员 `avoids`：同一套食材→词表匹配，命中则**降权不删除**。

### 2.4 菜式品类 tag

**菜式形态** `dishForms`：`stir_fry` 热炒 · `cold` 凉菜 · `braised` 卤菜 · `hotpot` 火锅 · `soup` 汤羹 · `steam` 蒸菜 · `bbq` 烧烤  

**主食形态** `stapleForms`：`rice` 米食 · `noodle` 面食 · `congee` 粥粉 · `bing` 饼类 · `dumpling` 水饺  

画像展示「面食」对应 key `noodle`：`prefer` 时面条局与水饺局都可出；`avoid` 时两类都不出。菜谱上水饺仍标 `dumpling`，用户不必再勾一层。  

偏好强度：`prefer` / `neutral` / `avoid`（未设置视为 `neutral`）。

### 2.5 搭配结构 `combo`

```jsonc
{ "meat": 1, "veg": 1, "soup": 0 } // 荤 / 素 / 汤 道数 → 一荤一素
```

展示文案由前端映射（一荤一素、一荤两素一汤等）。人数推荐表见 `详细设计-菜场输入与场景.md`。

**午饭 / 晚饭是否拆两套默认（已定）**：
- **不拆。** 画像只存一份 `defaultCombo`，按晚饭理解为宜（菜场主场景）；**日常**要几顿、午还是晚由当次 `mealSlots`（仅 `meal`，不绑日历日）决定，各顿共用这一套荤素汤，当次仍可改 `combo`。**非日常**默认 1 顿、可改顿数，不区分午/晚。哪一天吃由用户自行安排。
- `mealTimes` 只表示习惯几点吃（提醒用），不表示搭配。
- 不在引导里让用户分别设置午/晚默认，避免设置负担。
- **可后置：** 若运营上发现午饭长期要更简，再考虑当次「午饭用简配」或 `defaultComboByMeal`；先不改表结构。

### 2.6 完整示例（1 用户 : N 成员）

关系：一个账号 `users` 下多条 `members`（本人、配偶、孩子等）。忌口/品类在家庭级与成员级都可出现（成员可覆盖）。

```jsonc

{
  "uid": "u_demo001",                          // 业务用户主键
  "city": "杭州",                              // 所在城市（单个）
  "defaultPeopleCount": 3,                     // = members.length（缓存，UI 不单独编）
  "defaultCombo": {                            // 日常默认荤素汤（全户一份）
    "meat": 1,                                 // 荤
    "veg": 1,                                  // 素
    "soup": 1                                  // 汤
  },
  "mealTimes": {                               // 习惯几点吃饭（提醒用）
    "lunch": "12:00",
    "dinner": "18:30"
  },
  "cookBudget": "about30",                     // 做饭时间预算
  "familyAvoids": ["peanut"],                  // 家庭忌口：花生
  "dishFormPrefs": {                           // 家庭菜式品类偏好
    "stir_fry": "prefer",                      // 热炒：爱吃
    "hotpot": "neutral",                       // 火锅：一般
    "cold": "avoid",                           // 凉菜：少做
    "rice": "prefer",                          // 米食：爱吃
    "noodle": "neutral"                        // 面食（含面条/水饺方案开关）：一般
  },
  "onboardingDone": true                       // 是否完成首次引导
}

// members（N）
[
  {
    "uid": "u_demo001",                        // 所属用户
    "memberId": "m_self",                      // 成员 id
    "name": "我",                              // 称呼
    "role": "self",                            // 角色：本人
    "ageBand": "26_40",                        // 年龄段 26–40
    "taste": "normal",                         // 口味：正常
    "avoids": ["coriander"],                   // 个人忌口：香菜

    "sort": 0,                                 // 展示排序
    "createdAt": "2026-10-01T10:05:00.000Z",
    "updatedAt": "2026-10-01T10:05:00.000Z"
  },
  {
    "uid": "u_demo001",
    "memberId": "m_spouse",
    "name": "配偶",
    "role": "spouse",                          // 角色：配偶
    "ageBand": "26_40",
    "taste": "light",                          // 口味：清淡
    "avoids": [],                              // 无个人忌口
    "dishFormPrefs": { "spicy": "avoid" },     // 个人覆盖：少辣
    "sort": 1,
    "createdAt": "2026-10-01T10:06:00.000Z",
    "updatedAt": "2026-10-01T10:06:00.000Z"
  },
  {
    "uid": "u_demo001",
    "memberId": "m_child",
    "name": "孩子",
    "role": "child",                           // 角色：孩子
    "ageBand": "5_15",                         // 年龄段 5–15（小）
```

说明：推荐时家庭忌口按食材 `avoidTags` 硬排除（如 `pork` 去掉一切含猪肉类主料/调味的菜）；成员 `avoids` 仅降权。

## 4. 首次引导

### 4.1 完整引导（onboarding 页）

建议步骤（可微调文案，埋点 `onboarding_step`）：

1. 家庭忌口  
2. 菜式品类偏好（可跳过则全 neutral）  
3. **菜系偏好**（可跳过则全 neutral；先多选喜欢再多选讨厌；无「家常」选项）  
4. 添加成员（至少本人：年龄段五档 + 口味 + 忌口；可「再加一位」）  
5. 默认搭配、用餐时间、做饭预算、城市（旁注：`仅用于匹配当地常见食材`；**人数由成员数摘要不编**）  

允许跳过非关键步，但 `familyAvoids` 与「本人」建议强引导。完成后 `onboardingDone=true`。首页可「先逛逛」跳过完整引导。

### 4.2 日常轻量补全弹层（确认食材后）

面向「先逛逛、未填忌口」用户：在**日常**路径确认食材与场景之后、调用 `recommend.create` 之前，用短弹层收最有用的家庭设置；**可取消/跳过，不挡出方案**。

| 项 | 约定 |
|----|------|
| 触发 | `scene.mealType === daily` 且 `familyAvoids` 为空（且尚未标记轻量弹层已处理） |
| 不触发 | 非日常；已有家庭忌口；本用户已保存或跳过过该弹层 |
| 字段 | ① 家庭忌口多选（短词表，可「更多」）；② **爱吃什么（可选）**：多选「火锅」「面食」→ 写 `dishFormPrefs.hotpot` / `noodle = prefer` |
| 不收 | 人数、搭配、成员、用餐时间、城市、预算（场景页或完整引导 /「我的」） |
| 主按钮 | 保存 → `profile` 写 `familyAvoids`（及可选 prefs）→ 再 `recommend.create`（当次即用新忌口硬排除） |
| 次按钮 | 暂时跳过 → 直接 `recommend.create`；标记已提示，避免反复弹 |
| 文案 | 强调「填忌口少推不能吃的；跳过不影响本次看方案」 |

可选用户字段：`profileLitePromptedAt`（date）或 `profileLiteSkipped: bool`，与 `onboardingDone` 独立——跳过轻量弹层**不等于**完成完整引导。

埋点：`profile_lite_show` / `profile_lite_save` / `profile_lite_skip`。

## 5. 供推荐消费的快照

`recommend` 读取时组装：

```ts
{
  familyAvoids,
  members: [{ ageBand, taste, avoids, dishFormPrefs? }],
  // 日常：members + scene.guestCounts；非日常：仅 scene.partyCounts 档位默认（见菜场 §3.1.1–3.1.2）
  dishFormPrefs,      // 家庭
  cookBudget,
  defaultPeopleCount, // = members.length 缓存
  defaultCombo
}
```

- **硬排除**：日常 `familyAvoids`；非日常 `partyAvoids`（本场忌口，不写回家庭）——按菜谱食材 `avoidTags` 求交（§2.3.1），**不**用菜名  
- **成员忌口**：**降权**（日常用餐人含档案成员时）；非日常用餐人不并入档案成员个人忌口  
- **年龄段**：有「小」或「老」（含访客/本场档）时，对菜谱辣/重口软降权（见推荐 §3.0.8）  
- **口味**：用餐人 `taste`（档案或档位默认）与菜谱软匹配（见推荐 §3.0.8）  
- **品类**：家庭 prefer 加权、avoid 降权；成员覆盖同 tag 时以成员为准参与该人相关分  
- **非常规方案**（火锅 / 面条 / 水饺）：由推荐引擎按本快照触发，不经过当次场景勾选。细则见推荐与反馈。

## 7. 边界

账号登录与 identities → 账号详细设计。当次场景覆盖人数/搭配/忌口 → 菜场输入与场景详细设计。
