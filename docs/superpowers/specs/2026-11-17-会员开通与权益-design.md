> 日期：2026-11-17  
> 状态：已实现，待手测（2026-11-18；未在微信开发者工具执行，§12 保持未勾）

## 1. Goal

上线可购买的轻会员：用户能看清权益与今日换菜用量、完成首购/复购支付、服务端认定会员态；换菜触顶可导向开通，且**不挡今天去买菜**。

## 2. Non-goals

- 成长值 / 饭友等级  
- 自动续费  
- 冰箱配菜、菜谱导入、食记扩容等非本产品能力  
- **单独的权益说明页**（权益少，全部做进同一会员页）  
- 清单/开屏去广告的实现（阶段 2；页上阶段 1 不承诺「已免展示广告」）

## 3. 入口与状态展示

### 3.1 首页 VIP 入口

- 位置：首页顶栏 **字号切换「大」按钮左侧**（`home-type-scale` 左侧）。  
- 形态：可点击的 **VIP 闪光图**（静态图或短循环动效；资源放入 `miniprogram/assets/images/`）。  
- 点击 → `pages/membership/index`（可带 `from=home_vip`）。  
- 未开通 / 已开通均进**同一页**；页内按态切换「购买」与「会员信息」。

### 3.2 「我的」资料区

- 在昵称 / 「第 N 位大厨」一带展示 **会员状态**：  
  - 未开通：如「未开通会员」或弱文案 + 可点进开通页  
  - 已开通：如「会员至 YYYY-MM-DD」  
- 整块资料区或状态文案可点进同一会员页（`from=mine`）。

### 3.3 换菜触顶

- 见 §7；「开通会员」进同一页（`from=swap_cap`）。

## 4. 单页信息架构（不拆权益页）

`pages/membership/index` 一页搞定：

| 区块 | 未开通 / 已过期 | 生效中 |
|------|-----------------|--------|
| 顶栏状态 | 未开通 | 会员生效中 · 到期日 |
| 权益要点 | 3～4 条宫格或列表（换菜不限次、日常菜数放宽、免换菜激励预告等） | 同左，可标「已享有」 |
| 用量 | 换菜：每日 3 次 · 今日已用 x | 换菜不限次（可仍展示今日已换次数作参考） |
| 套餐 + CTA | 月/季/年 + 底栏支付 | **隐藏购买**或收起到「续费/再买」 |
| 会员信息 | — | 档位、生效/到期、订单入口（可选）、刷新会员状态 |
| 购买须知 | 支付前可打开；建议首次支付前确认「已知晓」 | 可仍从页脚打开 |

**禁止**再做 `pages/membership/benefits` 之类仅展示权益的第二页。

## 5. 权益（页上文案）

对齐盈利方案；与竞品六宫格无关。

| 权益 | 普通 | 会员 |
|------|------|------|
| 换菜 | 自然日 **3** 次（日常+聚会一池）；触顶仍可去买菜 | **不限次**（客户端冷却 + 服务端限流） |
| 日常单次总菜数 | ≤ **12**（各顿菜谱卡之和；聚会免检） | **不限**（仍受推荐引擎合理上限/频控，避免拖库） |
| 换菜激励 | 激励可用后：看 1 得 1；可有激励日上限 | **免看激励** |
| 展示类广告 | 阶段 2 前无 | 阶段 2 去广告；阶段 1 **不写**「已免清单广告」 |

## 6. 套餐与定价

| SKU | 时长 | 页价 | 首购价 |
|-----|------|------|--------|
| `month` | 31 天 | **¥6.6** | **¥0.99** |
| `quarter` | 93 天 | **¥16.6**（约 ¥5.5/月） | **¥9.9** |
| `year` | 365 天 | **¥56.6**（约 ¥4.7/月） | **¥39.9** |

> 页价已定稿；首购季/年可配置，上表为默认。

规则：

- **单次购买，不自动续费。**  
- **每档首购优惠各用一次**（月/季/年互不占用）；用过后该档显示页价。  
- 月卡首购 **固定 0.99 元**。  
- 价格与商品 ID 放云配置或常量模块；每档首购/页价各一个米大师道具（共 6 个），避免固定标价冲突。

购买须知要点：

1. 不自动续费  
2. 支付成功权益自动到账；异常时可点「刷新会员状态」  
3. 各档首购优惠仅一次  
4. 会员免的是 **换菜功能激励**；展示类广告策略以届时说明为准（阶段 1 无清单广告则照实写）  
5. 虚拟商品，原则上不退（合规表述）

## 7. 换菜额度与触顶（服务端强制）

- 鉴权：云函数 `recommend` 换菜路径（当前产品为 `reject` 管道）校验：  
  - `isMemberActive(uid)` → 不扣日免费额度  
  - 否则自然日（`Asia/Shanghai`）`used < 3` 才允许换批成功并 `used++`  
  - 触顶返回明确错误码，如 `SWAP_CAP`，附 `used` / `limit`  
- 前端触顶层（软挡）：  
  1. 文案：今日免费换菜已用完；**当前方案仍可去买菜**  
  2. **主按钮：去买菜**  
  3. 次：看视频再换 1 次（激励开关打开时）  
  4. 次：开通会员  
- **禁止**因额度清空方案或禁止进清单。

## 8. 数据模型

### 8.1 `memberships`（当前态，每 uid 一条或取最新 active）

| 字段 | 说明 |
|------|------|
| `uid` | 用户 |
| `tier` | `month` \| `quarter` \| `year` |
| `startsAt` | 生效 |
| `expiresAt` | 到期；`now < expiresAt` 为有效 |
| `updatedAt` | |

查询：`expiresAt > now` 视为会员。续费：若仍在有效期内购买，从 `max(now, expiresAt)` 起叠加时长（实现时写死「叠加」或「从支付日重算」，推荐 **在原到期日上叠加**）。

### 8.2 `membership_orders`

| 字段 | 说明 |
|------|------|
| `orderId` | 业务订单号 |
| `uid` | |
| `sku` | |
| `amountFen` | 实付分 |
| `isFirstPurchase` | 是否命中该档首购 |
| `wxPayment` | 微信侧单号等 |
| `status` | `created` \| `paid` \| `closed` \| `refunded` |
| `createdAt` / `paidAt` | |

### 8.3 首购标记

- `users.firstPurchaseUsed: { month?: true, quarter?: true, year?: true }`  
  或订单聚合判断「该 uid+sku 是否曾有 paid」。推荐 **订单聚合为准**，users 上缓存可加速展示价。

### 8.4 换菜日额度

- 集合或 user 子字段：`swapDaily: { day: 'YYYY-MM-DD', used: number, rewardExtra: number, rewardWatches: number }`  
- 日切按上海时区。

## 9. 支付与云函数

| API（示意） | 职责 |
|-------------|------|
| `membership.getStatus` | 是否会员、到期、今日换菜 used/limit、各档是否仍首购、展示价 |
| `membership.createOrder` | 校验 sku、算价（含 0.99 首购）、建单、返回支付参数 |
| `membership.payCallback` / 查单 | 验签、标记 paid、写/续 `memberships`、记首购 |
| `membership.refresh` | 主动查单对账，给「刷新会员状态」按钮 |

技术：微信小程序虚拟支付 / 米大师道具直购（`short_series_goods`）；**一切以服务端 `fulfillPaidOrder` 为准**，前端成功回调不可单独授会员。环境变量与推送见 `cloudfunctions/membership/README.md`。

`xpay.queryOrder` 当前为 stub（恒返回 `null`）。`refresh` 因此还不能凭查单补发货；延迟到账依赖消息推送 `xpay_goods_deliver_notify`。`devGrant` 仅当 `MEMBERSHIP_ALLOW_DEV_GRANT=1`。

失败：支付取消不建权益；超时可刷新；重复通知幂等。

### 9.1 未支付订单（已拍板，已实现）

- **全局同时仅 1 笔**未支付（`created` 且未过 `payExpiresAt`）；列表展示近 5 条：`paid` + 有效未支付；已取消 / 已过期不展示（或灰显无操作）。
- 同档再下单 → 弹层引导支付已有未支付单（复用 `orderId` 重签）。
- 异档再下单 → 提示已有未支付单；确认后**关旧单并自动下新档订单**。
- **有效期 5 分钟**（`payExpiresAt`）；后端不跑倒计时，**懒关闭**（`getStatus` / `createOrder` / `cancelOrder` / 重签时收敛）。过期只禁「取消 / 再拉起支付」；微信已付款的发货回调仍授期。
- **`cancelOrder` 或再次拉起支付 / 重签**若订单已过期或已关闭：前端统一 Toast（或等价提示）**「订单已取消，请重新下单」**，并刷新列表/状态。
- 同用户 `createOrder` 短时串行锁（后端 `orderLockUntil` + 前端 busy）。
- 查单契机：支付 success 轮询、`refresh`、再进会员页（频控）；`queryOrder` 接通后生效。

## 11. UI 资源与实现要点

- VIP 闪光图：首页 `home-nav` / 顶栏行内，在 `home-type-scale` **左侧**；触控热区 ≥ 44px。  
- 「我的」状态与首页入口视觉可统一 VIP 小标，避免两套语义。  
- 会员页视觉可参考模板暖色卡片，但遵循本仓库现有 token，不引入成长条。
