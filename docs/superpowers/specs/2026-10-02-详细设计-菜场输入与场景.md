## 1. 范围

- 确认页：时令主列表默认全选（有上限）；四季常见默认计入但不占主列表；调味不出现  
- 当次场景：饭菜类型、人数、搭配、忌口（非日常）、想做几顿、节日  
- 输出：`ingredientIds[]` + `scene` → 交给推荐  
- **不含**：美团抓取实装、拍照识菜（入口**不展示**；事件名可预留）

## 2. 食材列表

### 2.1 拉取 `ingredients.list`

入参：`city?`（缺省用 `users.city`）  

逻辑：

1. 查 `ingredients`：`cities` 为空（全国）或包含入参城市  
2. 若该城专属条数过少 → **fallback** 仅全国项，返回标记 `fallback: "national"`  
3. 分层返回（字段见主数据 §2.2）：

```ts
{
  seasonal: Ingredient[],     // onConfirmPage 的时令主料，已按类截断
  yearRound: Ingredient[],    // 四季常见主料
  fallback?: "national"
}
```

分类：`leaf` 叶菜 · `root` 根茎 · `fruit_veg` 茄果 · `bean` 豆类 · `mushroom` 菌菇 · `meat` 肉类 · `seafood` 水产 · `egg_dairy` 蛋奶 · `tofu` 豆制品  

`kind=seasoning` **不返回**（或单独忽略），不进确认页、不进已选主料。

时令主列表上限：每类约 6～10、合计约 40～70，按 `sort` 截。长尾不在 `seasonal` 里。

### 2.2 前端交互

- **主列表**：只渲染 `seasonal`，分类可折叠，进入时**默认全选**这些时令项  
- 全选 / 清空：只作用于主列表，不动四季常见  
- **四季常见**：默认全部计入已选；主列表不铺开。一条折叠摘要「四季常见 · 已计入 N 样」，点开可取消今天没有的。若家庭忌口含某大类（如 `pork`），对应食材**默认不计入**（仍可在折叠区看到并手动勾回，但不推荐这样做宗教忌口）  
- **自定义补菜**：用户输入名称 → 本地临时 id（`custom_xxx`）或调用 `ingredients.addCustom`（可仅本地）  
- **语音补菜**：点语音 → 录音 → 转写 → 抽出菜名给用户确认后并入 `selected`（可匹配库内 id，匹配不到当手补）。埋点 `ingredient_voice_start` / `ingredient_voice_result`（成功带 `count`）  
- **拍照识菜**：**不展示**入口；上线后再做。事件名可预留 `ingredient_photo_*`，当前不打、不提示「暂未开放」

### 2.3 确认输出

`selected` = 主列表勾选 ∪ 未取消的四季常见 ∪ 手补。**必须含**未展开取消的四季项，否则家常菜会因缺鸡蛋/猪肉而配不出。

```ts
{
  selected: [{ id, name, category?, custom?: boolean, source?: "seasonal"|"year_round"|"manual" }],
  methodsUsed: ("default_list"|"manual"|"photo"|"voice")[]
}
```

埋点见埋点详细设计：`ingredient_*`、`ingredient_confirm`。

## 3. 当次场景 `scene`

```ts
{
  mealType: "daily" | "family_party" | "friends_party" | "holiday_party",
  holidayId?: string,          // mealType=holiday_party；对应 holidays.items[].id
  holidayDate?: string,        // 选中的该年公历 YYYY-MM-DD（快照，避免跨年歧义）
  peopleCount: number | null,  // 非日常初始可为 null
  combo: { meat, veg, soup } | null,
  partyAvoids?: string[],      // 仅非日常；当次硬排除
  mealSlots: MealSlot[],       // 想做几顿
  persistComboToDefault?: boolean  // 日常且用户确认写回时由推荐页带
}

type MealSlot = {
  meal: "lunch" | "dinner" | "other",  // 保留午/晚；非日常用 other
  label?: string                       // 展示用，如「晚饭①」；不表示日历日
}
```

不设 `dayOffset`：推荐只按顿数出几套菜，**哪一天吃由用户自己安排**。

### 3.0 完整示例（当次：多食材 + 一 scene）

关系：一次提交 = **多条选中食材** + **一份 scene**（含多顿 `mealSlots`）。交给推荐后写入 `recommendations`。

```jsonc
{
  "uid": "u_demo001",                          // 当前用户
  "selected": [                                // 今日可选食材（多条）
    {
      "id": "ing_egg",                         // 食材 id
      "name": "鸡蛋",                          // 名称
      "category": "egg_dairy",                 // 分类
      "custom": false,
      "source": "year_round"                   // 四季常见：页面未铺开但已计入
    },
    { "id": "ing_tomato", "name": "番茄", "category": "fruit_veg", "custom": false, "source": "year_round" },
    { "id": "ing_pork", "name": "猪肉", "category": "meat", "custom": false, "source": "year_round" },
    { "id": "ing_potato", "name": "土豆", "category": "root", "custom": false, "source": "year_round" },
    { "id": "ing_green_veg", "name": "青菜", "category": "leaf", "custom": false, "source": "seasonal" },
    { "id": "custom_tofu", "name": "豆腐", "category": "tofu", "custom": true, "source": "manual" }
  ],
  "methodsUsed": ["default_list", "manual"],   // 使用过的输入方式
  "scene": {                                   // 当次场景（一份）
    "mealType": "daily",                       // 饭菜类型：日常
    "holidayId": null,                         // 节日代号（非节日为空）
    "holidayDate": null,                       // 该年公历日期快照
    "peopleCount": 3,                          // 当次人数
    "combo": {                                 // 当次荤素汤
      "meat": 1,
      "veg": 1,
      "soup": 1
    },
    "partyAvoids": null,                       // 非日常忌口；日常为 null
    "mealSlots": [                             // 想做几顿（不绑日历日）
      { "meal": "dinner", "label": "晚饭①" },
      { "meal": "dinner", "label": "晚饭②" }
    ],
    "persistComboToDefault": false             // 是否写回画像默认搭配
  }
}
```

读法：提交里含主列表时令菜 + 未取消的四季常见 + 手补；推荐与清单都认这一份 `selected`。各顿共用同一个 `combo`。

### 3.1 日常 vs 非日常

| | 日常 `daily` | 非日常 |
|--|--------------|--------|
| 人数 | 预填 `defaultPeopleCount`，可改 | 不预填，必填后继续 |
| 搭配 | 预填 `defaultCombo`，可改 | 不预填；`peopleCount` 变化触发推荐搭配 |
| 几顿 | 可快捷选一顿/多顿晚饭等，**区分午/晚**；不指定用在哪一天 | **默认 1 顿**，可改顿数；**不区分午/晚**（`meal: "other"`） |
| 忌口 | 用画像，不在本页选 | 本页选 `partyAvoids`（当次硬排除） |
| 写回默认 | 推荐采纳/补选搭配后可写回人数+搭配 | **禁止**写回 |

### 3.2 按人数推荐搭配 `suggestComboByPeople(n)`

| 人数 n | 推荐 combo (meat-veg-soup) |
|--------|----------------------------|
| 1 | 1-1-0 |
| 2 | 1-1-1 |
| 3 | 1-2-1 |
| 4–6 | 2-2-1 |
| ≥7 | 2-3-1 |

用户可改；改后打 `scene_combo_change`，系统建议打 `scene_combo_suggest`。

### 3.3 节日

- 读 `holidays` 当年（必要时下一年）的 `items`，筛「今天起未来 N 天」（N=30）  
- `holiday_party` 必选一条：提交 `holidayId`（`items[].id`）+ `holidayDate`（该条 `date`）  
- 界面展示 `nameZh`；`nameEn` 可不用  
- 自定义节日名后置  

---

### 3.4 想做几顿

- 至少 1 个 slot；上限建议 ≤7 顿，防止推荐爆炸  
- **不绑定日历日**：只表示要出几顿菜、午还是晚；用户自行决定哪天吃哪顿  
- **日常**：UI 快捷如「一顿晚饭」「两顿晚饭」，映射为 `mealSlots[]`；**午/晚用 `meal` 区分**。各顿共用当次一个 `combo`。详见用户画像详细设计 §2.5。  
- **非日常**：默认 `[{ meal: "other", label: "本场" }]`（1 顿）。用户只调顿数，不选午饭/晚饭；多顿为 `other` + 序号 label（第 1 顿、第 2 顿）。

## 4. 页面结构建议

同一「输入流程」内两段（可同页折叠或上下分区）：

1. 食材确认  
2. 场景设置  

进入本页之前：首页 → 进场确认弹层（见饮食记录详细设计）。

提交：校验食材非空、场景完整 → `recommend.create`。
