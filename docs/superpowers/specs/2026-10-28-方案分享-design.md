# 方案分享（点对点）

日期：2026-10-28  
状态：已实现（2026-10-28）  
实现计划：[`../plans/2026-10-28-方案分享.md`](../plans/2026-10-28-方案分享.md)  
需求摘要：`docs/superpowers/specs/2026-10-24-方案分享-requirements.md`  
概述：`doc/需求概述.md` 模块 3「方案分享」

## 背景与目标

- 去菜场的人不一定是做饭的人；买菜方确认「能买到 + 能做」后，把方案甩给做饭的人看清**买哪些菜、做什么菜**。  
- 被分享者须能在小程序内**反复查看**（保存进「已选方案」），不能只依赖微信聊天卡片。  
- **不是**社区广场 / 排行榜。

## 决策摘要

| 项 | 决定 |
|----|------|
| 技术路径 | 分享时云端写入**只读快照**；卡片带 `shareId`；不跟分享人后续改勾选/换方案 |
| 打开后 | 只读预览（菜名 + 用料）；点「保存到我的」才进回访 |
| 入口 | ① 推荐页**每张方案卡**上的分享；② 购买食材（清单）页；③「我的 → 已选方案」里**自己产出**的条目 |
| 内容 | 菜名 + 用料清单；**无**步骤；**无**「已买」勾选 |
| 用料范围 | 始终**完整**清单；忽略分享人在食材页的已买勾选 |
| 预览与登录 | 预览不强制登录；点「保存」时未登录再走登录 |
| 回访落点 | 并入现有「已选方案」，标签区分「别人分享的」；**不**单独「收到的方案」列表 |
| 收到的条目 | 点开 = 与落地预览同款只读；**不可再分享**；无「去买菜」、无已吃点选 |
| 二次保存 | 同一用户同一 `shareId` **幂等**（不重复占列表） |

## 1. 用户流程

### 1.1 发起分享

```
推荐页：点某方案卡「分享」
  → 服务端按该 plan 生成快照（若尚无）→ 返回 shareId
  → onShareAppMessage 路径带 shareId

食材页：点「分享」
  → 对应当前已采纳 plan 生成/复用快照（完整用料，不含 bought 状态）
  → 同上调起分享

已选方案：仅 source=自产 的条目显示分享
  → 复用或生成该次采纳对应快照
  → source=收到的 条目：无分享按钮
```

### 1.2 被分享者

```
点微信卡片
  → 打开落地页（shareId）只读：菜名列表 + 分类用料
  → 未保存也可看全；退出后仍可用同一卡片再进
  → 「保存到我的」→ 需登录 → 写入「已选方案」（标签：分享）
  → 之后从「我的 → 已选方案」点开 = 同款只读页（可不再显示保存按钮，或显示「已保存」）
```

## 2. 界面要点

### 2.1 发起侧

- **推荐页**：分享控件在**方案卡片上**（每卡独立）；点哪张分享哪张。  
- **食材页**：页级分享入口（与「去买菜」进入的当前方案绑定）。  
- **已选方案**：自产条目有分享；收到的条目无。  
- 卡片文案 / 封面图：实现时再定（可用方案菜名拼接作 title；封面可用品牌默认图）。**回访机制优先于花活样式。**

### 2.2 落地 / 只读详情页

- 标题区：可显示「来自好友的方案」或分享人昵称（有则展示，无则省略）。  
- **菜名**：列出该方案全部菜名（多顿则按顿分组，若快照含 meal 结构）。  
- **用料**：按分类展示名称列表；**不可勾选**。  
- 底栏：「保存到我的」（未保存）；已保存则弱文案「已保存到已选方案」或隐藏按钮。  
- **不做**：已买勾选、去买菜、换一批、步骤展开。

### 2.3 已选方案列表

- 收到的条目与自产混排（仍按时间倒序）；卡片角标或副文案：**分享**（或「来自好友」）。  
- 点开 → 只读详情（§2.2），无已吃勾选、无分享。  
- 自产条目：保持现有已吃点选 + 可分享。

## 3. 数据

### 3.1 快照集合（建议 `plan_shares`）

```ts
type PlanShareSnapshot = {
  shareId: string
  createdAt: string
  createdBy: string           // 分享人 uid
  // 溯源（可选，便于排查；打开逻辑不依赖其仍有效）
  sourceRequestId?: string
  sourcePlanIndex?: number
  dishes: { name: string; mealLabel?: string }[]
  ingredients: { category: string; name: string; displayName?: string }[]
  // 不含：bought、步骤、分享人勾选态
}
```

- 创建时机：用户点分享且需要调起转发时（或首次分享该 plan 时）；同一 `(requestId, planIndex)` 可复用已有 `shareId`，避免重复文档。  
- **不可变**：创建后不因分享人改推荐/清单而更新。  
- 保留策略：实现时定（建议至少保留较长时间；过期打开提示「分享已失效」）。

### 3.2 接收者「已选」挂载

两种等价实现（实现计划二选一，产品表现一致）：

**推荐**：在接收者侧写一条「虚拟已选」记录，例如集合 `received_plans` 或扩 `recommendations` 形态：

```ts
{
  ownerUid: string
  shareId: string
  source: "shared"            // 与自产 accepted 区分
  savedAt: string
  // 列表展示用冗余：菜名摘要、分享人昵称可选
}
```

列表 API（`listAccepted` 或并行接口）合并自产 `accepted` + `source=shared`，按时间倒序；收到的项**不**走 `plan_ate`。

幂等：`(ownerUid, shareId)` 唯一；重复保存返回已有记录。

## 4. 接口与微信（示意）

| 能力 | 说明 |
|------|------|
| `share.create` | 入参：requestId+planIndex 或已选条目 id；校验归属为当前用户自产；返回 `{ shareId }` |
| `share.get` | 入参 shareId；返回快照（预览，可匿名读或仅需登录态弱校验——**建议可读可不登录**，防刷另议） |
| `share.save` | 需登录；幂等写入收到的已选 |
| `onShareAppMessage` | `path: /pages/sharedPlan/index?shareId=...`（路径名实现时定） |

分享人必须登录才能 `create`。

## 5. 非目标

- 公开 Feed、点赞、排行榜  
- 步骤 / 做法正文  
- 落地或收到详情上的已买勾选、「去买菜」、已吃点选  
- 收到的方案再分享  
- 从分享发起推荐引擎 / 换一批  
- 语音、拍照相关入口  

## 6. 埋点（建议）

- `plan_share_create`：`{ entry: "recommend" | "shopping" | "accepted" }`  
- `plan_share_open`：`{ shareId }`  
- `plan_share_save`：`{ shareId }`  
- 列表点击收到的条目：`accepted_open_shared`

## 7. 成功标准

- 三处自产入口均可调起分享，卡片打开后可见完整菜名与用料。  
- 未保存可看全；保存后出现在「已选方案」且带分享标识；再次打开不依赖聊天记录仍在。  
- 分享人改清单 / 换方案不影响已发出的快照。  
- 收到的条目无分享、无已吃勾选；重复保存不产生重复行。
