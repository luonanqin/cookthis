# 用户序号与首次仪式

日期：2026-11-16  
状态：已实现  
实现计划：[`../plans/2026-11-16-用户序号与首次仪式.md`](../plans/2026-11-16-用户序号与首次仪式.md)  
关联：[`2026-10-02-详细设计-账号与身份.md`](./2026-10-02-详细设计-账号与身份.md) §5  

## 目标

- 让用户知道自己是「第 N 位大厨」，有归属感。  
- **序号不写进公开昵称**，降低从展示名推断用户量、可枚举的风险。  
- 首次进入「我的」用轻蒙层 + 数字滚动，做一次仪式。

## 决策摘要

| 项 | 决定 |
|----|------|
| 默认昵称 | 仍为 `大厨` + uid 派生短码（现有）；**不含**流水号 |
| 本人可见 | 昵称下小字：`第 N 位大厨` |
| 对外 | 分享卡等只出 nickname，不带 N |
| 首次仪式 | **轻蒙层** + 数字滚到 N；文案「第 N 位大厨」 |
| 播放次数 | 每账号一次（服务端标记）；已看过则直接常态小字 |

## 1. 数据

### `users` 新字段

```ts
userNo: number                    // 注册时原子分配，从 1 起；稳定不变
userNoRevealSeenAt?: string      // ISO；首次仪式播完后写入；有值 = 不再播
```

- **分配**：`auth.login` 创建新用户时，用云库计数器 / 事务取下一个 `userNo`（实现时选微信云开发可用的原子方案；禁止「先 max+1 无锁」）。  
- **老用户回填**：按 `createdAt` 升序、同秒按 `uid` 稳定排序，赋连续 `userNo`；已有值不改。回填脚本一次性跑。  
- **API**：`auth.login`、`profile.get` 对**当前登录用户**返回 `userNo`；`userNoRevealSeenAt` 可返回布尔 `userNoRevealSeen` 或原字段。  
- **禁止**：列表接口、分享冗余字段、他人资料中返回 `userNo`。

昵称生成逻辑不变；用户改昵称不影响 `userNo`。

## 2. 「我的」常态 UI

`profile-row` 结构：

```
[头像]  大厨D4JE
        第 128 位大厨          ← 小字、次要色；仅本人页
```

- `userNo` 未就绪（极端）时：第二行不展示或暂不显示，不展示错误序号。  
- 不展示 openid / uid / 内部计数器名。

## 3. 首次仪式

### 触发

- 进入 `pages/mine`，且已有合法 `userNo`，且 `userNoRevealSeen` 为假。  
- 播完（或用户点「知道了」关闭）→ 调云函数写 `userNoRevealSeenAt`，本地也可记一份防闪断重播。  
- 系统「减弱动效」开启：蒙层仍出，数字**直接定格**最终 N，不滚动。

### 表现（轻蒙层）

- 半透明遮罩，居中卡片（非全屏强打断；点遮罩或主按钮可关）。  
- 主文案：`欢迎加入`（或等价短句）+ 大号滚动数字区。  
- 数字：从较低起点（建议 `max(0, N - span)`，`span` 约 30～80，N 很小时从 0）在 **1.2～1.8s** 内 ease-out 滚到 N。  
- 到位后展示完整句：**第 N 位大厨**；按钮「开始用」/「知道了」。  
- 关闭后蒙层消失，头图下小字已是最终文案（可与蒙层同步写上，避免关完才跳变）。

### 非目标

- 不在首页 / 引导末步强制插播（避免挡 onboarding）；若产品日后要改触发页，另议。  
- 不做排行榜、不做「超越 xx% 用户」。  
- 不把滚动过程录成必须看完才能用「我的」其它区块以外的全局锁——蒙层打开时本页其它操作自然被挡住即可。

## 4. 安全与隐私

- 公开表面（昵称字符串、分享）无线索指向 `userNo`。  
- 拖库若拿到整表仍可见 `userNo` 列：属库权限问题；本设计只降低**展示层与公开 API**泄露规模。敏感字段（手机号等）策略不变。  
- 计数器集合 / 文档需与业务同级权限，防未登录乱加序号。

## 5. 验收

- 新用户昵称为 `大厨xxxx` 形态，不含数字序号。  
- 首次进「我的」见轻蒙层，数字滚到与 `userNo` 一致；再进不再播。  
- 「我的」头图下常驻「第 N 位大厨」。  
- 分享出的方案卡等无 N。  
- 老用户回填后每人有唯一 `userNo`，与创建先后一致。

### 手测清单

1. 新号登录 → nickname 无流水号；`userNo` 递增。  
2. 首次「我的」蒙层滚到 N → 知道了 → 小字常驻；再进无蒙层。  
3. 分享卡无 N。  
4. 回填后老用户有唯一号、再进仪式仅未见过的播。  
5. `userNo` 缺失时不显示错号。
