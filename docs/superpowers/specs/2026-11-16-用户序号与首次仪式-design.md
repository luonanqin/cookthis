# 用户序号与首启仪式（含使用步骤）

日期：2026-11-16  
状态：已实现（首页①→② 连贯首启；「我的」仅小字）  
实现计划：[`../plans/2026-11-16-用户序号与首次仪式.md`](../plans/2026-11-16-用户序号与首次仪式.md)  
关联：[`2026-10-02-详细设计-账号与身份.md`](./2026-10-02-详细设计-账号与身份.md) §5  

## 目标

- 让用户知道自己是「第 N 位大厨」，有归属感。  
- **序号不写进公开昵称**，降低从展示名推断用户量、可枚举的风险。  
- **首次进入小程序**用一段连贯动效：序号仪式 → 自动过渡到使用步骤 → 可去偏好引导。

## 决策摘要

| 项 | 决定 |
|----|------|
| 默认昵称 | 仍为 `大厨` + uid 派生短码；**不含**流水号 |
| 本人可见 | 「我的」昵称下小字：`第 N 位大厨`（常驻） |
| 对外 | 分享卡等只出 nickname，不带 N |
| 触发 | **首次进入小程序**（首页）；每账号一次 |
| 动效 | **同一蒙层**：① 数字滚到 N → ① 上移 → ② 使用步骤落下；非关①再开② |
| ② 文案 | 三步（见 §3，已定） |
| ② CTA | 左「先逛逛」→ 关层留首页；右「完善偏好」→ 完整引导 |
| 标记 | 整段结束写 `userNoRevealSeenAt` |
| 埋点 | `user_no_reveal_show` → `user_no_reveal_steps` → `user_no_reveal_ack`（`via`: `browse` \| `onboarding`） |

## 1. 数据

```ts
userNo: number
userNoRevealSeenAt?: string   // 首启整段结束后写入
```

- 新用户：`auth.login` 原子分配 `userNo`。  
- 老用户：按 `createdAt`/`uid` 回填。  
- `login` / `profile.get` 仅回本人；ack 写标记。  
- 禁止列表/分享返回 `userNo`。

## 2. 「我的」常态

```
[头像]  大厨D4JE
        第 128 位大厨
```

无蒙层。缺 `userNo` 则不展示第二行。

## 3. 首启连贯动效

### 触发

- 首页在 `login` 已有合法 `userNo` 且未见过首启时展示。  
- 优先于进场确认 / 菜场规模（勿叠弹）。  
- 减弱动效：① 定格 N 后短切②，仍同一蒙层。

### ① 序号

- 欢迎短句 + 大号数字；约 1.2～1.8s 滚到 N；定格「第 N 位大厨」约 0.3～0.6s。  
- **无独立关闭①**；自动进入过渡。

### 过渡

- ① 上移/缩小；② 落入；约 0.4～0.6s；禁止闪断换层。

### ② 使用步骤（文案已定 · 三步）

- **主文（标题）：** 使用说明（左对齐；无副文小字）  
- **三步（序号圆标 + 左对齐标题/说明）：**  
  1. **确认今日可选食材** — 看看菜场时令与常见菜，可补充  
  2. **生成完整菜品搭配** — 结合口味和近期食用，不喜可换  
  3. **按清单采购回家做** — 明确购买不费脑  
- 横向并列：左 **先逛逛** → ack + 关层；右 **完善偏好** → ack + 进 onboarding  

- 点遮罩：**不关闭**

## 4. 安全

公开表面不带 N；计数器与 ack 需登录态。

## 5. 验收

- 昵称无流水号；「我的」有小字、无蒙层。  
- 首次进小程序：①→② 连贯；两 CTA 行为正确；再进不播。  
- 不与进场确认/规模叠弹；分享无 N。
