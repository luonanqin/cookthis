## 1. 目标与边界

**目标**

- 「先逛逛」/ 跳过完整引导后，**不挡**确认食材 → 出推荐。  
- 全屏轻量补全（§2.2）仍**一生（每用户）最多认真打扰一次**。  
- 缺口未消时，在**推荐页顶栏**与**「我的」**展示**不可关闭**的弱提醒，导回补全。  
- 推荐页快捷补充保存后：**必须重跑推荐并刷新页上方案**。

**非目标**

- 不因画像不全禁止 `recommend.create`。  
- 不做「关闭后 N 天再出现」的可关提醒。  
- 不在进场确认 / 菜场确认页再叠强制问卷。  
- 不改菜系 prefer/avoid 推荐规则（仅「已表态」判定）。

---

## 2. 与现有字段的独立性

| 字段 | 含义 | 与常驻提醒 |
|------|------|------------|
| `onboardingDone` | 完整引导完成或「先逛逛/暂时跳过」后标 true（现实现：跳过也会写 true） | **独立**。提醒看缺口，不看此字段。 |
| `profileLitePromptedAt` / `profileLiteSkipped` | 全屏轻量层已处理（保存或跳过） | **独立**。跳过轻量层 **不算**忌口已表态；仍可出推荐页顶栏。 |
| `familyAvoids` | 忌口词表 | 有元素 → 忌口缺口消。 |
| **新增** `familyAvoidsNone` | 用户明确「我家无忌口」 | `true` → 忌口缺口消（即使 `familyAvoids=[]`）。 |
| **新增** `familyAvoidsConfirmedAt` | 忌口表态时刻（有忌口或点无忌口） | 审计/埋点用；判定以 `length>0` 或 `familyAvoidsNone` 为准。 |
| **新增** `cuisinePrefsConfirmedAt` | 菜系已表态时刻 | 有 prefer/avoid **或** 点过「暂无偏好」后写入；有此字段（或任一 prefer/avoid）→ 菜系缺口消。 |

**原则**：频控字段只管「全屏还弹不弹」；表态字段管「常驻消不消」。二者不要混用。

## 3. 数据模型（`users` 增量）

```ts
familyAvoidsNone?: boolean           // 默认 false/缺省
familyAvoidsConfirmedAt?: Date       // 可选
cuisinePrefsConfirmedAt?: Date       // 可选；「暂无偏好」必写；首次保存任一 prefer/avoid 时也写
```

**写入口（`profile` 云函数）**

| action | 行为 |
|--------|------|
| `saveProfileLite` | 保持现语义写忌口/品类 + `profileLitePromptedAt`。若 `familyAvoids.length>0` → `familyAvoidsNone=false`，写 `familyAvoidsConfirmedAt`。若保存时空数组 → **不**置 `familyAvoidsNone`（与「跳过」一样，忌口仍算未表态）。 |
| `skipProfileLite` | 仅频控；**不**动 `familyAvoidsNone` / ConfirmedAt。 |
| `updateFamily` | 若传入 `familyAvoids` 且 length>0 → 清 `familyAvoidsNone`，写 ConfirmedAt；若 `familyAvoidsNone===true` → 强制 `familyAvoids=[]`，写 ConfirmedAt；若传入菜系且含 prefer/avoid → 写 `cuisinePrefsConfirmedAt`；若 `cuisinePrefsNoPreference===true`（见下）→ 写 ConfirmedAt，prefs 可保持全空/neutral。 |
| **新增** `confirmFamilyAvoidsNone` | 专用短 action：`familyAvoidsNone=true`，`familyAvoids=[]`，`familyAvoidsConfirmedAt=now`。供「我的」/快捷层「我家无忌口」。 |
| **新增** `confirmCuisineNoPreference` | `cuisinePrefsConfirmedAt=now`；不强制改 prefs（可保持 `{}`）。供「暂无偏好 / 全部一般」。 |

`profile.get` / `auth.login` / 客户端 `session` 缓存均带回上述新字段，便于缺口判定。

## 4. 缺口判定（纯函数）

建议文件：`cloudfunctions/_shared/profileGaps.js` + `miniprogram/utils/profileGaps.js`（vendored）。

```ts
type ProfileGapsInput = {
  familyAvoids?: string[]
  familyAvoidsNone?: boolean
  membersCount: number          // members.length；客户端用缓存/get 结果
  city?: string | null
  cuisinePrefs?: Record<string, 'prefer'|'neutral'|'avoid'>
  cuisinePrefsConfirmedAt?: string | Date | null
}

type ProfileGapId = 'family_avoids' | 'members' | 'city' | 'cuisine'

type ProfileGaps = {
  gaps: ProfileGapId[]          // 有序
  familyAvoidsOpen: boolean
  membersOpen: boolean
  cityOpen: boolean
  cuisineOpen: boolean
  anyOpen: boolean              // gaps.length > 0
  recommendBanner: boolean      // === familyAvoidsOpen（推荐顶栏只盯忌口表态）
}
```

**判定规则**

| gap | open 当 |
|-----|---------|
| `family_avoids` | `!(familyAvoids.length>0 \|\| familyAvoidsNone===true)` |
| `members` | `membersCount < 1` |
| `city` | `!city`（空串/null） |
| `cuisine` | 无任一 `prefer`/`avoid`，**且**无 `cuisinePrefsConfirmedAt` |

**推荐页顶栏**：`recommendBanner = familyAvoidsOpen`。  
（产品：顶栏快捷补充与轻量层同款，只收忌口+爱吃；成员/城市/菜系放到「我的」多项提醒。顶栏不因仅缺城市而出现。）

**「我的」整块**：`anyOpen`；列表逐项对应四个 gap。

单测覆盖：跳过轻量后仍 `familyAvoidsOpen`；`familyAvoidsNone` 后关闭；仅有 ConfirmedAt 无 prefer 时关闭菜系 gap 等。

## 5. UI / 交互

### 5.1 推荐页顶栏

- 位置：方案列表上方（hint 附近），小字弱样式。  
- 文案取向：`补一下家庭忌口，少推不能吃的`（可微调）；**无关闭按钮**。  
- 展示条件：`profileGaps(...).recommendBanner === true`（进页 / onShow / 快捷保存后重算）。  
- 点击 → 打开**半屏/全屏 sheet**，表单复用确认页轻量补全（忌口短词表 + 可选火锅/面食）；额外提供文案链或次按钮：**「我家无忌口」** → `confirmFamilyAvoidsNone`。  
- 主按钮「保存」→ `saveProfileLite` 或 `updateFamily`（同源 sanitize）→ 刷新本地 user → **立刻重跑推荐**（§6）→ 重算 gaps，缺口消则顶栏消失。  
- 取消关闭 sheet **不**消顶栏。

### 5.2 「我的」提醒块

- 位置：列表顶部（头像/昵称下、各 section 前）。  
- 不可关闭；按 `gaps[]` 渲染 1～4 行，例如：  
  - 忌口未表态 → 点进忌口区（可滚到家庭忌口 +「我家无忌口」）  
  - 无成员 → 打开添加家人  
  - 无城市 → 滚到城市 picker  
  - 菜系未表态 → 滚到菜系 +「暂无偏好」  
- 某 gap 关闭后该项消失；`anyOpen===false` 整块不渲染。

### 5.3 组件复用

- 抽出 `components/profile-lite-form`（或 `utils` + 两处 wxml 片段）：忌口 chips、「更多」、爱吃 chips、无忌口入口。  
- 确认页全屏轻量层、推荐页快捷 sheet **共用同一套**，避免两套词表漂移。

## 6. 推荐页保存后刷新方案

**输入**：当前页已有 `requestId` / storage `cookthis_last_recommend` 与 `cookthis_last_selected`（含 `selected` + `scene`）。

**流程**

1. 快捷保存成功，本地 `ensureLogin` / 更新 `cookthis_user`。  
2. `setData({ busy: true })`（与换一批同级 busy，防连点）。  
3. `recommend.create`（**新建**会话，与从确认页进入一致；不要只 `swap`——忌口变化属硬过滤，应整次重算）。入参：storage 中的 `selected` + `scene`（scene 不变）。  
4. 成功且 `plans.length>0`：覆盖 `cookthis_last_recommend`，`applySnap`，重置 engage 计时；清空该 request 旧 shopping checks（若 requestId 变了则自然隔离）。  
5. 成功但空方案：与确认页一致——展示空态/「食材不够出菜了」类提示，**留在推荐页**（或允许返回改食材）；顶栏按新 gaps 更新（忌口已表态则顶栏可消失，即使空方案）。  
6. 失败：toast，保留旧方案与顶栏。

**注意**：`create` 会生成新 `requestId`；进场确认锚点、清单 checks 按新 id；可接受。

## 9. 页面逻辑摘要

```
确认页日常提交
  ├─ shouldShowProfileLite? → 全屏轻量（频控）
  │     ├─ 保存 → create
  │     └─ 跳过 → create（忌口仍可能未表态）
  └─ 否 → create

推荐页 onShow
  └─ gaps.recommendBanner → 顶栏
        └─ 快捷保存 / 无忌口
              └─ create 刷新方案 + 重算顶栏

我的 onShow
  └─ gaps.anyOpen → 提醒列表（点进编辑 / 无忌口 / 暂无偏好）
```
