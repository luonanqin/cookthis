# 手补食材：拼音/别名联想与规范名入库

日期：2026-11-17  
状态：已定稿（待实现）  
实现计划：[`../plans/2026-11-17-手补食材联想与规范名.md`](../plans/2026-11-17-手补食材联想与规范名.md)  
关联：[`2026-10-02-详细设计-菜场输入与场景.md`](./2026-10-02-详细设计-菜场输入与场景.md) §2.2；别名 [`2026-10-18-城市货架与全量食材别名-design.md`](./2026-10-18-城市货架与全量食材别名-design.md) / catalog 别名表  

## 背景

确认页「补菜」现为自由文本写入 `manuals`，`name` 原样进 `selected`。推荐靠主料精确命中 + `aliasIndex` 扩展；**库外生词 / 错别字无法解锁菜谱**，用户以为补了却不出菜。另有用户**会读不会写**，需要拼音检索。

## 决策摘要

| 项 | 决定 |
|----|------|
| 检索 | 汉字前缀/包含 + **拼音全拼 / 首字母**，词表 = 规范名 ∪ 别名 |
| 点选候选 | **匹配名写入规范名**（`canonical`）；列表可显示用户点中的文案 |
| 自由文本未命中 | 仍可添加，但标「暂无法匹配菜谱」；进推荐不挡，但该名通常无贡献 |
| 持久 | 仍仅本趟确认页有效（回首页重进清空）；换规模 `preserveSelection` 保留手补 |
| 不入库 | 不把拼音串、未登记生词写入别名表（运营另补高频异名） |

## 1. 目标

- 降低「叫法不同 / 不会写字」导致的手补无效。  
- 推荐侧收到的手补名尽量落在现有别名图上，与勾选时令/四季一致。  
- 不改变「本趟手补、重进清空」的产品策略。

## 2. 数据形态

手补项（确认页 `manuals[]` / 提交 `selected` 中 `source: "manual"`）：

```ts
{
  id: string              // 如 custom_<ts> 或 canon 派生，去重用
  name: string            // **提交给推荐的匹配名 = 规范名**（命中时）；未命中则为用户原文
  displayName?: string    // 可选；点选时用户看到的提示文案（别名或规范名）
  canonical?: string      // 命中时 = name；未命中可省略
  matched: boolean        // 是否映射到库内食材/别名
  source: "manual"
}
```

- UI 芯片优先展示 `displayName || name`。  
- `ingredient_confirm` / `recommend.create` 的 `selected[].name`：**一律用 `name`（匹配名）**。  
- 已在主列表或四季勾选的同一规范名：手补时提示「已在列表中」或自动勾选，**不重复加 manuals**。

## 3. 词表与检索

### 3.1 词表来源

客户端可用（与确认页同城货架一致更佳）：

- 当前规模下时令 + 四季的展示名；以及  
- 全量/别名索引中的 **规范名 + 每条别名**（别名指向 canonical）。

实现可选：

- **A（推荐 MVP）**：登录后已有 `aliases` / catalog 缓存则建本地检索索引（规范名、别名、预计算拼音）。  
- **B**：云函数 `ingredients.suggest`（query + city/scale）——词表大或包体敏感时再用。

### 3.2 匹配规则（候选排序）

对输入 `q`（去空白；小写拼音）：

1. 规范名/别名 **前缀**命中（汉字）  
2. 规范名/别名 **包含**命中  
3. 规范名/别名的 **拼音全拼前缀**（如 `xihong` → 西红柿/番茄）  
4. **拼音首字母前缀**（如 `xh` / `xhs`）  

同一 canonical 多别名命中 → **合并为一条候选**，展示可用「规范名」或「命中的别名（规范名）」；选中后 `name = canonical`。  
上限：下拉约 **8～12** 条；无结果显示「无匹配，可仍添加（可能无法出菜）」。

拼音库：小程序侧轻量方案（如精简拼音表或现成小依赖）；**不**在云函数推荐热路径做拼音。

## 4. UI（确认页补菜区）

```
[+ 补菜]
[ 输入框：菜名或拼音          ] [添加]
  ├ 西红柿（番茄）     ← 候选
  ├ 番茄
  └ …
已补：西红柿 ×  猪蹄 ×（无法匹配）
```

- 输入变化（防抖 ~150–300ms）刷新候选；点候选 → 写入手补（规范名）并清空输入。  
- 点「添加」：  
  - 若当前高亮/唯一强命中候选 → 同点选；  
  - 若无命中 → `matched: false`，原文入库，芯片角标或旁注「暂无法匹配菜谱」。  
- 不强制用户必须选候选（避免库不全时卡死）。

## 5. 与推荐 / 别名的关系

- 命中规范名的手补与勾选同一主料等价，走现有 `expandNames`。  
- **不必**为手补再写一条别名；异名靠点选时已落到 canonical。  
- 未命中原文：行为与今日自由文本相同（通常无菜），但用户有提示。  
- 清单展示：可用 `displayName || name`，避免只显示内部规范名造成「我补的不是这个」错觉（若规范名与点选文案不同）。

## 6. 埋点

| event | 时机 | props |
|-------|------|-------|
| `ingredient_manual_suggest_show` | 出现候选 | `queryLen`, `hitCount` |
| `ingredient_manual_add` | 添加成功 | `matched`, `via`: `pick` \| `free` |
| `ingredient_manual_unmatched` | `matched: false` 添加时 | `nameLen`（勿传原文以免脏数据进分析） |

跳过类不适用。可并入埋点详设 §4.3「未强制」中的手补细化。

## 7. 非目标

- 手补永久收藏 / 跨次保留  
- 服务端自动把生词写入 `aliases.json`  
- 大模型纠错  
- 语音/拍照补菜（仍后置）  
- 改推荐算法本身（只保证输入可匹配）

## 8. 验收

- 输入 `xihongshi` / `西红柿` / `番茄` 均可选到同一规范名；提交后能配上以该主料为 main 的菜。  
- 点选别名展示可用别名文案，但 `selected.name` 为规范名；与已勾选重复时不双计。  
- 无候选时仍可添加，有「无法匹配」提示。  
- 回首页再进确认页，手补仍清空；页内换规模手补仍保留。
