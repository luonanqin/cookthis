# 已选方案历史与点选已吃

日期：2026-10-09  
状态：已定稿  
范围：采纳后的方案回顾列表、列表内点选/取消已吃、与进场确认去重衔接。  
非范围：已吃记录列表的删除 UI（见饮食记录 §4.2，另做）；不改变「去买菜」不自动写已吃。

## 背景

- 「去买菜」已在 `recommendations` 写入 `accepted` / `acceptedAt` / `acceptedPlanIndex`，并保留完整 `scene` + `plans`，但无列表入口，用户事后无法回顾要做哪些菜。  
- 进场确认已有勾选记已吃；需要从「已选方案」侧也能按道标记，且与进场确认去重。

## 决策摘要

| 项 | 决定 |
|----|------|
| 存储 | 不新建集合；列表查 `recommendations` 且 `accepted: true` |
| 分页 | `acceptedAt` 倒序；每页 **7**；上拉再加载 7（cursor） |
| 记已吃 | 菜前勾选（样式同进场确认）；**点选即写、再点即删**；无单独提交按钮 |
| 日志粒度 | 历史点选：**一道菜一条** `meal_logs`（`source=plan_ate`） |
| 提示 | 列表顶**长期小字** + **首次**进页悬浮气泡（本地记已看过） |
| 进场确认 | 不展示已标记菜；滤完为空则不弹层（含 `plan_ate`） |

## 验收要点

- 点「去买菜」后，已选方案列表出现该条（时间、场景、方案菜）。  
- 列表初始 7 条，滑到底再请求下一批 7 条。  
- 点菜打勾后立即进近 7 日已吃；再点取消后不再参与排除。  
- 某锚点方案菜若已全部 `plan_ate`（或其它来源已记），进场确认不弹。  
- 首次进已选方案页见气泡；之后只留顶栏小字。
