权威正文：`doc/需求概述.md` 模块 5「产品建议反馈」

## 为什么做

用户比运营更清楚缺哪道菜、哪种食材、哪类功能；需要一条轻量通道收建议，支撑菜谱库与产品迭代；回复可见可增强粘性。

## 已定（调研结论）

| 项 | 说明 |
|----|------|
| 能力 | 类型 + 文字提交；列表见类型/内容/时间；运营可导出、可回复 |
| 通知 | 站内列表 +「我的」无数字红点；可选订阅消息 |
| 未读 | 未读优先、时间倒序；行右侧小红点；点行已读；不加粗、不展示状态文案 |
| 运营 | 控制台/脚本回复，无独立后台 |
| 与「不行」 | 推荐 reject ≠ 产品建议 |

## 非目标

- 公开社区、用户自助上传菜谱进池、Web 管理端
