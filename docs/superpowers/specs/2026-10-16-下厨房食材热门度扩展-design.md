# 下厨房食材热门度采集（Chrome 扩展）

日期：2026-10-16  
状态：已定稿  
相关：`data/ingredients-by-category.json`；站点 [mbdbj.xiachufang.com](https://mbdbj.xiachufang.com/)

## 背景

需要按食材在下厨房「做过」人数衡量通用/热门程度，供后续排序或权重用。在浏览器里用扩展驱动移动站页面操作，降低脚本风控；词表随扩展打包，改词表即更新扩展。

## 决策摘要

| 项 | 结论 |
|----|------|
| 形态 | Chrome MV3：popup + content script（仅 `mbdbj.xiachufang.com`） |
| 词表 | 打包自 `ingredients-by-category.json`（约 449 唯一食材，带中文分类名） |
| 有效结果页 | URL 含 `/category/` |
| 非食材 | URL 为 `/search/?keyword=` → 不算热度，记为非食材，回首页 |
| 排序 | 进 category 后点「最受欢迎」 |
| 热度 | 前 N≤9 条「x人做过」求和；不足 9 按实际条数 |
| 节奏 | 单步 1.5–3.5s；食材间约 **10s**（9–11s）；每完成 **5** 个再歇 12–22s；跳转落地后再停 1.5–3s |
| 反爬 | 统计后上下滑 → 随机点一条结果 → 浏览器返回 → 再点 `#goback` |
| 登录 | 不需要 |
| 阻碍 | 验证码等需人工 → **暂停**；一般卡住（超时/DOM 不到）→ **刷新当前页重试，最多 3 次**，仍失败则 **停止**（等同暂停，不跳下一项） |
| 断点 | 进度文件识别已完成，接着跑 |
| 进度落盘 | storage 每项更新；文件每 **5** 个食材下载覆盖一次；暂停/完成/手动导出立即下载 |
| 最终输出 | txt；分类用**中文名**；按 count 倒序；非食材置底 |

## 架构

```
popup（开始/暂停/继续/导出结果）
    ↕ chrome.runtime messaging
content script（在下厨房页内：搜、点、读、回首页）
    ↕
chrome.storage.local（运行态 + 结果缓存）
    → chrome.downloads 覆盖下载 progress / result 文件
```

- **不**用独立后台去开无头浏览器；用户先打开首页再点「开始」。
- Service worker 仅做消息转发与触发 `downloads`（若 popup 关闭仍要续跑，由 content 持有状态机，storage 持久化）。

## 页面操作约定

选择器以需求为准，实现时做成常量，失败则暂停并提示「选择器失效」。

| 步骤 | 动作 |
|------|------|
| 搜 | `#search-bar-form input`（或给定 xpath 对应节点）填入食材名 → Enter |
| 判页 | 等导航；`/category/` → 有效；`/search/?keyword=` → 非食材 |
| 排序 | 点「最受欢迎」：`#site-body section ul li:nth-child(2) a`（对应 xpath `…/li[2]/a`） |
| 读数 | `#add-more-container a[i] … span` 中「(\d+)人做过」，i=1…min(9,条数) |
| 回首页 | 反爬后点 `#goback`；非食材直接回首页 |

超时（建议单步 15–20s 无预期 DOM/URL）或步骤卡住：

1. 记一次失败；`location.reload()` 刷新**当前页**；
2. 按当前食材所处阶段尽量恢复（若在首页则重新搜索；若已在 category 则重新点「最受欢迎」再读数）；
3. 同一食材同一卡住点最多 **3** 次刷新重试；
4. 仍失败 → **停止**（`status=paused`，`pauseReason` 写明重试耗尽），不自动进下一个；等人点「继续」或排查。

若页面出现明确验证码/登录墙：不走刷新重试，直接暂停并提示人工处理。

## 进度与输出文件

均下载到浏览器默认「下载」目录；**同名覆盖**（`conflictAction: "overwrite"`）。

### `xiachufang-ingredient-progress.json`

每次完成一个食材（或暂停）写一次。

```json
{
  "version": 1,
  "updatedAt": "ISO-8601",
  "status": "running|paused|done",
  "pauseReason": null,
  "cursor": 12,
  "done": {
    "五花肉": {
      "category": "肉类",
      "isIngredient": true,
      "count": 12345,
      "detail": [1200, 1100]
    },
    "飞龙肉": {
      "category": "肉类",
      "isIngredient": false,
      "count": null
    }
  }
}
```

- 启动：读 storage；若用户导入/检测到同名进度逻辑，以 storage 为准；扩展更新后 storage 仍在则继续。
- 「根据进度文件识别」：开始时跳过 `done` 里已有键；可选「从下载的 progress.json 导入」按钮（MVP：以 storage 为主，每次自动下载便于备份/换机时手动导入）。

### `xiachufang-ingredient-popularity.txt`

每次进度更新可同步覆写一份「当前完整排序预览」；全部完成后再写最终版（同名即可）。

```text
# 下厨房食材热门度（前≤9条「做过」合计）
# 更新时间: ...
肉类	五花肉	12345
叶菜	白菜	8900
...
# 非食材
肉类	飞龙肉	-
```

- 列：`分类中文名`、`食材名`、`count`（非食材为 `-`），Tab 分隔。
- 排序：`isIngredient=true` 按 count 降序；其后非食材（可按原词表顺序或名称）。

## Popup UI（最小）

- 进度：`已完成 / 总数`、当前食材、状态（运行中/已暂停/完成）
- 按钮：开始、暂停、继续、导出 txt（再下一次）、导入进度 JSON（可选但建议有，方便换机）
- 暂停原因文案

## 词表打包

- 扩展内 `data/ingredients.json`：构建时从仓库 `data/ingredients-by-category.json` 拷贝或裁剪为 `{ categoryName, name }[]`。
- 改词表 → 覆盖该文件 → 在 `chrome://extensions` 点「重新加载」。

## 非目标

- 不登录、不绕过验证码。
- 不采集菜谱正文/图片。
- 不对接小程序推荐逻辑（本扩展只产出 txt/进度）。

## 风险

- 移动站 DOM/xpath 变更 → 暂停并改选择器常量。
- 下载目录多次覆盖可能被浏览器改成 `(1)`：实现时固定 `filename` + `overwrite`；若仍冲突，在 popup 提示检查下载设置。
- 整表 ~449 项，按节奏约 1–2 小时；依赖断点与自动落盘。

## 验收

1. 未跑过：从第一个食材搜到回首页，progress/txt 更新。  
2. 中断后点继续：跳过已完成项。  
3. 故意搜一个会落到 `/search/?keyword=` 的词：进「非食材」段，count 为 `-`。  
4. 不足 9 条的 category：按实际条数求和。  
5. 人为制造一般卡住（断网再恢复）：同一食材刷新重试最多 3 次，仍失败则停止，不自动跳下一项。  
6. 验证码页：直接暂停，不计入刷新重试。
