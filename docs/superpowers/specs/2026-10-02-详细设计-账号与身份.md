本文只展开 **账号、登录身份、展示资料、端类型与埋点字段** 的设计细节；推荐引擎、食材等见技术设计概述。

---

## 1. 设计目标

1. 一人一个业务 **uid**，业务数据（画像、记录、推荐）全部挂 uid。  
2. 支持多种登录方式并存，且互不覆盖：  
   - 小程序微信登录  
   - （预留）App 内微信登录  
   - （预留 / 选填）手机号登录或绑定  
3. 区分 **登录方式（provider）** 与 **客户端端类型（platform）**。  
4. 展示昵称/头像自建，默认「大厨xxxx」，不依赖微信资料。  
5. MVP 先跑通小程序；表结构一次留好，避免上 App 时改主键。

---

## 2. 核心概念

| 概念 | 含义 | 示例 |
|------|------|------|
| `uid` | 产品内唯一用户 ID | `u_01J…` |
| `provider` | 登录/身份提供方 | `wechat_mp` / `wechat_app` / `phone` |
| `providerUserId` | 该提供方下的稳定 ID | 小程序 openid；App openid；`+86138…` |
| `unionId` | 微信开放平台统一 ID（可选） | 同一主体下打通 mp/app |
| `platform` | **本次请求/会话**来自哪端 | `mp` / `ios` / `android` |
| `loginProvider` | **本次登录**用的 provider | 可与 identities 中某条对应 |

**反模式（禁止）**

- 在 `users` 上只存一个 `openid` + 一个「用户平台类型」，表示「这个人是小程序用户」——一人多端会冲突。  
- 把手机号登录塞进「openid 字段」——手机号不是 openid。  
- 用小程序 openid 当作 App 微信登录的同一字符串。

---

## 3. 数据模型

### 3.1 `users`（人 + 展示 + 家庭设置）

一人一行。**不含**登录用 openid。

| 字段 | 类型 | 说明 |
|------|------|------|
| `uid` | string | 主键 |
| `nickname` | string | 展示名；默认见 §5 |
| `avatarUrl` | string? | 头像 URL；空则前端用默认图 |
| `phone` | string? | **展示冗余**（脱敏展示用）；规范号码以 identities 为准 |
| `phoneVerified` | bool | 是否已验证；与 `phone` identity 的 `verified` 同步 |
| `city` | string? | 用户所在城市（单个）；默认食材与可见菜谱按食物 `cities[]` 过滤 |
| `defaultPeopleCount` | number | **成员数缓存**（=`members.length`；增删成员后回写；UI 不单独编辑） |
| `defaultCombo` | object/string | 日常默认搭配 |
| `mealTimes` | object | 午饭/晚饭时刻 |
| `cookBudget` | string | 做饭时间预算 |
| `familyAvoids` | string[] | 家庭忌口 |
| `dishFormPrefs` | object | 菜式品类偏好 |
| `requirePhoneFor` | string[] | 预留：需验证手机号才可使用的能力码 |
| `createdAt` / `updatedAt` | date | — |

### 3.2 `user_identities`（登录身份绑定）

一人可多行。唯一约束：**(provider, providerUserId)** 全局唯一。

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 记录 id |
| `uid` | string | 所属用户 |
| `provider` | enum | `wechat_mp` \| `wechat_app` \| `phone` |
| `providerUserId` | string | 见下表 |
| `unionId` | string? | 仅微信类；有则便于合并 |
| `verified` | bool | 手机号是否验证；微信类登录成功即 `true` |
| `createdAt` / `lastLoginAt` | date | — |

不存 `appId`：本产品一套库对应一个小程序（+ 日后一个 App 用 `provider=wechat_app` 区分）。微信开放平台 AppID 放在服务端环境配置里换 code 即可。多个小程序共用同一张身份表时再考虑加「来源应用」。

**providerUserId 约定**

| provider | providerUserId | MVP |
|----------|----------------|-----|
| `wechat_mp` | 小程序 openid | **必做** |
| `wechat_app` | 移动应用 openid | 预留 |
| `phone` | E.164 或统一规范（如 `86` + 11 位） | 选填绑定；登录预留 |

索引建议：

- 唯一：`provider + providerUserId`  
- 普通：`uid`  
- 普通：`unionId`（若启用）

### 3.3 完整示例（1 用户 : N 身份）

关系：一个 `users` 对应多条 `user_identities`（小程序微信、手机号、日后 App 微信可并存）。

```jsonc
// users（1）
{
  "uid": "u_demo001",                          // 业务用户主键
  "nickname": "大厨K2M8",                       // 展示昵称
  "avatarUrl": null,                           // 头像 URL，空则用默认图
  "phone": "8613812345678",                    // 手机号（展示冗余）
  "phoneVerified": true,                       // 手机是否已验证
  "city": "杭州",                              // 用户所在城市（单个）
  "defaultPeopleCount": 3,                     // = members.length（缓存，UI 不单独编）
  "defaultCombo": {                            // 日常默认荤素汤搭配
    "meat": 1,                                 // 荤菜道数
    "veg": 1,                                  // 素菜道数
    "soup": 1                                  // 汤道数
  },
  "mealTimes": {                               // 习惯用餐时刻（提醒用）
    "lunch": "12:00",                          // 午饭
    "dinner": "18:30"                          // 晚饭
  },
  "cookBudget": "about30",                     // 做饭时间预算
  "familyAvoids": ["peanut"],                  // 家庭忌口（硬排除）
  "dishFormPrefs": {                           // 菜式品类偏好
    "stir_fry": "prefer",                      // 热炒：爱吃
    "hotpot": "neutral",                       // 火锅：一般
    "cold": "avoid"                            // 凉菜：少做
  },
  "requirePhoneFor": [],                       // 需验证手机才可用的能力码
  "createdAt": "2026-10-01T10:00:00.000Z",     // 创建时间
  "updatedAt": "2026-10-03T08:00:00.000Z"      // 更新时间
}

// user_identities（N，均挂 uid=u_demo001）
[
  {
    "_id": "id_mp_01",                         // 记录 id
    "uid": "u_demo001",                        // 所属用户
    "provider": "wechat_mp",                   // 登录方式：小程序微信
    "providerUserId": "oXXXX_mp_openid_abc",   // 小程序 openid
    "unionId": null,                           // 微信开放平台统一 id（可选）
    "verified": true,                          // 该身份是否已验证
    "createdAt": "2026-10-01T10:00:00.000Z",   // 绑定时间
    "lastLoginAt": "2026-10-03T08:00:00.000Z"  // 最近登录时间
  },
  {
    "_id": "id_phone_01",                      // 记录 id
    "uid": "u_demo001",                        // 所属用户
    "provider": "phone",                       // 登录方式：手机号
    "providerUserId": "8613812345678",         // 规范化手机号
    "unionId": null,                           // 非微信类无此字段含义
    "verified": true,                          // 手机已验证
    "createdAt": "2026-10-02T12:00:00.000Z",   // 绑定时间
    "lastLoginAt": "2026-10-02T12:00:00.000Z"  // 最近登录时间
  }
]
```

### 3.4 与埋点 `events` 的关系

每条事件建议带：

- `uid`  
- `platform`：`mp` \| `ios` \| `android`（端）  
- `loginProvider`：本次会话登录方式（可选）  
- **不要**用 `platform` 代替 identity，也不要把 openid 打进全量埋点（隐私与体积）；需要排障时另开安全日志。

## 4. 登录与绑定流程

### 4.1 小程序微信登录

```
客户端 wx.login → code
  → auth.login({ code, platform: 'mp' })
  → 换 openid（云开发/微信 API）
  → 查 user_identities(provider=wechat_mp, providerUserId=openid)
       ├─ 命中：更新 lastLoginAt，返回该 uid
       └─ 未命中：
            创建 users（默认 nickname/avatar）
            创建 user_identities(wechat_mp, openid, verified=true)
            返回新 uid
```

### 4.2 选填手机号（绑定，非独立登录）

```
已登录 uid
  → auth.bindPhone({ phone, smsCode? })
  → 可不校验短信：verified=false
  → upsert user_identities(provider=phone, providerUserId=规范手机号)
  → 同步 users.phone、users.phoneVerified
```

冲突：该 `phone` 已绑定其他 uid → 返回明确错误（提示「该手机号已使用」；合并账号见 §4.5，可后置）。

### 4.3 预留：App 微信登录

```
App 微信 SDK → code
  → auth.loginWechatApp({ code, platform: 'ios'|'android' })
  → 换 App openid（+ 可能的 unionId）
  → 优先：identities(wechat_app, openid)
  → 若有 unionId：可匹配已有 wechat_mp 同 unionId 的 uid（同一人）
  → 否则新建 uid + identity
```

### 4.4 预留：手机号登录（独立登录）

```
短信验证码通过
  → 查 identities(phone, 手机号) 且 verified=true
  → 命中则发自有 token（自定义登录）
  → 未命中则注册新 uid + phone identity
```

与方案 C 一致：小程序阶段以微信登录为主；手机号先绑定、后可升级为登录手段。

### 4.5 账号合并（二期，本文只定原则）

当「已登录 uid A」要绑定已被 uid B 占用的手机号/微信时：

- **拒绝绑定**，避免静默合并丢数据。  
- 二期：提供显式「合并账号」流程（选主 uid、迁移业务数据、删除从 uid），需单独评审。

### 4.6 后期强制验证手机号

- `users.requirePhoneFor` 含某能力码（如 `cloudSync`）时，前端拦截并引导验证。  
- 验证成功：`identities.phone.verified=true`，`users.phoneVerified=true`。  

### 4.7 两阶段如何认成同一人

认人只认 **uid**；openid / 手机号都是绑在 uid 上的身份。小程序从个人升级到企业时 **AppID 一般不变，openid 不变**。

**阶段一：个人认证（当前）**  
- 小程序：`wx.login` → `wechat_mp` + openid。  
- 没有 unionId，也没有微信手机号组件。  
- **对上 App 只靠已验证手机号**：小程序引导绑手机；App 手机登录按手机号找 uid；App 微信登录后必须绑同一手机，才能并到小程序那个 uid。  
- 未绑手机的 App 微信登录 = 另一个 uid，属预期。

**阶段二：改为企业认证之后**  
- 用户再用小程序微信登录：仍是原来的 openid → 原来的 uid。  
- 可绑开放平台：登录时把 **unionId** 写回已有 `wechat_mp`；App 微信登录用 unionId 匹配同一人。  
- 手机号继续当总钥匙（小程序 / App 手机 / 给 App 微信补绑）。  
- 撞到两个 uid（例如以前 App 微信没绑手机）：走 §4.5 显式合并，不静默覆盖。

匹配顺序（有则用，没有就下一步）：当前 openid 或手机号已存在 → unionId 能对上 → 已验证手机号能对上 → 新用户。

## 5. 展示资料（方案 A）

### 5.1 默认昵称

- 格式：`大厨` + **4 位**大写字母数字，例：`大厨K2M8`。  
- 生成：由 uid 哈希取 4 位；查重（同 nickname）则扩展到 5～6 位或加后缀。  
- 仅新用户写入；用户改过昵称后不再自动覆盖。

### 5.2 默认头像

- 客户端内置占位图；`avatarUrl` 为空时用占位图。  
- 上传后写入云存储 URL → `users.avatarUrl`。

### 5.3 修改

- `profile.updateDisplay({ nickname?, avatarUrl? })`  
- 昵称：长度限制（如 2～16 字）、敏感词校验。  
- 埋点：`profile_display_update`。

### 5.4 「我的」页展示

1. 头像 + nickname  
2. 手机号（有则脱敏，如 `138****5678`；无则「未绑定」入口）  
3. 家庭忌口 / 成员 / 搭配 / 城市等设置入口  

不展示 openid / uid（或仅开发态调试展示）。

## 6. 云函数职责（账号相关）

| 方法 | 说明 |
|------|------|
| `auth.login` | 小程序 code → wechat_mp identity → uid |
| `auth.bindPhone` | 当前 uid 绑定/更新 phone identity |
| `auth.loginWechatApp` | 预留 |
| `auth.loginPhone` | 预留（验证码登录） |
| `profile.updateDisplay` | 昵称头像 |
| `profile.*` | 家庭画像等（与身份无关） |

鉴权：云函数内取当前微信调用身份，解析到 uid 后，禁止客户端直传任意 uid 改他人数据。

## 8. 安全与合规要点

- openid / unionId 仅服务端存储与使用，不写进前端日志与普通埋点。  
- 手机号存储需加密或严格权限；展示脱敏。  
- 选填手机号须在隐私政策中说明用途（账号安全、日后同步等）。  
- 个人主体阶段不做依赖企业主体的手机号组件主路径。
